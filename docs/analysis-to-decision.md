# 从 AI 分析到用户决策

AI 分析只有进入“提出假设—人工判断—冻结记录—按期复盘”的闭环，才会帮助用户积累能力。知衡不会把报告阅读量当作进步，也不会让模型的行动建议直接变成正式决策。

## 交互契约

```text
结构化 AI 分析 → 用户选择一条行动 → 生成待确认草稿
                                      ↓
                用户补齐对象、情景数字、仓位与日期
                                      ↓
                       明确点击冻结 → 不可变决策卡
                                      ↓
                              到期复盘与概率校准
```

点击“转为决策草稿”只会复制以下文字线索：

- 当前综合判断、所选行动及其理由；
- 报告中已经列出的风险和未知项；
- 所选行动与报告给出的复盘/证伪条件；
- 原分析 ID 和行动序号，用于以后追溯来源。

系统不会代填投资对象、预期收益、下行情景、置信度、仓位和复盘日期。这些字段体现用户自己的目标、风险容量和判断，必须由用户逐项填写。草稿可以放弃；只有用户点击“冻结决策快照”后才会写入数据库。

## 数据完整性

正式决策保存时，服务端会检查来源分析确实存在于本地 `analyses` 表。来源 ID 和行动序号保存在不可变决策载荷中，不依赖客户端标签，也不会在复盘时被覆盖。旧版本没有来源字段的决策仍可读取。

分析记录与决策记录承担不同职责：

- 分析记录保存模型当时看到的上下文审计、结构化结论和工作流轨迹；
- 决策记录保存用户最终接受和修改后的命题、反方观点、情景数字、仓位、证伪条件与复盘日期；
- 两者有关联不等于两者相同。决策卡明确标记“已由用户确认”，但这不代表分析事实已经被外部核验或投资结果有保证。

云同步以加密数据包同时同步分析和决策，因此来源关系无需新的云端明文元数据。模型密钥、登录令牌与恢复密钥仍不进入同步包。

## 安全边界

- 模型不能调用保存决策接口，也不能执行交易；
- 未通过结构化输出校验的分析不能生成这个入口；
- 草稿内容始终可编辑，用户必须补全必填项；
- 服务端拒绝引用不存在的分析，避免伪造来源；
- 来源标签只说明文本从何而来，不代表正确性、适当性或收益承诺。
