# 账号与数据同步

账号和业务数据都保存在自建服务器的 PostgreSQL 中，设备之间通过数据版本同步。部署见 [自建部署指南](self-hosting.md)。

## 协议

1. `POST /api/auth/register`：邮箱、密码；公开注册，无需邀请码。请求只接收邮箱与密码，其他字段会被拒绝。
2. `POST /api/auth/login`：邮箱、密码，返回随机会话令牌、账户 ID 与过期时间。
3. 私有请求携带 `Authorization: Bearer <token>`；后端查数据库验证会话，服务器自行确定租户。
4. `GET /api/snapshot` 可在原估值事务内采用公共价格库中已经存在的新收盘价，不联网；有变化才推进账号版本，响应头 `x-data-revision` 表示采用后完整快照的最终版本。
5. 账号修改请求携带 `If-Match: <revision>`，在用户数据库锁内检查。缺失/旧版本通常返回 409，客户端保留输入并要求刷新核对；财务写入会先按本账号持久回执识别已提交的相同请求并返回当前快照。分析预览、模型连接测试、财务回执查询、公司代码解析及公共分红日历刷新不要求账号版本；公共目录保存校验其独立的目录版本。例外由服务端版本策略显式声明，其他 POST 预览入口不能据名称推断为免版本。
6. `GET /api/sync/version` 返回 `{ "revision": "..." }`。前台轮询合并请求、空闲降频、失败指数退避。版本不变不读取全量业务快照；有待确认草稿时不覆盖界面。
7. `POST /api/auth/logout` 撤销当前会话，其他设备保持登录。管理员重置密码撤销账号全部会话。

写入成功后客户端接受响应版本；读取版本接口、GET 汇率设置和 AI 响应不会提前推进表单基准版本。完整快照尚未加载时，不能用这些局部读取确认其他设备的新资料。版本同步只读取已保存的数据，不查询行情或刷新账号汇率；删除操作同样产生版本更新。

离开将卸载的编辑页前，应用会询问是否放弃未保存输入；取消浏览器历史或地址跳转时保留原页、地址和草稿。同页导航不清空草稿；问答页常驻保留输入，切到辅助页面后仍可返回继续。搜索、筛选和排序属于展示状态，不触发草稿放弃提示。

同步状态统一显示在侧栏，移动端顶部提供同一状态入口；点击进入“设置”。侧栏只有一个“设置”入口，账号、服务器连接、备份与导入、模型连接、问答预设和显示偏好都在同一页。

传输版本、同步屏障、待更新标记、写入计数和请求取消归当前账号会话。切换账号、退出或重新设置登录会话会使旧实例失效，取消旧请求并唤醒等待中的写入；旧请求不能发送等待中的修改、采纳版本、发布已保存事件或更新新账号界面，即使随后切回同一令牌也不能恢复旧请求。旧同步的结束只释放自己的屏障。页面草稿与已显示快照继续由原页面和应用层持有。覆盖导入同样绑定备份时的会话实例。

模型连接测试在账号锁内冻结已保存的接口、模型和凭据，等待期间释放锁，不推进资料版本。无关资料修改不使测试失效；被测配置或凭据改变时返回 409，用户需测试当前配置，不能把旧结果显示为新设置连接成功。失败或取消不保存结果。

## 边界

数据实时写入服务器，不在设备间上传/覆盖整库快照。离线无法保存，前端保留当前页面输入但没有持久离线队列。财务请求超时或 5xx 时先查询只读回执，未知结果保留原请求核对；不自动创建新修改。服务器能读取业务明文，没有端到端加密。

JSON 导出/导入用于备份与迁移，不是同步协议。导出包含个人档案、账本、每日原始条目、研究与复盘、分析历史、个人观察资料及允许备份的设置；设置仅包含统一汇率表/历史汇率、投资方法论和账号观察规则。模型配置、问答预设、API Key、登录会话及全局公共目录/行情库不进入账号备份。`POST /api/data/import` 默认仅允许空账号，显式加 `?replace=true` 可替换当前登录账号上述可备份数据，不合并，也不影响其他账号；目标账号的登录与不在备份内的配置、密钥保留。两种导入都要求 `If-Match` 版本，校验或写入失败时事务回滚。

“设置 → 备份与导入”提供导出/导入控件，支持选择 JSON 文件或展开“粘贴 JSON”，UTF-8 内容最大 64 MB；设置入口不依赖模型配置加载成功。导入方式默认“导入到空账号”；选择“覆盖当前账号”并读取 JSON 后，确认抽屉说明全部替换范围、失败回滚及备份恢复方式；还须勾选“我已导出当前数据”才允许确认覆盖。确认后会先下载 `mario-before-import-时间.json` 备份，再执行覆盖。覆盖请求绑定备份时的账号和数据版本；备份后若有新写入，服务器拒绝覆盖，需核对后重新预览。请允许浏览器下载并保管备份；需要回退时，可将该文件再次覆盖导入。登录信息及模型、行情密钥保持在目标账号中。PostgreSQL 完整备份和主密钥必须由管理员单独保管。

## 外部自选 JSON 导入

此入口解决既有自选和真实交易需逐笔重录的问题，接受 `{ "version": "1.0", "exportedAt": "RFC3339 时间", "data": { ... } }`，与 Mario 的 `schemaVersion` 备份明确区分。格式转换由 `db/watchlist_import` 完成，然后复用 `import_sync_data` 的单一恢复事务、账号隔离及版本校验；不改账号 schema 或 Mario 备份版本，不新增数据库或登录入口。失败保留原账号数据，恢复方式与上文一致。

- `data.accounts` 存在时只导入所选来源账户，完全忽略顶层 `data.watchlist` 的镜像。多账户必须在预览中明确选择；客户端把 `selectedAccountId` 放在请求顶层，服务端核对其存在及来源账户 ID 唯一性；不创建或切换 Mario 登录账号。没有 `accounts` 时使用顶层列表，交易账户名为“导入账户”。
- 预览显示所选账户、自选股数和源交易记录数，说明红利税合并及不导入字段。沪深六位代码转为 `.SS` / `.SZ` 后经现有观察契约校验；超出 50 家、重复证券或非沪深 A 股整次拒绝。自选保存为个人名单，源 `confirmed` 不作为基本面证据。
- `transactions` 按 `ts` 的毫秒时间排序，同时间保留原数组顺序；日期取 `Asia/Shanghai`，再分配持仓内唯一序号。`buy` / `sell` 的金额为 `qty × price`；`dividend` 的税前金额为 `qty × (gross ?? price)`，其中 `gross` 和 `price` 均为每股口径，两者差额作为该次分红代扣税。账本分红的数量和价格字段按现有契约置零。
- `dividendTax.price` 是整笔税费金额，不乘股数；只合入同证券、同时间戳及同股数的唯一卖出记录。缺匹配、多个候选、未知类型、未来交易或非法交易链整次拒绝。各笔原始时间、数量、价格与税前字段保存在对应交易备注中。
- 所有金额经十进制解析，最多 8 位小数；只消除与 8 位小数结果相差不超过 `0.000000000001` 的 JSON 浮点尾差，不吞掉真实第九位精度。启用来源手续费估算而未提供逐笔实际费用时拒绝导入，不推算历史费用；未启用时费用按零导入。
- 有真实成交时，股数、平均成本及盈亏均按原账本规则重放，`shares` 如存在必须与重放股数相同；保留清仓证券及其交易。`costPrice` 的源算法可能扣除分红或历史盈利，不覆盖真实成交成本。无交易且股数大于零时，按 `shares` 与 `costPrice` 保存手工持仓，不补造期初买入；无持仓也无交易的证券只进自选。
- `price` 只保存为无行情日期、未核验的参考价，不用 `exportedAt` 冒充行情观察日；非零持仓缺少正参考价时拒绝。`priceCny`、旧价格变化及行情缓存不作为权威报价。
- `cashTrackingEnabled=false` 或未提供时不导入占位现金。为 `true` 时保存 `cashBalance` 的 CNY、HKD、USD 当前精确余额并标记待核对；不导入期初资金及校准历史，也不重放历史成交扣款。
- 来源行业、自定义行业、目标价/目标股息率、旧股息及股息率、发现列表及静态行情编辑不进入公共目录或观察历史，也不改变 Mario 的观察规则。此类 JSON 不含 Mario 设置，格式适配保留目标账号当前观察规则（空账号按原默认值），方法论采用初始范本；覆盖模式仍替换其余全部可备份业务数据，请保留原文件用于核对未映射字段。

## 备份版本

当前同步数据集为 v28，租户数据库 schema 为 15；两者独立版本化，数据集版本描述 JSON 结构，schema 版本控制账号数据库的一次性迁移。数据集包含账号观察规则、买点观察名单、分红依据、逐日历史、未读状态及当前股数网格；旧比例网格仅保留历史参考。v27 及以前缺少账号规则时恢复默认配置；v24–v26 的观察与旧比例网格按[观察升级规则](buy-watch.md#数据升级与验证)在原事务中迁移，v23 及以前备份恢复为空观察名单。观察数据与财务数据一起事务恢复，失败整次回滚。早期备份按各自版本的结构校验后在单一事务内恢复，失败整次回滚：

- 含早期交易结构的 v1–v17 包整次拒绝恢复，不覆盖现有数据；不含交易的财务包按原结构恢复。
- 旧投资目标与组合流水（v1–v18）、组合检查点（v1–v16）、决策与结构化决策复盘（v1–v15）、长期记忆偏好表（v1–v21）只校验结构并跳过，不重建已退役功能；其他有效资料继续恢复，历史问答正文与冻结引用保留。
- v18–v20 恢复时保留已有现金余额，不重放历史现金流。现金核对基准、逐交易现金归属、更正历史、操作回执、异常隔离、公司行动与精确会计源自 v21 起包含在备份中；交易字段与成本算法见 [真实成交与持仓](holding-trades.md)。
- 新版备份需使用新版服务恢复。

投资方法论正文随账号数据备份保存，导入前检查非空及 4000 字符上限，失败不覆盖当前数据。备份未包含方法论时恢复为初始范本；模型密钥与账号登录信息不进入数据备份。旧格式适配仅服务存量备份恢复，停止支持对应版本后才可移除；不得因规范整理直接丢弃备份、财务审计或仍需恢复的数据。
