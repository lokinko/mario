# 账号与数据同步

旧的第三方账号、恢复密钥和云端加密快照上传实现已移除。当前使用自建 PostgreSQL 和服务器账号，部署见 [自建部署指南](self-hosting.md)。

## 协议

1. `POST /api/auth/register`：邮箱、密码；公开注册，无需邀请码。请求只接收邮箱与密码，已移除的 `registrationKey` 字段会被拒绝。
2. `POST /api/auth/login`：邮箱、密码，返回随机会话令牌、账户 ID 与过期时间。
3. 私有请求携带 `Authorization: Bearer <token>`；后端查数据库验证会话，服务器自行确定租户。
4. `GET /api/snapshot` 响应头 `x-data-revision` 表示本次快照的用户数据版本。
5. 修改请求携带 `If-Match: <revision>`，在用户数据库锁内检查。缺失/旧版本返回 409，客户端保留输入并要求刷新核对。预览与模型连接测试不写业务数据，不要求版本。
6. `GET /api/sync/version` 返回 `{ "revision": "..." }`。前台轮询合并请求、空闲降频、失败指数退避。版本不变不读取全量业务快照；有待确认草稿时不覆盖界面。
7. `POST /api/auth/logout` 撤销当前会话，其他设备保持登录。管理员重置密码撤销账号全部会话。

写入成功后客户端接受响应版本。读取版本接口不会提前推进表单基准版本；AI 响应也不推进，因为 AI 执行期间其他设备可能已修改数据。删除操作同样产生版本更新。

## 边界

数据实时写入服务器，不在设备间上传/覆盖整库快照。离线无法保存，前端保留当前页面输入但没有持久离线队列。财务请求超时或 5xx 时先查询只读回执，未知结果保留原请求核对；不自动创建新修改。服务器能读取业务明文，不再使用端到端加密表述。

JSON 导出/导入仅用于备份与旧数据迁移，不是同步协议；它排除模型密钥与会话。`POST /api/data/import` 默认仅允许空账号，显式加 `?replace=true` 可替换当前登录账号的全部业务数据，不合并，也不影响其他账号。两种导入都要求 `If-Match` 版本，校验或写入失败时事务回滚。

页面中勾选“覆盖当前账号已有数据”，选择 JSON 文件并确认后，会先下载 `mario-before-import-时间.json` 备份，再执行覆盖。覆盖请求绑定备份时的账号和数据版本；备份后若有新写入，服务器拒绝覆盖，需核对后重新选择文件。请允许浏览器下载并保管备份；需要回退时，可将该文件再次覆盖导入。登录信息及模型、行情密钥保持在目标账号中。PostgreSQL 完整备份和主密钥必须由管理员单独保管。

## 已移除功能的旧备份兼容

当前数据快照格式为 v22，证券成交采用真实买卖与现金分红结构，不兼容旧交易。含旧交易记录的 v1–v17 包整次拒绝恢复，不覆盖现有数据；不含交易的旧财务包仍按原结构校验和恢复。v19 不再导出投资目标和组合流水；v1–v18 旧备份中的这两类表仅校验结构并跳过，其他有效资料继续恢复。数据库升级会删除这两张旧表。快照也不再导出已移除的决策确认、单笔决策复盘、分析看板组合快照。v20 将同币种存款合并为一个余额，并启用交易自动结算；恢复 v18/v19 备份时保留已有余额，不对历史成交重复扣款。新版备份需使用新版服务恢复。v21 增加现金核对基准、逐交易现金归属、永久更正历史、操作回执、异常隔离、公司行动与精确会计源。v18–v20 恢复时不重放旧现金流。交易字段、成本算法及异常隔离修复规则见 [真实成交与持仓](holding-trades.md)。

v22 移除长期记忆偏好表和分析中的记忆元数据；旧备份仅校验该表结构并跳过，不恢复偏好。历史问答正文与冻结的引用资料仍保留。数据库升级自动删除旧偏好表，并清除预设中的记忆选项。

投资方法论正文随账号数据备份保存，导入前检查非空及 4000 字符上限，失败不覆盖当前数据。旧备份未包含方法论时恢复为初始范本；模型密钥与账号登录信息仍不进入数据备份。
