# 每日资产自动追踪

“我的情况”显示每日总资产、净资产、变化和趋势。存款与投资列表的金额可直接编辑，失焦或回车保存，Tab 跳到下一项；明确输入 0 可以清零，空值不会被当成 0。保存失败保留输入和请求编号，可重试；过期版本需要先核对最新金额。

## 日期与金额口径

新增投资持仓时填写持仓数和当前价格，当前市值按“持仓数 × 当前价格”即时计算并只读展示；修改任一项都会更新结果，缺少数量或价格时显示待补充，不将空值当成零价格。填写证券代码后可留空当前价格，保存时自动获取日收盘价并计算市值；已有代码持仓继续通过行情更新同步价格和市值。日收盘价不代表盘中实时成交价，获取失败时保留原值并显示失败原因。现金余额和缺少数量、价格明细的旧记录仍可直接编辑总金额。

首次使用保存设备的 IANA 时区，随后随账户加密同步，不随设备时区变化。每个日期只展示一份组合状态；同日同资产覆盖写入，跨日保留最后保存值。第一次从当前资产建立记录，保留原估值日期，不追溯构造历史负债。

启动、返回前台和前台跨日补齐沿用记录；服务关闭期间不运行后台任务。恢复时依据已保存的历史条目补齐，不把新输入的金额填进过去日期。沿用值保留最后确认日期，不代表每日重新估值。页面分别显示较昨日和较上次实际更新的金额变化；首次记录没有可比较的前值。

每日追踪不要求全部资产估值日期一致，也不冻结组合流水。当前资产以统一设置中的日度汇率或手动覆盖折算，更新后只记录到当天，已有历史不会被改写，汇率观察日独立保留；缺失汇率时保存原币金额，总资产和净资产为空，显示待补全。切换基准币种后图表分段，跨币种的差额不计算。新增、移除记录不被推断为交易；金额变化不等于收益。

## 存储与接口

- `daily_settings`：唯一账户记账时区。
- `daily_entries`：稀疏原始记录，主键为日期与资产 ID 的稳定组合，同日覆盖；负债和基准币种是独立条目。删除资产留下标记，历史不受当前持仓的删除影响。
- `daily_totals`：每日完整状态和汇总缓存，包含沿用日；可从原始记录重建，不参与同步冲突。

全部持仓写入（包括行情估值）与每日记录在同一 SQLite 事务内完成。金额快捷保存只修改金额、估值日期和版本，撤销旧行情核验，使用统一设置中的汇率，不把汇率更新视为余额重新确认。服务端版本检查防止过期覆盖，请求编号使网络重试幂等。

- `POST /api/daily-assets/ensure`，`{timezone}`：首次初始化并补齐日期；已设置时区不被覆盖。
- `GET /api/daily-assets?from=&to=&before=&limit=`：按日期倒序查询，默认 30 条、每页最多 400 条，返回 `nextBefore` 游标。GET 不写库。
- `GET /api/daily-assets/compare?from=YYYY-MM-DD&to=YYYY-MM-DD`：指定两天的总额、逐项及类别占比变化。
- `PUT /api/holdings/{id}/amount`，`{amount,expectedRevision,requestId}`：金额快捷保存；版本来自 `Snapshot.holdingRevisions`。

同步格式 v11 包含时区、日条目和统一汇率设置，继续兼容 v1–v10 包。独立资产的编辑可合并；同一记录的不同修改沿用冲突保护。导入先验证再应用，重建缓存与同步数据原子提交，历史关联不依赖当前仍存在的持仓。旧客户端不能读取 v11 包，多设备应升级到支持该版本的客户端。

## 分析与授权

默认提供最近 30 日历史和其区间比较；从历史页面进入问答时，`AnalysisRequest.dailyAssetRange` 指定所选起止日，另外附上这两日的完整比较。此操作仅预填问题，用户发起分析后才调用模型。

`dailyAssetHistory` 属于“每日资产记录”授权（`includeDailyAssets`）；负债及净资产同时受财务档案授权控制。每日记录、区间端点及比较均纳入预览指纹，保存后旧预览失效。AI 必须说明沿用值、确认日期和资料缺口，不得凭余额变化声称收益、买卖行为或投资能力。历史与授权后的数值一起保存在分析档案中。
