# 可追溯市场数据

## 买点观察与持仓估值

当前默认入口[买点观察](buy-watch.md)通过 `WatchMarketProvider` 读取公开日线、交易日期参考和已实施分红，计算 TTM 股息率、日周 BOLL 及[历史趋势与金叉](buy-watch.md#股价趋势与金叉图)；观察结果独立保存在账号观察历史，不改写持仓或成交。股息率使用公司每股分红与对应收盘价，不用个人账户分红到账金额代替。

观察序列、持仓估值和真实成交各自保留来源与日期：调整收盘用于技术指标，实际收盘用于观察股息率，券商成交原值用于个人账本。具体窗口、送转归一、周线口径和缺失处理见[观察规则](buy-watch.md#明确规则)。基本面和分红持续性不由行情接口直接判定。

## 持仓汇率与估值

### 外部查询与账号并发

汇率查询、汇率刷新、保存普通持仓及核验估值先在账号锁内冻结输入，等待供应商时释放一层账号锁；成功或失败返回前重获锁。写入流程核对冻结的账号版本，期间任何账号写入都会使本次结果返回 409，保留最新数据并由客户端核对后重试；普通持仓保存中的汇率检查与价格补齐分别校验各自的等待窗口。只读汇率查询不推进版本，允许无关个人写入，但汇率表在等待期间改变时拒绝旧报价。取消外部等待不提交后续写入，也不重新占用账号锁。已完成的汇率刷新或手动覆盖仍按原事务独立保存，不因随后保存持仓失败而回滚。

此调整不改变存储和备份格式，证券报价预览及逐持仓后台价格刷新继续沿用其既有并发策略。

外币持仓必须先换算到用户的基准币种，才能进入组合汇总、风险检查和再平衡计算。完全手填的汇率容易产生日期错位、录入错误和无法追溯的问题。本模块提供可替换的 `FxRateProvider`，首个实现使用欧洲中央银行（ECB）公开参考汇率。

ECB 的 [Data Portal API](https://data.ecb.europa.eu/help/api/data-examples) 提供 SDMX 2.1 数据访问和 CSV 输出；mario 读取 `EXR.D.<currency>.EUR.SP00.A` 日度序列。ECB 说明参考汇率通常在工作日发布，属于买卖报价的平均参考值，仅供信息使用，并不代表实际市场成交价；完整边界见 [ECB 汇率说明](https://data.ecb.europa.eu/key-figures/ecb-interest-rates-and-exchange-rates/exchange-rates)。

## 换算协议

对原币 `from` 和基准币种 `to`：

1. 查询请求日期及此前 7 天的相关欧元参考序列；
2. 只选择不晚于请求日期、且两个币种都存在观察值的最新共同工作日；
3. ECB 数值表示“1 EUR 对应多少该币种”，因此计算 `from → to = to_per_eur / from_per_eur`；
4. EUR 一侧按 1 处理；同币种汇率恒为 1；
5. 返回请求日期、实际观察日期、回退天数、原始数据 URL、方法链接和用途限制。

系统不混用两个不同日期的币种观察值，也不把周末回退值伪装为当日成交价。当前客户端支持 CNY、USD、HKD、EUR、JPY 和 GBP。

`GET /api/market-data/fx-rate` 只查询指定原币、目标币和日期：当日可只读复用该目标币对应的有效汇率表，未命中时通过 Provider 查询同一币对；不会刷新账号的完整汇率表、改写持仓或每日记录，也不推进账号版本。持仓汇率的持久更新仍由既有刷新流程负责。

## 自动更新与统一设置

“我的情况”页头的汇率入口打开共享汇率抽屉，悬停提示显示当前涉及币种的汇率，抽屉显示当前资产涉及的币种、观察日期、来源及手动覆盖，编辑控件和其他币种按需展开。持仓和现金的表单不要求填写汇率。服务端自动查询 ECB，无需用户配置密钥。

运行期间的小时任务仅查询公开的 USD → CNY 报价，预热 ECB 来源缓存，不写账号汇率或持仓。账号完整汇率表由“更新汇率”（`POST /api/fx-settings/refresh`）、保存手动覆盖，以及保存普通持仓时的汇率检查更新；普通保存会复用同日一小时内的成功检查，失败检查一分钟后可重试。读取快照、汇率设置、数据版本和补齐每日记录均不触发账号汇率刷新。ECB 按工作日发布，周末及假日采用不晚于请求日期的最近共同观察值，界面保留实际观察日期。

当前持仓统一使用当前账户基准币种对应的汇率；余额确认日期与汇率观察日期分别保留，更新汇率不会把沿用余额标成重新确认。不同账户、不同基准币种的手动设置相互独立。统一设置支持：

- 自动汇率及来源、观察日期、最近检查时间；
- 修改指定外币的汇率，作为持续有效的手动覆盖；
- “恢复自动”，撤销该外币的手动覆盖；
- “更新汇率”，立即重新向来源查询，不覆盖已有手动值。

当前持仓使用 `central_daily` / `central_manual` 标记汇率来源。

账户汇率表和手动覆盖按账号保存，并随账号 JSON 备份导出、导入；备份不包含模型配置或 API Key。当前持仓录入使用页面表单与真实成交入口；备份恢复采用[账号与数据同步](cloud-sync.md)的 JSON 格式。

## 失败与限制

网络、超时、异常 HTTP 或无有效观察值时保留此前可用参考值并显示更新错误；没有可用值时保留原币金额，暂停对应换算，不猜测汇率。失败后可自动重试，也可在统一设置中手动指定或主动刷新。ECB 参考值仅供组合折算，不等同于券商成交价或银行结算价。

## 统一公共价格库

所有账号共用 PostgreSQL `mario_market.price_histories`，按规范证券代码一行保存滚动五个日历年的完整日收盘序列。`.SH`／`.SS`、`sh`／`sz` 前缀和港股前导零先归一；同一证券不按账号、持仓数量或成交起点建立价格副本。公共库不保存用户 ID、数量、成本、现金、密钥或私人名单。

每个完整版本包含原收盘值、前复权值、币种、实际交易日期、五年起点、已完成收盘截止、复权基准日、供应商及原价／复权／公司行动来源 URL、采集时间和已知拆送股事件。金额保留来源十进制字符串。源序列归一到最近一条具有有效原价和复权值的完整收盘日，作为统一前复权基准；最新基准日的前复权价与该日原价相等。缺失值保留为空，不按数组位置拼接日期，不填零或猜测停牌日价格；上市不足五年时仅保存已有实际历史。

持仓估值和趋势使用这份前复权序列；股息率继续使用同一交易日的原收盘值。前复权历史价不等于历史实际成交价，原始成交、成本、现金与已冻结的每日历史不按新复权序列回写。价格、日期、来源、口径和基准属于同一完整版本，不混合不同供应商的两段序列。

### 来源与五年窗口

- 沪深 A 股股票及上证交易日参考优先采用东方财富 `klt=101` 日线：`fqt=0` 原价与 `fqt=1` 前复权按日期对齐；股票完整分页核验已实施送股、转增，未知或缺页不解释为没有行动。
- 所有证券价格统一先尝试东方财富，再降级到 Yahoo。国内股票识别沿用沪市 `60`／`68`、深市 `00`／`30` 代码段。沪市 `50`／`51`／`56`／`58`、深市 `15`／`16`／`18` 基金（含 ETF、LOF、REIT）的拆分资料独立读取天天基金对应证券的完整“分红送配 → 拆分详情”，不套用股票送转方案。核对页面证券身份、表头、日期、比例及重复记录，保留五年窗口之前的拆分；只有来源明确显示“暂无拆分信息”才可确认空列表，缺页、加载占位或解析失败均整组回退 Yahoo。基金净值不替代场内收盘价。
- 港美股先通过东方财富证券搜索精确解析代码、市场及品种，拒绝模糊首项、重复候选、代码／市场编号不一致。当前支持普通港元港股，以及 NASDAQ／NYSE／AMEX 的美元股票、ADR 和 ETF；市场编号分别为 `116`、`105`、`106`、`107`，港股补足东方财富所需的五位代码。原价与前复权均按已解析的同一证券、市场和日期读取。无法可靠识别的海外市场、特殊类别股、港股非普通股及人民币柜台等直接降级 Yahoo，不猜代码或交易币种。
- 海外公司行动读取东方财富独立的港股／美股拆合股报告，校验完整分页、固定总量、证券、实施状态、生效日和拆分方向，保留五年前事件。报告明确返回空数据也不证明没有拆股：如 QQQ、VOO 的旧拆股可能缺失，需向 Yahoo 月采样补充完整行动资料，核对同一代码、币种、品种和交易所时区。补充只提供公司行动证据，两个价格序列仍全部来自东方财富；来源 URL 随公共版本保留。资料无法完整核验时整组降级，不能把空报告解释为零行动，也不能拼接两家的价格序列。
- 证券后缀校验覆盖上述基金代码段，例如 `508077.SZ` 返回应改为 `508077.SS` 的明确错误；不静默替用户更改持仓或交易的证券归属。
- 东方财富请求失败、资料不完整或不支持的证券整组回退 Yahoo 的 `query1`／`query2` 日线；原收盘取 `quote.close`，调整序列取 `adjclose`，按最近完整收盘原价归一。Yahoo 历史 `close` 可能经过拆股调整，记录其真实 `split_adjusted_daily_close` 口径；GBp／GBX 两种序列都换为 GBP。
- Yahoo 另用月采样查询完整拆股事件，月采样价格不进入日线；检查公司行动至采集当日，不因价格仅保留五年而漏掉更早成交对应的公开行动。
- 东方财富完整复权序列滞后时也尝试 Yahoo，采用实际有效收盘日较新的整组版本；同日优先东方财富。主源完整查询仍最多 24 秒，公共服务与整轮持仓原有总时限不变。所有源失败时保留原公共版本。来源均为免费公开接口，没有覆盖或稳定性保证。
- Yahoo 的每个只读请求对连接失败、超时、HTTP 429 或 5xx 最多重试一次，间隔 200 毫秒；404、无效证券和响应格式错误不重试。连接限时 5 秒，单次请求仍为 8 秒，公共服务与整轮持仓更新继续执行原有总时限。最终失败保留各来源的简明原因，不只显示最后一个域名的原始长 URL；服务器日志保留原错误链。持续的 DNS、代理或出站网络故障仍需在运行服务器排查，不能靠重试保证恢复。

窗口从该证券已完成收盘截止向前五个日历年计算，闰日按日历回退。历史查询只读这份窗口，窗口外或证券上市前没有报价，不再为账号临时创建另一套历史行情。

### 收盘日期与自动更新

收盘截止由[统一时间策略](../server/src/models/market/close.rs)决定：沪深在北京时间 15:05、港股在当地时间 16:15、美股普通代码在纽约时间 16:15 后采用当日完整收盘，纽约自动处理夏令时；其他未识别市场保留 UTC 昨日的保守截止。周末与节假日只使用来源实际返回的交易日期，不把请求日写成实际收盘日。

服务启动即检查，并每五分钟更新活跃证券。持仓、个人观察、公共目录和明确查询登记所需证券；后台只更新最近 48 小时仍被这些消费者使用的记录，不扫描全市场，也不自行续期无人使用的旧标的。停止使用的历史继续保留，重新使用时复用或补抓。

公共编排按证券合并同进程并发，单实例最多四个来源流程；数据库 120 秒租约与令牌协调不同 API 进程，旧请求不得覆盖新请求。网络期间不持有数据库事务。失败尝试和错误保存在公共行中，一分钟退避在重启后继续生效；已覆盖最新有效收盘的完整版本复用一小时，再检查来源更正，尚滞后的结果一分钟后可重试。跨收盘截止重新检查，不沿用上一截止日的成功判断。后台每轮最多 120 秒，按上次尝试时间优先处理尚未检查的记录；单证券来源更新最多 90 秒，失败不清空数据，过期租约可恢复。

写入在一个原子操作中替换该证券的整个五年版本和来源元数据；不仅检查目标截止，还比较实际复权基准，不能用日期倒退的行情替换已有较新数据。公共更新不推进任何账号版本。

### 持仓读取与写回

有代码、正数数量的普通持仓使用共享前复权收盘价；现金、期权、已清仓和无代码手工资产不自动套用股票价格。已有手工参考价不再是上市证券的持续覆盖：成功取得共享行情后统一采用公共值，私有数量和真实成交成本继续归账号。

`GET /api/snapshot` 只读公共库中已经存在的有效价格，不访问行情供应商；在已有账号锁内将新价格通过原估值事务应用到本账号，再返回完整快照。首次资料尚未准备时保留已有参考价，后台或显式更新补齐。其他账号已更新公共行情后，本账号下一次读取即可采用；同日来源更正也会比较实际价格和口径，不仅按日期跳过。读取时若价格没有变化，不重复写持仓、当日观测或账号版本；如果采用了新价格，响应头使用更新后的账号版本。读取不会刷新账号汇率或改写过去日期的资产记录。

“我的情况”页头的“刷新”（`POST /api/market-data/security/refresh`）与后台持仓任务消费同一服务：公共版本有效时直接复用，缺失或到期时由公共服务统一更新并持久化后再应用。首次有代码和正数数量且价格留空的持仓也先准备同一份公共价格。`GET /api/market-data/security-price` 返回库内对应日期的前复权报价；它本身不写个人持仓，首次或到期的公共资料可被统一补齐。`PUT /api/holdings/{id}/verified-valuation` 将指定日期的公共估值应用到账号。

原币市值仍按精确股数 × 前复权收盘价计算。持仓价格、精确会计、当前核验依据与当日资产观测保持同一账号事务，保留请求日、实际收盘日、来源、价格口径、复权基准和公共采集时间。较早报价不覆盖已核验的较新收盘。手动及后台刷新先冻结持仓版本，网络期释放账号锁，返回后重新取锁逐只比较；在途交易、编辑、删除及新估值优先。整轮持仓查询保持 90 秒截止，已取得的有效结果照常保存，未完成的逐项返回原因；价格预览、保存普通持仓、核验估值及手动刷新均等待 180 秒，写请求不自动重提。

存在待确认公司行动时沿用原暂停及人工核对流程，不从前复权价格推算交易或自动修改数量。持仓表行内和持仓详情均不显示价格口径、复权说明和日期，现价悬停提示显示实际价格日与来源；趋势按周取点展示五年窗口，见[趋势图](buy-watch.md#股价趋势与金叉图)。观察的 `priceRevision` 记录公共序列内容版本；同日更正可重算当前观察，只有采集时间变化不重算。技术信号不证明低估或应买入。

### 唯一入口与迁移

账号独立行情 Key、Twelve Data 运行入口、逐账号来源选择、独立的持仓／观察行情抓取及内存价格缓存均已退役。设置页说明共享行情，无个人行情配置接口。旧加密行情密钥不再被读取，保留原存储及整站备份，不在本次数据升级中删除用户密钥。

启动事务幂等增加公共价格表，无账号 schema 或个人备份结构迁移；旧持仓及历史证据保留，下次读取或后台成功检查后采用公共版本，不把私人手工价格反向导入公共库。个人 JSON 备份只含本账号及已采用的估值证据，不携带或覆盖公共五年行情；整站 PostgreSQL 备份包含公共表和刷新状态。新前复权来源校验与旧来源证据的读取校验共存仅为历史恢复；停止支持对应旧证据后可移除旧来源白名单，旧运行路径不恢复。
