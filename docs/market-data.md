# 可追溯市场数据

## 产品目的

外币持仓和流水必须先换算到用户的基准币种，才能进入组合汇总、风险检查、规划和变化归因。完全手填的汇率容易产生日期错位、录入错误和无法追溯的问题。本模块提供可替换的 `FxRateProvider`，首个实现使用欧洲中央银行（ECB）公开参考汇率。

ECB 的 [Data Portal API](https://data.ecb.europa.eu/help/api/data-examples) 提供 SDMX 2.1 数据访问和 CSV 输出；mario 读取 `EXR.D.<currency>.EUR.SP00.A` 日度序列。ECB 说明参考汇率通常在工作日发布，属于买卖报价的平均参考值，仅供信息使用，并不代表实际市场成交价；完整边界见 [ECB 汇率说明](https://data.ecb.europa.eu/key-figures/ecb-interest-rates-and-exchange-rates/exchange-rates)。

## 换算协议

对原币 `from` 和基准币种 `to`：

1. 查询请求日期及此前 7 天的相关欧元参考序列；
2. 只选择不晚于请求日期、且两个币种都存在观察值的最新共同工作日；
3. ECB 数值表示“1 EUR 对应多少该币种”，因此计算 `from → to = to_per_eur / from_per_eur`；
4. EUR 一侧按 1 处理；同币种汇率恒为 1；
5. 返回请求日期、实际观察日期、回退天数、原始数据 URL、方法链接和用途限制。

系统不混用两个不同日期的币种观察值，也不把周末回退值伪装为当日成交价。当前客户端支持 CNY、USD、HKD、EUR、JPY 和 GBP。

## 自动更新与统一设置

“我的情况 → 汇率设置”是唯一汇率管理入口。持仓、现金、组合流水的表单不再要求填写汇率，CSV 模板也不包含汇率列。服务端自动查询 ECB，无需用户配置密钥。

服务运行期间每小时查询当前日期的完整币种表；每天首次读取账户会刷新当日汇率，打开的客户端通过已有版本同步应用变化。服务关闭期间不执行任务，再次启动后自动更新。ECB 按工作日发布，周末及假日采用不晚于请求日期的最近共同观察值，界面保留实际观察日期。

当前持仓统一使用当前账户基准币种对应的汇率；余额确认日期与汇率观察日期分别保留，更新汇率不会把沿用余额标成重新确认。不同账户、不同基准币种的手动设置相互独立。统一设置支持：

- 自动汇率及来源、观察日期、最近检查时间；
- 修改指定外币的汇率，作为持续有效的手动覆盖；
- “恢复自动”，撤销该外币的手动覆盖；
- “更新自动汇率”，立即重新向来源查询，不覆盖已有手动值。

新保存的组合流水按发生日自动读取参考汇率。发生日在手动覆盖生效日之后的流水使用该手动值；更早的发生日继续读取历史参考值。流水冻结当时的汇率及来源，后续自动刷新或手动修改不会改写历史。当前持仓使用 `central_daily` / `central_manual` 标记；流水使用 `ecb_reference` / `user_declared`。

账户汇率缓存和手动覆盖按账号保存，并随 v11 数据包导出、导入；仍兼容 v1–v10 数据包。导出只包含汇率设置，不包含模型配置、API Key 或本地提醒设置。CSV 旧汇率列可继续解析，但新记录最终统一由服务端汇率来源补齐；预览与提交之间若汇率变化，要求重新预览。

## 失败与限制

网络、超时、异常 HTTP 或无有效观察值时保留此前可用参考值并显示更新错误；没有可用值时保留原币金额，暂停对应换算，不猜测汇率。失败后可自动重试，也可在统一设置中手动指定或主动刷新。ECB 参考值仅供组合折算，不等同于券商成交价或银行结算价。

## 证券价格 Provider

`SecurityPriceProvider` 与汇率接口彼此独立。默认使用 Yahoo Finance 的公开日线接口 `https://query1.finance.yahoo.com/v8/finance/chart/{symbol}`，不可用时尝试同一来源的 `query2` 域名，无需注册或 API Key。这是非正式公开接口，没有稳定性或覆盖保证；市场后缀、数据延迟和供应商见 [Yahoo 数据说明](https://help.yahoo.com/kb/finance/article-exchanges-data-delays-sln2310.html)。

“我的情况 → 投资持仓”填写证券代码和正数持仓数量即可自动更新：支持 `AAPL`、`0700.HK`、`600519.SS`、`000001.SZ` 等 Yahoo 代码，也支持 `sh600519` / `sz000001` 及带前导零的港股代码。上海 `.SH` 后缀查询时转换为 Yahoo 的 `.SS`；已知股票和 ETF 代码段的交易所填错时，在请求行情前提示正确后缀，例如歌尔股份 `002241.SH` 应改为 `002241.SZ`。不根据 `000xxx` 推断交易所，保留上海指数与深圳股票的区别。纯数字代码有歧义，必须带交易所后缀。新增持仓可以留空价格，服务端保存前补齐；无代码、无数量、零数量及现金持仓不自动估值。代码能否查询取决于来源覆盖，场外基金等不可用标的继续手工记录。

原有 Twelve Data [`/time_series`](https://twelvedata.com/docs/market-data/time-series) 保留为主动查询的可选来源。配置个人 Key 后，主动查询采用 Twelve Data；自动更新始终用免费公共来源。密钥按账号加密保存，通过 `Authorization: apikey …` 请求头发送，不进入行情公共缓存、AI 载荷或同步包。

每次查询明确提交证券代码和估值日。服务端回看最多 10 个自然日，只采用不晚于请求日的最近有效交易日。为避免把尚未收盘的当日日线误称为收盘价，观察日最晚只取 UTC 昨日；交易所本地日期按来源的 IANA 时区解析，周末及假日明确保留实际观察日。自动查询使用上海日期，与统一汇率一致。Yahoo 读取 `indicators.quote.close`，不采用分红复权的 `adjclose`；其历史收盘价可能经过拆股调整，记录为 `split_adjusted_daily_close`，不冒称未复权。London 的 `GBp` / `GBX` 价格从便士换为 GBP，避免百倍金额错误。Yahoo 未提供 MIC 时保留空值。Twelve Data 使用 `adjust=none`，记录为 `unadjusted_daily_close`。

账户快照读取、持仓保存、每日追踪补齐及已有版本同步检查时，自动将可用行情应用到持仓；持仓仍由所属账号的锁和事务保护。服务端校验 Provider 币种与持仓币种一致，再以：

```text
原币市值 = 当前持仓数量 × 来源日收盘价
```

原子更新持仓，并在独立记录中冻结数量、单位价格、市值、请求日、观察日、回退天数、价格口径、交易所、来源 URL、方法链接、限制和采集时间。检查点复制当时的估值证据，后续更新不会改写历史。用户手工修改持仓代码、市值、币种或估值日时，当前核验记录会自动失效，避免旧来源继续为新数字背书。

## 服务全局缓存

缓存位于 API 服务进程内，按规范化证券代码和请求日期共用，跨账号及每次请求新建的 Provider 共享 HTTP 连接池。仅缓存公共行情，不缓存持仓数量、个人市值或用户密钥；多 API 进程各有独立缓存。成功结果保存 1 小时，失败保存 1 分钟；同一键使用独立异步锁合并并发查询，全局最多 4 个上游查询，不让网络等待占住全缓存锁。最多 512 条记录，在容量不足时淘汰不在使用的记录，全部繁忙时返回可重试错误。每次响应流式限制 1 MB，每个上游请求超时 8 秒。

运行期间每小时刷新缓存中近期的当前标的，跨日使用新日期，不触碰账户数据。账户下次读取时应用新行情；无变化时不重复写持仓、每日记录或数据版本。服务重启后按需重新获取，账户已保存的价格证据仍然保留。`POST /api/market-data/security/refresh` 返回 `{snapshot,updatedCount,errors}`，界面提供“更新自动价格”；该操作尊重共享缓存和失败退避，不因重复点击增加上游请求。失败详情同时返回 `Snapshot.priceRefreshErrors`，界面保留原价并提示；币种、来源、日期或价格不合格时不更新对应持仓。

Twelve Data 的个人方案用于个人、内部和非商业用途；调用额度、市场覆盖、展示和再分发权利取决于用户自己的方案及交易所许可。当前 [个人价格页](https://twelvedata.com/pricing) 列出 Basic 免费方案的分钟和每日额度，完整使用限制见 [服务条款](https://twelvedata.com/terms)。mario 不内置共享密钥、不代理转售行情，也不保证任一代码或市场在用户方案中可用。

## 证券价格限制

- 日收盘价不是实时成交、券商结算价、可成交报价或内在价值；
- 日收盘价不自动处理分红再投资；Yahoo 历史价可能经过拆股调整，不能直接和拆股前数量相乘。拆股、合并、代码变化和其他公司行动需结合当时数量与券商记录核对；
- 现金、非上市资产和无支持代码的持仓可以继续使用人工市值，但界面与风险检查会明确显示“未核验”；
- 网络、超时、限流、权限不足、响应超过 1 MB、币种不一致、日期或价格异常都会停止更新，不回退到猜测值；
- 当前尚未在每个外部现金流时点重建全部持仓，因此仍不能计算严格时间加权收益率；
- 后续还需增加公司行动、基准指数与券商持仓导入，并继续遵守各数据源许可。免费公开接口的存在不代表任意商业展示或再分发已获得许可。
