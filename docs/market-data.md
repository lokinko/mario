# 可追溯市场数据

## 买点观察与持仓估值

当前默认入口[买点观察](buy-watch.md)通过 `WatchMarketProvider` 读取公开日线、交易日期参考和已实施分红，计算 TTM 股息率及日周 BOLL；观察结果独立保存在账号观察历史，不改写持仓或成交。股息率使用公司每股分红与对应收盘价，不用个人账户分红到账金额代替。

观察序列、持仓估值和真实成交各自保留来源与日期：调整收盘用于技术指标，实际收盘用于观察股息率，券商成交原值用于个人账本。具体窗口、送转归一、周线口径和缺失处理见[观察规则](buy-watch.md#明确规则)。基本面和分红持续性不由行情接口直接判定。

## 持仓汇率与估值

外币持仓必须先换算到用户的基准币种，才能进入组合汇总、风险检查和再平衡计算。完全手填的汇率容易产生日期错位、录入错误和无法追溯的问题。本模块提供可替换的 `FxRateProvider`，首个实现使用欧洲中央银行（ECB）公开参考汇率。

ECB 的 [Data Portal API](https://data.ecb.europa.eu/help/api/data-examples) 提供 SDMX 2.1 数据访问和 CSV 输出；mario 读取 `EXR.D.<currency>.EUR.SP00.A` 日度序列。ECB 说明参考汇率通常在工作日发布，属于买卖报价的平均参考值，仅供信息使用，并不代表实际市场成交价；完整边界见 [ECB 汇率说明](https://data.ecb.europa.eu/key-figures/ecb-interest-rates-and-exchange-rates/exchange-rates)。

## 换算协议

对原币 `from` 和基准币种 `to`：

1. 查询请求日期及此前 7 天的相关欧元参考序列；
2. 只选择不晚于请求日期、且两个币种都存在观察值的最新共同工作日；
3. ECB 数值表示“1 EUR 对应多少该币种”，因此计算 `from → to = to_per_eur / from_per_eur`；
4. EUR 一侧按 1 处理；同币种汇率恒为 1；
5. 返回请求日期、实际观察日期、回退天数、原始数据 URL、方法链接和用途限制。

系统不混用两个不同日期的币种观察值，也不把周末回退值伪装为当日成交价。当前客户端支持 CNY、USD、HKD、EUR、JPY 和 GBP。

`GET /api/market-data/fx-rate` 只查询指定原币、目标币和日期：当日可只读复用该目标币对应的有效汇率表，未命中时通过 Provider 查询同一币对；不会刷新账号的完整汇率表、改写持仓或每日记录，也不推进账号版本。持仓汇率的持久更新仍由既有刷新流程负责。

## 自动更新与统一设置

侧栏状态区的汇率入口打开共享汇率抽屉，抽屉显示当前资产涉及的币种、观察日期、来源及手动覆盖，编辑控件和其他币种按需展开。持仓和现金的表单不要求填写汇率。服务端自动查询 ECB，无需用户配置密钥。

运行期间的小时任务仅查询公开的 USD → CNY 报价，预热 ECB 来源缓存，不写账号汇率或持仓。账号完整汇率表由“更新汇率”（`POST /api/fx-settings/refresh`）、保存手动覆盖，以及保存普通持仓时的汇率检查更新；普通保存会复用同日一小时内的成功检查，失败检查一分钟后可重试。读取快照、汇率设置、数据版本和补齐每日记录均不触发账号汇率刷新。ECB 按工作日发布，周末及假日采用不晚于请求日期的最近共同观察值，界面保留实际观察日期。

当前持仓统一使用当前账户基准币种对应的汇率；余额确认日期与汇率观察日期分别保留，更新汇率不会把沿用余额标成重新确认。不同账户、不同基准币种的手动设置相互独立。统一设置支持：

- 自动汇率及来源、观察日期、最近检查时间；
- 修改指定外币的汇率，作为持续有效的手动覆盖；
- “恢复自动”，撤销该外币的手动覆盖；
- “更新汇率”，立即重新向来源查询，不覆盖已有手动值。

当前持仓使用 `central_daily` / `central_manual` 标记汇率来源。

账户汇率表和手动覆盖按账号保存，并随账号 JSON 备份导出、导入；备份不包含模型配置或 API Key。当前持仓录入使用页面表单与真实成交入口；备份恢复采用[账号与数据同步](cloud-sync.md)的 JSON 格式。

## 失败与限制

网络、超时、异常 HTTP 或无有效观察值时保留此前可用参考值并显示更新错误；没有可用值时保留原币金额，暂停对应换算，不猜测汇率。失败后可自动重试，也可在统一设置中手动指定或主动刷新。ECB 参考值仅供组合折算，不等同于券商成交价或银行结算价。

## 证券价格 Provider

`SecurityPriceProvider` 与汇率接口彼此独立。默认使用 Yahoo Finance 的公开日线接口 `https://query1.finance.yahoo.com/v8/finance/chart/{symbol}`，不可用时尝试同一来源的 `query2` 域名，无需注册或 API Key。这是非正式公开接口，没有稳定性或覆盖保证；市场后缀、数据延迟和供应商见 [Yahoo 数据说明](https://help.yahoo.com/kb/finance/article-exchanges-data-delays-sln2310.html)。

“我的情况 → 投资持仓”填写证券代码和正数持仓数量即可自动更新：支持 `AAPL`、`0700.HK`、`600519.SS`、`000001.SZ` 等 Yahoo 代码，也支持 `sh600519` / `sz000001` 及带前导零的港股代码。上海 `.SH` 后缀查询时转换为 Yahoo 的 `.SS`；已知股票和 ETF 代码段的交易所填错时，在请求行情前提示正确后缀，例如歌尔股份 `002241.SH` 应改为 `002241.SZ`。不根据 `000xxx` 推断交易所，保留上海指数与深圳股票的区别。纯数字代码有歧义，必须带交易所后缀。新增持仓可以留空价格，服务端保存前补齐；无代码、无数量、零数量及现金持仓不自动估值。代码能否查询取决于来源覆盖，场外基金等不可用标的继续手工记录。

Twelve Data [`/time_series`](https://twelvedata.com/docs/market-data/time-series) 是主动查询的可选来源。配置个人 Key 后，主动查询采用 Twelve Data；自动更新始终用免费公共来源。密钥按账号加密保存，通过 `Authorization: apikey …` 请求头发送，不进入行情公共缓存、AI 载荷或同步包。

每次查询明确提交证券代码和估值日。服务端回看最多 10 个自然日，只采用不晚于请求日的最近有效交易日。收盘截止按证券所属市场判断：沪深 `.SS` / `.SZ` 在北京时间 15:05 起允许采用当日收盘，港股 `.HK` 在香港时间 16:15 起、美股普通代码在纽约时间 16:15 起允许采用当日收盘，纽约时区自动处理夏令时；提前收市日仍等待通常收盘阈值，其他未识别市场保留 UTC 昨日的保守截止。阈值包含来源发布时间缓冲；沪深竞价收盘为 [15:00](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml)，港股收市竞价最晚至 [16:10](https://www.hkex.com.hk/Services/Trading-hours-and-Severe-Weather-Arrangements/Trading-Hours/Securities-Market)，美股核心时段至 [16:00](https://www.nyse.com/trade/hours-calendars)。交易所本地日期按来源的 IANA 时区解析，已识别市场的时区必须匹配；周末及假日仅采用来源实际返回的交易日期，不补造当日行情。自动查询使用上海日期，与统一汇率一致。Yahoo 读取 `indicators.quote.close`，不采用分红复权的 `adjclose`；其历史收盘价可能经过拆股调整，记录为 `split_adjusted_daily_close`，不冒称未复权。London 的 `GBp` / `GBX` 价格从便士换为 GBP，避免百倍金额错误。Yahoo 未提供 MIC 时保留空值。Twelve Data 使用 `adjust=none`，记录为 `unadjusted_daily_close`。

服务器启动时补查，并每 5 分钟按账号检查有证券代码、正数数量的普通持仓；现金、已清仓、无代码手工资产和期权不查价。后台采用上述收盘截止，只查询尚未取得该截止日收盘的持仓；已保存的行情日期作为重启后的完成依据，无需新增调度表或迁移数据。来源延迟、失败和节假日未取得新行情时继续重试，保留已有价格和真实日期；旧于已保存行情或手工估值日期的报价不覆盖当前值。服务器继续运行即可更新，浏览器无需打开，前端通过既有账号版本同步取得新快照。

后台查询先在账号锁内冻结持仓版本，等待行情时释放锁，返回后重新取锁并校验版本。查询期间发生交易、数量／代码编辑、删除或另一轮估值更新时，本次旧结果跳过，下轮重新读取；单只失败不阻塞其他持仓。价格、市值、精确会计、来源与当日资产观测沿用同一仓储事务；不修改真实成交、持仓成本或存款，不补写过去日期的价格，也不触发 AI。买点观察的收盘检查及 19:00 截止保持独立。

“更新自动价格”（`POST /api/market-data/security/refresh`）对有代码、正数数量的非现金、非期权持仓查询免费来源并逐项保存。保存普通持仓时，只有代码和正数数量已填而当前价格为空才先补查价格；已有价格不会因读取快照、每日补齐或版本检查而自动替换。`GET /api/market-data/security-price` 只返回报价，`PUT /api/holdings/{id}/verified-valuation` 才把指定报价日期的估值应用到账号。持仓写入由所属账号的锁和事务保护，服务端校验 Provider 币种与持仓币种一致，再以：

```text
原币市值 = 当前持仓数量 × 来源日收盘价
```

在同一事务内更新该持仓与当日资产观测，并在当前核验记录中保存数量、单位价格、市值、请求日、观察日、回退天数、价格口径、交易所、来源 URL、方法链接、限制和采集时间。`valuationDate` 保存请求日，实际价格日期独立使用 `observedOn`；每日条目冻结当时的精确会计值，AI 分析审计按授权冻结当时的估值依据，后续更新不改写此前记录。价格使用来源的精确十进制值；刷新时数量未变的手工持仓保留已存精确股数，成交管理持仓以成交重放结果为准。用户手工修改持仓代码、市值、币种或估值日时，当前核验记录会自动失效，避免旧来源继续为新数字背书。

### 只读证券报价与并发

`GET /api/market-data/security-price` 使用 `PortfolioService::preview_security_quote`：在请求已有的账号锁内选定来源并读取本次 key，只在该 Provider 查询等待期间释放一层账号锁，供应商成功或报错后先重获锁再返回。慢报价不占住同账号的快照读取和其他独立操作；该预览不写持仓、汇率、每日记录或账号版本。

在途预览使用开始时选定的来源和配置。期间修改或删除行情 key 不追溯取消已经发出的请求，下一次查询才采用新配置；不会为无关资料修改新增 409，也不自动换源重查。响应头仍表示请求结束时的账号 revision，不是报价所对应的全量资料快照版本；客户端不从证券或汇率报价 GET 接受新的写入基准，后续保存继续使用原有版本检查。

估值核验复用的 `security_quote` 仍在写入请求的账号锁内执行，随后由原仓储事务保存；本次解锁不适用于核验估值、保存持仓、价格刷新、汇率查询或汇率更新。取消整个预览 Future 沿用账号锁 helper 的既有释放语义，不承诺客户端断线一定立即取消服务端查询。真实两连接锁、冻结配置及认证 HTTP 回归见[应用测试](../server/src/application/portfolio_quote_tests.rs)与[HTTP 测试](../server/src/hosted_quote_tests.rs)。

## 服务全局缓存

免费价格 Provider 由运行时装配并跨账号共享实例、HTTP 连接池和进程内缓存；键包含规范化证券代码、请求日期及公司行动查询起点，缓存条目同时记录收盘截止日；收盘阈值跨越后立即重新查询，避免收盘前缓存挡住当日新价格，也避免不同成交历史范围复用不完整结果。仅缓存公共行情，不缓存持仓数量、个人市值或用户密钥；多 API 进程各有独立缓存。已覆盖收盘截止日的成功结果保存 1 小时，来源仍滞后的成功结果及失败仅保存 1 分钟；同一键使用独立异步锁合并并发查询，单个 API 实例最多 4 个上游查询，不让网络等待占住全缓存锁。最多 512 条记录，在容量不足时淘汰不在使用的记录，全部繁忙时返回可重试错误。每次响应流式限制 1 MB，每个上游请求超时 8 秒。

运行期间每小时刷新缓存中近期的当前标的，跨日使用新日期，不触碰账号数据；账号后台收盘刷新或用户点击更新时再应用可用报价。无变化时不重复写持仓、每日记录或数据版本。服务重启后按需重新获取，账号已保存的价格证据仍然保留。`POST /api/market-data/security/refresh` 返回 `{snapshot,updatedCount,errors}`；该操作尊重共享缓存和失败退避，不因重复点击增加上游请求。失败详情也放入本次返回快照的 `priceRefreshErrors`，不作为持久错误状态；界面保留原价并提示，币种、来源、日期或价格不合格时不更新对应持仓。

Twelve Data 的个人方案用于个人、内部和非商业用途；调用额度、市场覆盖、展示和再分发权利取决于用户自己的方案及交易所许可。当前 [个人价格页](https://twelvedata.com/pricing) 列出 Basic 免费方案的分钟和每日额度，完整使用限制见 [服务条款](https://twelvedata.com/terms)。mario 不内置共享密钥、不代理转售行情，也不保证任一代码或市场在用户方案中可用。

## 证券价格限制

- 日收盘价不是实时成交、券商结算价、可成交报价或内在价值；
- 日收盘价不自动处理分红再投资；Yahoo 历史价可能经过拆股调整，不能直接和拆股前数量相乘。拆股、合并、代码变化和其他公司行动需结合当时数量与券商记录核对；
- 现金、非上市资产和无支持代码的持仓使用人工市值，界面显示其来源与日期；
- 网络、超时、限流、权限不足、响应超过 1 MB、币种不一致、日期或价格异常都会停止更新，不回退到猜测值；
- 当前尚未在每个外部现金流时点重建全部持仓，因此仍不能计算严格时间加权收益率；
- 尚无基准指数与券商持仓导入。免费公开接口的存在不代表任意商业展示或再分发已获得许可。
