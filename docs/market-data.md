# 可追溯市场数据

## 产品目的

外币持仓和流水必须先换算到用户的基准币种，才能进入组合汇总、风险检查、规划和变化归因。完全手填的汇率容易产生日期错位、录入错误和无法追溯的问题。本模块提供可替换的 `FxRateProvider`，首个实现使用欧洲中央银行（ECB）公开参考汇率。

ECB 的 [Data Portal API](https://data.ecb.europa.eu/help/api/data-examples) 提供 SDMX 2.1 数据访问和 CSV 输出；mario 读取 `EXR.D.<currency>.EUR.SP00.A` 日度序列。ECB 说明参考汇率通常在工作日发布，属于买卖报价的平均参考值，仅供信息使用，并不代表实际市场成交价；完整边界见 [ECB 汇率说明](https://data.ecb.europa.eu/key-figures/ecb-interest-rates-and-exchange-rates/exchange-rates)。

## 换算协议

对原币 `from` 和基准币种 `to`：

1. 查询请求日期及此前 7 天的相关欧元参考序列；
2. 只选择不晚于请求日期、且两个币种都存在观察值的最新共同工作日；
3. ECB 数值表示“1 EUR 对应多少该币种”，因此计算 `from → to = to_per_eur / from_per_eur`；
4. EUR 一侧按 1 处理；同币种汇率恒为 1；
5. 返回请求日期、实际观察日期、回退天数、原始数据 URL、方法链接和用途限制。

系统不混用两个不同日期的币种观察值，也不把周末回退值伪装为当日成交价。当前客户端支持 CNY、USD、HKD、EUR、JPY 和 GBP。

## 自动更新与统一设置

“我的情况 → 汇率设置”是唯一汇率管理入口。持仓、现金、组合流水的表单不再要求填写汇率，CSV 模板也不包含汇率列。服务端自动查询 ECB，无需用户配置密钥。

服务运行期间每小时查询当前日期的完整币种表；每天首次读取账户会刷新当日汇率，打开的客户端通过已有版本同步应用变化。服务关闭期间不执行任务，再次启动后自动更新。ECB 按工作日发布，周末及假日采用不晚于请求日期的最近共同观察值，界面保留实际观察日期。

当前持仓统一使用当前账户基准币种对应的汇率；余额确认日期与汇率观察日期分别保留，更新汇率不会把沿用余额标成重新确认。不同账户、不同基准币种的手动设置相互独立。统一设置支持：

- 自动汇率及来源、观察日期、最近检查时间；
- 修改指定外币的汇率，作为持续有效的手动覆盖；
- “恢复自动”，撤销该外币的手动覆盖；
- “更新自动汇率”，立即重新向来源查询，不覆盖已有手动值。

新保存的组合流水按发生日自动读取参考汇率。发生日在手动覆盖生效日之后的流水使用该手动值；更早的发生日继续读取历史参考值。流水与组合检查点冻结当时的汇率及来源，后续自动刷新或手动修改不会改写历史。当前持仓使用 `central_daily` / `central_manual` 标记；流水使用 `ecb_reference` / `user_declared`。

账户汇率缓存和手动覆盖按账号保存，并随 v11 数据包导出、导入；仍兼容 v1–v10 数据包。导出只包含汇率设置，不包含模型配置、API Key 或本地提醒设置。CSV 旧汇率列可继续解析，但新记录最终统一由服务端汇率来源补齐；预览与提交之间若汇率变化，要求重新预览。

## 失败与限制

网络、超时、异常 HTTP 或无有效观察值时保留此前可用参考值并显示更新错误；没有可用值时保留原币金额，暂停对应换算，不猜测汇率。失败后可自动重试，也可在统一设置中手动指定或主动刷新。ECB 参考值仅供组合折算，不等同于券商成交价或银行结算价。

## 证券价格 Provider

`SecurityPriceProvider` 与汇率接口彼此独立。首个适配器使用 Twelve Data 的 [`/time_series`](https://twelvedata.com/docs/market-data/time-series) 日线接口。用户在“模型与隐私”中保存自己的 API Key；密钥由系统钥匙串或 Android Keystore 托管，并通过服务端 `Authorization: apikey …` 请求头发送，不出现在 URL、SQLite、AI 载荷、日志或同步包。

每次查询明确提交证券代码和估值日。服务端回看最多 10 个自然日，只采用不晚于请求日的最近有效交易日，并要求 Provider 同时返回计价币种、交易所、MIC 和证券类型。为避免把尚未收盘的当日日线误称为收盘价，请求最晚只取 UTC 昨日；因此估值日是今天时会显式回退到最近已完成日线。请求使用 `adjust=none`，保存的是未复权日收盘价；这是为了和用户声明的“估值日实际持有数量”相乘，避免把复权价与历史数量混用。

证券估值只能在已经保存的持仓上主动执行。服务端校验 Provider 币种与持仓币种一致，再以：

```text
原币市值 = 估值日持仓数量 × 未复权日收盘价
```

原子更新持仓，并在独立记录中冻结数量、单位价格、市值、请求日、观察日、回退天数、价格口径、交易所、来源 URL、方法链接、限制和采集时间。检查点复制当时的估值证据，后续更新不会改写历史。用户手工修改持仓代码、市值、币种或估值日时，当前核验记录会自动失效，避免旧来源继续为新数字背书。

Twelve Data 的个人方案用于个人、内部和非商业用途；调用额度、市场覆盖、展示和再分发权利取决于用户自己的方案及交易所许可。当前 [个人价格页](https://twelvedata.com/pricing) 列出 Basic 免费方案的分钟和每日额度，完整使用限制见 [服务条款](https://twelvedata.com/terms)。mario 不内置共享密钥、不代理转售行情，也不保证任一代码或市场在用户方案中可用。

## 证券价格限制

- 日收盘价不是实时成交、券商结算价、可成交报价或内在价值；
- 未复权价格不自动处理分红再投资；拆股、合并、代码变化和其他公司行动仍需结合当时数量与券商记录核对；
- 现金、非上市资产和无支持代码的持仓可以继续使用人工市值，但界面与风险检查会明确显示“未核验”；
- 网络、超时、限流、权限不足、响应超过 1 MB、币种不一致、日期或价格异常都会停止更新，不回退到猜测值；
- 当前尚未在每个外部现金流时点重建全部持仓，因此仍不能计算严格时间加权收益率；
- 后续还需增加公司行动、基准指数、券商持仓导入和可控缓存，并继续遵守各数据源许可。
