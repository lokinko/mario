## 先纠正对现状的三点理解

1. **已有资料摘要。** [问答预览](../../client/src/features/research/Advisor.tsx#L531)包含中文分组、是否选择、条数和说明，之后才是 JSON 正文。可以讨论入口是否足够显眼，不能称为“只有 JSON”或授权不起作用。发送每轮重读已保存预设并冻结输入，不新增每次确认。
2. **已有完整手写复盘。** [复盘页面](../../client/src/features/reviews/ReviewCenter.tsx)可新建自由文字，桌面主导航直达。手机 ≤900px 的快捷栏没有复盘，需“更多 → 复盘记录 → 新建”；[手机导航](../../client/src/app/navigation.ts#L64)、[小屏样式](../../client/src/styles.css#L577)与[应用壳](../../client/src/App.tsx#L484)说明该路径。主导航的 jsdom 测试没有验证手机 CSS，不能据此宣称手机底栏已直达。
3. **已有观察日期、状态和周内矩阵。** [公司列表](../../client/src/features/watch/WatchList.tsx)、[完整周表](../../client/src/features/watch/WatchWeekly.tsx)能看最新日期／当前状态及本周每日记录。真正缺少的是“哪一次未读变化”的日期和方向，尤其跨周尚未查看的变化。

### 1. 未读变化应解释到哪一层

[仓储](../../server/src/db/watch.rs#L135)按公司标记全部既有未读为已读，读取时用 `EXISTS` 聚合，返回的 [WatchRow](../../client/src/api/watch.ts)只带 `alert` 布尔。进入／退出的提醒以实际保存的有效状态变化为依据，数据不完整不当作退出；这与“当前状态”及“本周逐日状态”是不同信息。

候选展示例如“11-06 进入关注区间”。需要从已保存的提醒与当时状态取得依据，不能用当前配置投影后的 latest 倒推过去；历史不足以确认方向时只显示可确认的日期或“有未读变化”，不猜测。先保留公司级已读，不新增通知中心、站外推送或完整时间线。API 需要补充事件摘要；若要求恢复已被同日覆盖的信息或保留所有变化，还需另定存储边界。

**需要选择：** 日期＋进入／退出是否足够，还是同时需要解释股息、日线或周线哪一项发生变化？推荐先前者。

### 2. 周末先讨论哪五家

[前端组装](../../client/src/features/watch/BuyWatch.tsx#L278)使用 `rows.slice(0, 5)`，名单来自[按证券代码读取的仓储](../../server/src/db/watch.rs#L29)。[上方列表](../../client/src/features/watch/presentation.ts#L106)独立应用筛选、置顶及排序；[周末矩阵](../../client/src/features/watch/WatchWeekly.tsx#L54)则仍使用完整原始名单。因此当前批次与矩阵前五一致，不能笼统说“页面显示顺序错误”。现行行为已在[买点规范](../buy-watch.md#检查讨论与复盘)明确。

推荐候选保留最多五家，列清本次名单，并从完整自选按置顶／变化／关注优先选取，不随临时搜索、持仓筛选或数值排序改变。需要让显示名单、问题组装与服务端证据匹配协同验证，不能只改按钮文案。[证据选择](../../server/src/application/analysis.rs#L154)还要求问题命中公司、已有观察和来源，且所有研究证据共享五条上限；“选中讨论”不等于“已有足够证据”。不扩大公司或证据上限。

**需要选择：** 采用置顶／变化优先，还是保持代码顺序、仅列清本次五家？后者改动更小，前者更接近平日关注顺序。

### 3. 是否需要讨论后直接写复盘

[问答结果](../../client/src/features/research/Advisor.tsx)没有打开个人复盘的动作；[现行复盘规范](../review-and-rules.md)要求用户主动保存自己的文字，模型回答只留在问答历史。快捷入口的价值是衔接话题，而不是补一个缺失的复盘功能。

若采纳，建议只在从观察发起的周末讨论完成后出现“写下本次复盘”，打开现有空白草稿；通过应用壳协调，不让 research 功能引用 review 功能内部组件。仍由用户填写和保存，不预填模型结论，不新增周期／评分，也不为此改手机全局导航。已有未保存草稿必须继续受保护。

**需要选择：** 这个直接写作入口是否有用，还是现有导航已经足够？可在用户形成记录习惯后再做。

### 4. 资料摘要若外显，必须说明实际输入

[发送逻辑](../../client/src/features/research/Advisor.tsx#L131)每轮重读问答预设并生成实际预览。关闭持仓授权就不发送持仓与交易，关闭研究证据就不发送观察依据；这是正确边界。现有问题也已使用“授权的”资料措辞。

若要外显，复用真实 `preview.groups` 的条数、说明和生成时间，并在问题或资料变化后标为待刷新。尚未准备预览时最多写“预设允许”，不能仅凭授权开关就说“观察已带入”。建议当前继续使用已有抽屉，优先解决未读变化和周末批次。
