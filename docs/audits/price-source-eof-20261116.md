# 价格来源提前断连排查与重试修复（2026-11-16，历史记录）

## 现场证据与判断

用户部署版本为 `5998ff7`，dashboard 的逐股错误为东方财富网络传输失败、Yahoo query1/query2 超时。云端只读检查显示：东方财富一个请求曾返回 HTTP 200、约 0.31 秒；Yahoo 两个域名均在连接 443 时超时，没有取得 HTTP 响应。

随后云端日志明确定位到东方财富 `/api/qt/stock/kline/get` 的 `fqt=0` 原价日线：Reqwest Request → Hyper SendRequest → `UnexpectedEof`，对端没有发送 TLS `close_notify` 就断开连接。普通 A 股、ETF 及海外证券均有相同错误，不能据此归因于单个证券解析。

同一地址的 curl HTTP/1.1 与 HTTP/2 请求也均发生 OpenSSL unexpected EOF；同日期、同参数，仅改变字段列表逗号是否编码为 `%2C` 的两次请求均失败。因此没有将该故障归因为逗号编码、Rustls 独有缺陷或 HTTP 版本，也没有为此更换查询格式、TLS 后端或放宽验证。底层原因仍可能涉及源站、边缘节点或出站线路；单次 HTTP 200 不证明整条采集流程持续可用。

[Rustls 官方说明](https://docs.rs/rustls/latest/rustls/manual/_03_howto/index.html#unexpected-eof)说明 `UnexpectedEof` 与未发送关闭通知有关。程序仍须校验完整 HTTP 消息；本次修复不把截断正文作为有效行情，也没有忽略 TLS 错误。

## 代码修复

原东方财富原价／前复权 GET 使用单次发送，未经过历史来源已有的有限重试；原重试条件也未覆盖发送中断和响应体提前关闭。现在这些请求与 Yahoo 历史 GET 统一使用同一请求函数，对连接、超时、传输中断、HTTP 429/5xx 最多重试一次，沿用 200 毫秒间隔。保留原 Referer，JSON 解析或资料校验错误及 404 不重试。

网络错误增加原价日线、前复权日线、公司行动资料、Yahoo 日线／行动历史阶段说明；后台日志继续保留原错误链。单次请求 8 秒、东方财富整组 24 秒、公共单证券 90 秒及后台每轮原有截止保持不变。没有新增来源、改数据契约、调整观察条件、放宽价格与行动校验、修改数据库或把失败状态改成成功。

当前行为与验证要求见[市场数据](../market-data.md#来源与十年窗口)、[模块边界](../module-boundaries.md#持仓收盘估值)。云端持续提前断连和 Yahoo 无法建立连接尚未恢复；这份记录只确认恢复策略与诊断改进，不证明部署后 300 只已获取成功。
