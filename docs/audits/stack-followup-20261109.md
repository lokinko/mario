# 技术栈后续优化验收（2026-11-09）

## 范围与设计

沿用[架构说明](../architecture.md)第 3–5 节的依赖方向、第 6 节的冻结输入流程和第 7 节的状态／事务归属，继续解决观察、账本与讨论使用中的等待、加载和维护成本。本轮按用户要求执行剩余第 1、3–8 项；第 2 项 Linux 环境验收不执行。上一轮验收见[技术栈简化](stack-simplification-20261109.md)。

| 项目 | 本轮交付与边界 |
| --- | --- |
| 1. 模型连接测试解锁 | 锁内冻结已保存配置与凭据，外部等待时解锁，返回重取锁并核对原目标；无关资料修改允许通过，模型或凭据改变返回 409。失败、取消和成功均不保存测试结果，不推进账号版本。真实独立 PostgreSQL 连接验证锁释放与重获。 |
| 3. 阶段观测 | `mario::timing` debug 事件覆盖物理连接、schema 绑定、SQL、租约／清理、账号锁、供应商、快照构建／序列化与 HTTP 状态；不记录 SQL、参数、连接地址、密钥或请求正文。409／503 可从状态字段聚合。 |

## 测量证据

`npm run measure:storage` 创建一次性本机 PostgreSQL，20 个合成 CNY 持仓，每种模式读取 30 次。以下是同次配对测量，单位毫秒；不代表生产 HTTP 延迟、线上容量或多账号吞吐。

| 阶段／模式 | p50 | p95 |
| --- | ---: | ---: |
| 新建连接读取 | 167.543 | 193.817 |
| 租约读取，含归还清理 | 13.020 | 19.784 |
| 同一已打开连接读取 | 12.224 | 17.567 |
| 物理连接与 schema 检查 | 151.143 | 177.544 |
| 快照计算 | 11.989 | 17.117 |
| 账号锁等待 | 0.214 | 0.432 |
| JSON 序列化 | 0.378 | 0.524 |

瓶颈主要是连接建立，因此保留现有数据库边界与驱动，仅复用安全清理后的租户连接。回归覆盖独占租约、租户隔离、空闲上限、最近租户保留、未提交／失败事务、advisory lock、临时对象、search_path、超时及断线替换；不以耗时阈值断言正确性。

前端本轮前主 JS 为 898,997 字节（gzip 约 286.55 KB），最终主 JS 为 741.90 KB（gzip 239.05 KB），分别减少约 17.5%／16.6%；辅助页另有独立 chunk。此数字只比较初始主 JS，不声称总资源或线上加载速度同比下降。既有大于 500 KB 的 Vite 提示仍保留。

## 验证与交付

日志隐私回归在完整并行测试中暴露了线程局部订阅器与共享调用点初始化的捕获问题，最终改为独立测试进程先安装全局订阅器，按生产启动顺序实测连接／绑定／SQL／账号锁事件并检查参数、SQL 与数据库地址不入日志；未添加生产测试开关或删除断言。本机 Git `bin/git.exe` 启动器曾偶发空输出，最终门禁使用随运行环境提供的稳定 Git 可执行入口，来源指纹回归保持原断言。

一次门禁在 Vite 已完成构建后遇到本机 Node 24.14.1 的 libuv Windows 断言退出；最终验证改用环境自带的 Node 24.22.1，依赖版本与门禁断言不变。

最终完整 `npm test` 退出码为 0；数据库验收仅使用脚本创建并销毁的临时 PostgreSQL，不读取部署 `.env` 或生产数据库。
