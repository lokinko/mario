# 多代理评议与长期记忆实际回复验收（2026-11-16）

## 结论与边界

本记录验收 `investment-workflow-v17` 的[多代理评议](../ai-workflow.md#多代理评议)与[长期记忆整理](../ai-memory.md)。主负责人逐份阅读了每个采纳报告的正文、建议、例外条件、事实与引用，以及研究简报、选票和计票；整理代理的提案逐条阅读。

**只运行了24题固定虚构题集中的6题子集**（`reduce`、`followup`、`watch-add`、`watch-no-personal`、`quality-source-conflict`、`quality-summary-unread-source`），覆盖减仓、追问、观察名单加仓、未授权个人资料、同期间来源冲突和摘要冒充原文。未运行v17完整24题，不能写成全题集通过。所有题目 `webSearch=false`，使用 `.runtime/qa-eval.env` 的 `openai-responses / gpt-6.1-sol` 专用配置，只读取固定虚构资料，不访问真实账号数据库、不改资产或交易，整理结果只写报告文件、不入库。

## 第一轮：发现两项缺陷

报告 `.runtime/qa-eval/council-v17-20261116.json`（含 `MARIO_EVAL_DREAM=1` 的 `.dream.json`），6题均完成。

- 采纳报告语义全部达到[实际回复质量验收](../ai-workflow.md#实际回复质量验收)门槛：首句直接回答，960,000元人民币子集、83.33%、0.83个月覆盖、1.5÷25＝6%、+0.8065%偏离等计算可复核，未生成买入股数，未把观察信号当作低估证明，摘要未被当作已读原文。仅见一处全角字形笔误。
- **缺陷一：研究代理在3道含个人资料的题目全部两次校验失败**，引用了对象（`/facts/dataIssues/0`）或空值（汇率缺失时的 `portfolioValue`）。原因是研究契约只写“引用规则与报告facts相同”，没有给出“只引非空标量、空值改引问题码”的规则；错误信息统一为“无效或未授权”，修复无从对照。方案代理收到完整规则，均一次通过。
- **缺陷二：投票没有区分力**。5/6题三个方案都得满分20，采纳完全由方案顺序决定，状态却显示为 `voted`，会被误读为评审偏好。
- 整理代理提出3项新增、0项被拒：1条用户原话偏好（逐字摘录、注明授权仍按当轮）、2条模型推断观点（附适用条件与重新核算条件）；没有把模型答案写成用户偏好。

## 修复

- 引用规则抽为报告与研究简报共用的同一段提示；校验错误分别写明未授权、不存在、指向对象或数组、值为空（附改引问题码示例）。
- 选票新增必填 `preferred`：在展示方案中选一个愿原样采纳的方案，不能选自己否决的方案，全部否决时为null；评分说明增加“2分表示找不到可指出的缺陷，质疑所指维度不给2分”。
- 计票先比首选票再比均分；胜出与次名在首选、均分、否决上全同时状态为 `tied`，阶段文字与“评议过程”写明按方案顺序采纳。

## 工程验收中发现的桥接缺陷

`test-codex-bridge --protocol-fixture` 显示：配对桥接一次只处理一个请求，三个并行方案代理中两个被“正在处理另一请求”拒绝，评议退化为单方案、未投票，阶段却写成“1 个通过校验”。默认 `npm test` 只运行 JavaScript 模拟 worker，未发现该问题。已修复为执行端声明 `accepts_concurrent_calls=false` 时依次执行方案与选票，模型调用失败与格式校验失败分开计数，并把协议夹具接入完整门禁。真实 Codex 或 ChatGPT 订阅推理未在本轮执行。

## 仍然存在的限制

- 三个代理使用同一模型，评分仍有饱和倾向；`tied` 只保证不把顺序冒充偏好，不保证选出最佳方案。计票通过不证明结论正确。
- 单张选票可能因超长质疑或漏评被作废，评审人数随之减少。
- 子集与固定虚构资料不能代表所有未来回答，也不构成真实证券估值或收益证明。整理代理只验收了一批输入，修复未改动其契约。
