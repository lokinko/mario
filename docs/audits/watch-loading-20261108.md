# 买点观察首屏加载优化验收（2026-11-08）

本次处理用户确认的“刚进入买点观察就很慢”，部署目标为 2 核 4 GiB。这里记录代码与隔离验收证据，未连接部署机采样，不把本机耗时称为线上结果。长期契约见[买点观察](../buy-watch.md#观察桌面)。

## 原因与设计

原首屏同时请求自选和全部行业；同账号请求都取账号锁，两者实际会排队。自选 `watch_board` 对每家公司分别读取最新观察、检查状态、检查截止、未读状态，共 `4N+3` 次业务查询，之后还读取本周所有完整观察。行业目录对每家公司单独读快照。五年趋势和三年展示分红随每条完整观察一起反复解析、序列化和传输。前一轮五年趋势改造放大了这条既有读取路径。

按[架构说明](../architecture.md#65-买点观察)与[模块边界](../module-boundaries.md#买点观察趋势)分工：仓储批量投影列表摘要，应用层装配公共目录，HTTP 继续认证、账号锁和只读规则投影；前端详情拥有异步证据状态。没有把列表读取改成行情抓取，也没有放宽账号锁或改动财务事务。

## 实现与替换

- 自选列表固定 3 次业务查询：规则、批量条目/最近观察/未读状态、本周观察；50 家由 203 次降为 3 次。不含认证、建连接、schema 版本及账号锁本身的基础查询。
- 公共目录一次读目录、一次批量读当前成员摘要，删除逐家公司 `get` 循环；已移出目录的残留快照不进入摘要。
- SQL 在返回应用前去掉 `trends` 与 `dividendHistory`，包括周内记录。价格、日周指标、分红金额、实际日期、来源、规则、提醒与网格投影保留，AI 授权复盘原先使用的周内字段保留。
- 新增已认证 `GET /api/watch/{symbol}/observation`、`GET /api/watch/catalog/{symbol}/observation`，只读一家公司完整观察行。个人详情限本账号现存条目，公共详情限当前目录成员；读取不改写公共快照、账号版本或冻结历史。
- 首屏自选读取完成后再读轻量公共目录，公共请求不挡住已取得的自选；每 30 秒仅读当前分组的列表。打开公司后才加载完整证据，关闭、切换公司或摘要更新时取消旧请求。错误保留摘要，提供独立详情读取重试，不误报为无历史。

旧的全列表完整证据返回及逐家公司读取已由上述路径替换。没有新增持久缓存、schema 或备份版本；完整观察仍在原 payload 中，个人及整站备份保留。无需数据迁移、回填或重抓行情；失败保留原记录，回退到上版代码仍能读取原存储。详情 API 与当前前端应随原 `deploy.sh` 一起发布。

## 容量与行为验证

隔离 PostgreSQL 用合成数据创建 50 家自选，每家保存一周 5 条观察，每条包含五年日线计算出的至少 260 个周趋势点。列表响应为 **254076 字节**（约 254 KB）；300 份完整观察体本身为 **14614200 字节**（约 14.6 MB，尚不含旧响应外层条目等数据）。按此保守对照，列表体积减少约 **98.3%**。本机 debug 构建读取与序列化该摘要约 **151.5 ms**，此数字不包含真实认证/建连接/HTTP 传输，也不代表 2c4G 部署机耗时。未设依赖机器速度的毫秒断言；回归验证摘要比例和完整证据保留。

- 前端：53 文件、350 项通过；TypeScript/Vite 构建与 Prettier 通过。覆盖行业未完成时自选可显示、未打开详情不请求证据、切换公司迟到响应、关闭取消、失败后独立重读和观察更新后失效。
- 后端：346 项通过、5 项联网测试默认忽略；fmt、全部 targets 的 Clippy（warnings 为错误）及构建通过。此次只改数据库读取，未运行与此无关的联网来源抽查。
- 真实 HTTP 使用两线程 Tokio 与一次性 PostgreSQL：未认证详情返回 401，其他账号读取私人条目返回 404；自选列表不带趋势，详情保留趋势和三年展示历史；公共详情按账号规则投影；前后版本及个人备份内容指纹相同，没有供应商调用。
- 仓储验证本周各日历史状态、失败保留、未读提醒、网格和备份恢复；迁移/恢复的完整证据断言经单公司详情读取验证，摘要另断言不带趋势，没有放宽原数据恢复保证。
- 架构检查通过。完整 `npm test` 已执行，仍在 `scripts/server-artifacts.test.mjs` 因仓库既有缺失 `scripts/test-financial.mjs`、`scripts/test-backup.mjs` 等夹具源而失败，后续桥接/Web/财务验收链未执行；未关闭或放宽门禁。

## 交付与清理

本次提交并推送代码，不部署；上线后仍需测量部署机的首字节时间、响应体积及 CPU/内存，才能确认实际延迟改善。公共摘要仍由 PostgreSQL 从原 JSON 投影，未引入额外状态；全局请求账号锁、连接初始化与其他后台资源竞争继续沿原架构运行，不声称所有性能开销已经消除。
