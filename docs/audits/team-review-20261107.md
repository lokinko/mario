# 2026-11-07 智能体团队首轮审查

## 范围与方法

本轮由前端、后端、测试和产品体验四个角色分别审查，主智能体复核调用链、整合修复并统一验证。以[产品目标](../product-vision.md)中的“认可公司 → 收盘检查 → 变化提醒 → 结合真实交易讨论 → 周末复盘”为优先级，兼顾账本精度、账号隔离和测试真实性。未开展 benchmark 新研究，未部署，也未进行真实账号或生产数据验收。

初次检查存在其他任务尚未提交的股数网格与 schema/备份迁移，审查未覆盖或替换这些改动。其他任务随后自行提交为 `931d944`；审查期间又提交账号观察规则与备份 v28（`0deea99`、`e6d259c`）。本轮将这些已提交更新整合至隔离工作树，保留其契约，只交付下述独立修复。

静态审查结论不等于浏览器实测。以下区分确定缺陷、产品讨论和验证入口的后续事项；尚未采纳的建议不是产品要求。

## 本轮修复

| 问题 | 触发与影响 | 修复边界与验证 |
| --- | --- | --- |
| 离开页面丢失草稿 | 方法论编辑后点击导航或通过浏览器历史离开，页面卸载且无提示；重新进入只剩已保存正文 | 应用壳统一保护会卸载的页面草稿，拒绝跳转保留地址和输入；同页导航及常驻问答保留语义。覆盖取消、接受、地址/历史跳转及问答常驻回归 |
| 旧历史覆盖新公司问题 | 问答历史详情仍在读取时，从观察页发起新公司讨论；旧详情稍后返回，清空已填入的新问题 | 接收新问题时使历史请求失效并清理读取状态；延迟响应回归验证新问题与新对话保留 |
| 展示筛选被误认作草稿 | 观察页搜索、持仓筛选与排序触发全局变更捕获，产生无实际业务修改的草稿标记 | 工具栏按现有 `data-presentation` 约定标记，只影响展示状态 |
| 局部汇率读取提前确认远端版本 | 其他设备修改资产后，本设备先打开汇率抽屉；局部 GET 采纳新版本但资产快照未加载，后续版本轮询不再发现变化 | 只读汇率设置不采纳快照版本，显式保存与完整快照继续按原政策推进；API 回归覆盖旧版本保留、远端变化可发现及写入冲突 |
| 当天汇率查询返回错误币对且写账号数据 | 记账币为 CNY，查询当天 USD→HKD 却从 CNY 汇率表按原币取值；缺失/过期时还触发完整汇率刷新 | 仅只读复用目标币匹配且有效的缓存，未命中查询请求币对；查询前后版本与完整导出内容不变，成功、过期和来源失败都覆盖 |
| 行情刷新覆盖精确股数 | 手工持仓保存无法由浮点精确表示的股数，刷新报价后以浮点字符串覆盖原十进制股数，并据此重算成本、市值 | 未修改股数时保留持久精确值，交易管理仍由成交重放数量决定；验证精确成本/市值、备份恢复和显式数量修改 |
| 期权报价旧版本回执无法重放 | 报价已提交但响应及回执查询都失败，原请求重试在 HTTP 版本检查处被拒绝 | 在既有财务回执分支补充期权报价，不豁免新写入版本检查；真实 HTTP 覆盖跨实例重放、一次回执/日志、内容冲突和账号隔离 |
| 测试隐式继承外部目标 | 完整验收虽创建一次性数据库，父进程的功能测试 URL/令牌仍可令子步骤改用其他站点与账号 | 启动边界剔除隐式外部目标，只保留调用方显式传入的临时服务配置；短命 Node 子进程覆盖环境剔除、显式覆盖、数据库与 PG 选项隔离 |
| 自选详情隐藏本次来源失败 | 列表显示读取失败，但详情只展示旧观察和新的检查时间；抽屉遮住列表修复入口 | 详情在数据旁说明失败及保留的行情日期，首次失败也可就地重新检查；忙碌时禁用重试，成功不显示失败 |

## 待讨论的产品取舍

### 变化提醒应解释哪一层信息

当前仓储将历史未读变化聚合为一个布尔值，界面提供“标为已读”，不直接说明变化日期与进入/退出方向。如果周五进入、周一退出、周二才打开，当前状态与未读标记不能解释错过的变化。

证据：[提醒聚合与已读](../../server/src/db/watch.rs)、[行内提醒](../../client/src/features/watch/WatchList.tsx)、[本周矩阵](../../client/src/features/watch/WatchWeekly.tsx)。

建议先在公司行显示最近未读变化的日期和方向，详情再展示变化条件。较轻方案只显示“某日进入/退出关注区间”；完整事件列表信息更多，操作与实现成本也更高。当前不建议另建通知中心。

### 周末复盘先讨论哪些公司

当前“前 5 家”来自按证券代码排序的原始名单；页面显示顺序则先置顶，再优先未读变化和关注状态。用户置顶的高代码公司可能没有进入默认批次。五家上限本身已有明确约定，不作为缺陷。

证据：[原始名单顺序](../../server/src/db/watch.rs)、[复盘问题组装](../../client/src/features/watch/BuyWatch.tsx)、[显示排序](../../client/src/features/watch/presentation.ts)。

建议保留上限，先明确显示本次五家公司，默认按未筛选名单的置顶与变化优先选择。备选是手选最多五家，控制更强，但增加操作。若采纳选择策略，服务端证据的匹配与排序也应一起验证，不能只修改问题文案。

### 如何说明讨论实际带入的资料

观察页始终请求“结合我的交易讨论”，但问答遵循已保存授权预设。关闭持仓或研究证据时，相应交易、现金或观察不会发送，这一过滤行为正确；当前资料预览需要主动打开，主体是 JSON。

证据：[观察发起讨论](../../client/src/features/watch/BuyWatch.tsx)、[问答采用预设](../../client/src/features/research/Advisor.tsx)、[授权事实卡](../../server/src/context/fact_sheet.rs)、[观察证据授权](../../server/src/application/analysis.rs)。

建议输入区显示简短、中性的范围摘要并链接现有预设，例如“持仓和交易未授权”“观察依据已带入”。继续自动使用保存的预设，不新增每次确认，不自动扩大授权。更轻方案是只调整入口文案，但解释能力有限。

### 如何从讨论进入个人复盘

周末入口进入问答；用户若想写自己的“下周继续等什么”，仍需去复盘记录新建，手机还需经过“更多”。模型回答留在问答历史，不等于用户已写个人总结。

证据：[周末讨论入口](../../client/src/features/watch/BuyWatch.tsx)、[问答结果](../../client/src/features/research/Advisor.tsx)、[个人复盘](../../client/src/features/reviews/ReviewCenter.tsx)。

建议提供“写下本次复盘”，打开现有自由文字编辑器；最轻方案只跳转到复盘记录，更连贯的方案带入公司和日期。个人结论仍由用户填写，不自动将模型答案保存为用户判断。

## 后续验证事项

以下为审查发现，尚未纳入本轮修复，也不声称对应业务功能已经出错：

- 完整门禁构建尊重 `CARGO_TARGET_DIR`，部分 Web/Codex 验收默认二进制路径固定，且可继承 `MARIO_TEST_SERVER_BIN`；非默认环境可能验收旧产物。后续应让各套件绑定本轮构建输出。本轮验证显式使用隔离树标准构建路径并清除上述外部覆盖。
- Codex 完整门禁默认采用 JS 假 worker；现有 `--protocol-fixture` 可覆盖真实 worker 的 503 恢复、状态传递和输出后不重放，但未接入默认完整入口。
- 加密备份 CLI 已有独立验收，但默认完整门禁只含财务层的原生 `pg_dump`/`pg_restore` 逐表比较；加密封装、主密钥发布、会话撤销和错误密码等还需单独运行既有备份验收。
