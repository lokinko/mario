# 持仓价格联网与刷新超时验收（2026-11-08）

本记录说明用户部署后的反馈与本次验收，不作为通用研究或产品扩张计划。当前行为归[市场数据](../market-data.md)，模块职责见[架构第 6.3 节](../architecture.md#63-行情与汇率)与[持仓收盘估值边界](../module-boundaries.md#持仓收盘估值)。

## 问题与复现

用户反馈部署后没有看到自动补价，点击“更新自动价格”提示“请求超时，写入可能已经完成”；询问持仓后台日志后，用户反馈均为“外部网络请求失败”。这支持后台查价已尝试但来源访问失败，尚不足以判定服务器的具体 DNS、连接或 TLS 故障。

代码中另有两个可确定复现的缺陷：

- 客户端价格刷新采用默认 15 秒超时；Yahoo 两个域名每个可等待 8 秒，多批持仓耗时还会累加。新增传输测试模拟 16 秒返回，在修复前复现了用户看到的提示。
- 手动价格刷新仍持有请求账号锁等待网络；新增独立数据库连接测试在修复前无法取得该锁，验证了慢查价会阻塞同账号操作。

## 最终实现

- 沪深 A 股股票免费价格改为东方财富未复权日线优先，完整核验已实施送转后才采用；失败整组回退 Yahoo，来源滞后时比较实际交易日，日期较新者优先，同日优先国内原价。ETF、指数及港美股等维持 Yahoo 路径。
- 送转沿用观察模块的完整分配分页与解析；缺页、未知历史、错证券或协议失败不会解释为没有行动。按每十股比例登记待确认公司行动，继续由用户核对，不自动改数量。
- 国内适配器经既有价格端口注入免费 Provider；缓存与并发预算保持单一所有者，不让行情适配器读取账号库。新增来源采用现有估值记录和备份结构，无 schema 或备份版本迁移。
- 手动与后台刷新共用锁内冻结、锁外查价、重取锁后逐持仓版本校验。并发编辑、交易、删除和新估值优先，保持原有估值及当日资产观测事务。
- 整轮查价共用 90 秒截止，包含并发排队和缓存等待；到期取消未完成网络，不再开始新批次查询，保存已取得的有效报价，其余逐只返回错误。前端该入口等待 180 秒，写请求仍只发一次。
- 后台启动和每账号完成新增日志；逐来源失败记录底层错误详情，便于区分触发失败与来源访问失败。

## 验收结果

- `npm run test:server`：348 项通过，原有 6 项外部依赖测试忽略；只连接脚本创建并最终删除的一次性 PostgreSQL。
- 前端构建、Prettier、全部 341 项 Vitest 通过。新增传输测试确认 16 秒返回时不中断、不重复提交，并采纳返回版本。
- Rust 格式检查、Clippy 全目标零警告和构建通过；架构边界检查及 `git diff --check` 通过。
- 国内来源回归覆盖原价精确值、证券与交易所、重复日期、缺页、已实施送转、待确认行动、恶意来源／复权参数／重复参数、账号备份恢复；免费 Provider 回归覆盖国内优先、整组回退、滞后日期择新和全失败。
- 截止回归使用暂停时间验证：六只虚构持仓中保留一只成功，五只分别报错，90 秒到期后不再开始后续批次网络；原值保留。并发回归覆盖手动及后台在途编辑、删除与较新报价优先。

另创建一次性真实托管 API 与虚构账号，使用关闭的本地代理阻断 Yahoo，仅允许国内来源及本地 API 直连；先验证 AAPL 报价失败，证明 Yahoo 确实不可用，再完成：

1. 建立中国移动 `600941.SS` 测试持仓（虚构 10 股，原价 100.49，估值日 2026-10-14）。
2. 通过认证 POST 手动刷新，约 0.4 秒返回更新 1 项且无错误；价格 103.49，实际收盘日 2026-11-06，来源 `eastmoney_daily_close`，精确会计及重新读取一致。
3. 将同一测试持仓恢复为旧价并停止临时服务；再次启动后只读取快照，没有调用报价或手动刷新，后台约 1 秒自动恢复到 103.49。启动与账号完成日志均存在。

这些时间只记录本次联网样本，不是延迟承诺。测试没有读取或改写用户真实持仓、线上账号或线上数据库，也没有重启线上服务。
