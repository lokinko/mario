# 2026-11-02 benchmark 策略探索（第一轮历史记录）

> 本文记录第一轮交付时的参数变体与成绩，不代表当前策略目录。第二轮已按“一种逻辑只保留最优参数”合并：`trend_core25_sat75_m15` 改为 `trend_core_satellite`，`trend_single_m15` 改为 `trend_single`，其余 7 个参数变体删除。当前排名以 [benchmark 文档](../benchmark.md) 为准。

本次在 `pools-v5-20261031` 上比较 620 组参数，找到更高的切片总分，未找到可以确认的样本外优势。最佳组合总分从 3.3855 提高到 3.4959，代价是更高的个股集中度、更低的胜率及更差的单期尾部表现。分数提升主要来自 2018–2025 年，2006–2017 年反而弱于原第一名。

## 设计与范围

沿用[架构说明的离线 benchmark 研究工具](../architecture.md#离线-benchmark-研究工具)和[模块边界](../module-boundaries.md)中已有的新增策略方式：增加 `benchmark/strategies/<名字>/strategy.py`、`strategy.md` 及所属测试，不改变评分公式、输入契约、CLI 或依赖方向。另外修复正式验证发现的 Windows 隔离子进程编码问题：`-I` 会忽略环境中的 `PYTHONUTF8`，因此执行器显式使用 `-X utf8`，父进程通信也固定 UTF-8，保留原有隔离和导入限制。

- 策略只接收 `decide(sample)` 的当期输入，输出目标仓位和预先确定的卖出/网格规则。正式评测由原有静态检查、隔离子进程和 `scoring.py` 完成。
- 研究者可以用结果标签比较参数；最终策略运行时不能访问标签。参数选择偏差与策略执行时的未来信息隔离是两件事，本轮只保证后者。
- 研究发布包、扫描缓存、仓位、成绩和看板归 `.runtime/benchmark/`，没有账号状态、在线业务事务、数据迁移或生产路径替换。不新增依赖和共享模块。
- 本次不部署、不上传 HF、不修改已发布标签。HF 的 `pool-scoring-v5` 仍附原来的 14 个策略成绩；本地正式评测和看板现在包含 23 个策略。

## 数据与实验顺序

使用两个私有数据集仓库的不可变 `pool-scoring-v5` 标签，按 `hub-fetch` 合并并校验发布包哈希，恢复为 `.runtime/benchmark/pools-v5-20261031`。共 148 个季度决策点：科技池 2006–2025 年 80 期，红利池 2009–2025 年 68 期。当前数据不是截至 2026-11-02 的新增行情切片。

先用 `bench-run` 复跑原有 14 个策略，成绩与既有记录一致。第一阶段每个家族只按 2006–2017 年的 84 期选择参数，锁定后查看 2018–2025 年的 64 期。这段历史已经被此前研究使用，因此也不是独立留出集。

早段选择没有产生跨段一致领先原策略的结果。例如，集中持股家族在早段选出“中期动量低波前 1、动量门槛 10%”，全段总分 3.3077、后段 2.7607；核心/卫星家族在早段选出卫星 75%、门槛 10%、持股 1 只，全段 3.4197、后段 3.1558，后段弱于原第一名的 3.2632。按池分别选规则的组合早段 3.6254，后段退化到 2.4757，未采用。

第二阶段明确改为探索**当前切片上的样本内得分**：用全部 148 期总分排序参数配置，并将最终排名与已有策略合并。等效配置去重后，最终 Top-10 有 9 个新配置和原第一名。只固化这 9 个新配置，其他参数试验不创建策略目录。分段成绩仅用于诊断，不能再用后段声称独立验证成功。

## 保留规则与最终 Top-10

单股卫星：在动量严格超过门槛的候选中，按 63 日波动升序与 **63 日总动量**降序的名次和取一只，不使用剔除最近一月的动量。核心：沿用原行业分散的中期动量低波前 3。各部分没有符合门槛的股票时分别回退到全池低波 5 只等权，不是一直单股；没有可用标的的预算留作现金。两个部分重叠的证券先合并仓位再截断到 8 位小数。

两个部分统一沿用原卖出规则：红利 10% 止盈，科技池日波动低于 2.8% 才使用 8% 线距、2 份资金、初始 1 份的网格，其余持有到期。网格仓位是资金上限，因此目标预算不等于初始实际股票仓位。

## 收益与风险判断

本节的“最差一期”是 90 天窗口内三段加权的**收益得分**，不是连续组合的最大回撤，也不是单段收益率或年化收益。

| 方案 | 总分 | 平均收益得分 | 胜率 | 最差一期收益得分 | 相对原第一名的总分差 95% 区间 |
| --- | ---: | ---: | ---: | ---: | --- |
| 原行业分散策略 | 3.3855 | 1.4767 | 76.4% | −11.1091 | — |
| 核心 25% / 卫星 75%，门槛 15% | 3.4959 | 1.6716 | 73.0% | −13.6105 | [−0.3337, 0.5519] |
| 核心 50% / 卫星 50%，门槛 15% | 3.4638 | 1.6057 | 74.3% | −12.2749 | [−0.2109, 0.3640] |
| 核心 75% / 卫星 25%，门槛 15% | 3.4158 | 1.5408 | 75.0% | −11.5525 | [−0.1437, 0.2065] |
| 全卫星，门槛 15% | 3.4787 | 1.7388 | 69.6% | −16.5004 | [−0.5207, 0.6917] |

配对区间按同一样本的新旧逐期总分之差计算，以自然年为簇，把同年两个池子的所有决策点一起重采样；20 个年份有放回抽取 10000 次，每次用被抽中的实际期数计算均值，随机种子为 20261102，排序后取下标 250 与 9749。它保留同年同市场依赖，但未校正参数搜索后的选择偏差，也不保证覆盖所有跨年相关性，所以不能作为显著性的证明。所有区间都覆盖 0。

若继续研究，50%/50% 是比单股更适合比较的中间方案；若只追求本切片总分，25%/75% 排第一。两者都没有达到替换原策略所需的独立验证证据。下一步应固定规则后使用新的前瞻决策点或此前未反复研究的数据；继续重扫这 148 期只能提高样本内选择程度。原始数据的成分代理、事后维护行业、停牌与公司行动近似等限制继续适用。

## 复现与验证

在仓库根目录使用约定虚拟环境执行：

```powershell
. D:/Users/Desktop/home/code/.venv/Scripts/Activate.ps1
npm run benchmark -- hub-fetch --repo lokinko/mario_bench --labels-repo lokinko/mario_bench_labels --tag pool-scoring-v5 --out .runtime/benchmark/pools-v5-20261031
npm run benchmark -- bench-run --release .runtime/benchmark/pools-v5-20261031
npm run test:benchmark
npm run check:architecture
```

测试覆盖核心行业限制与卫星总动量选择的区别、重叠预算合并、向下截断、严格门槛、缺失指标与空池、低波回退、代码顺序稳定性，以及红利止盈/科技网格的互斥规则。执行器增加中文输入、中文路径与中文异常的通信回归测试。正式评分复核所有 148 期，并确认看板包含最终 Top-10。修改范围为离线策略与其执行器编码，没有修改应用前后端、财务记账逻辑或公共数据契约。

验收结果：`npm run test:benchmark` 的 95 个测试通过；`npm run check:architecture` 通过（含 7 个边界测试）；23 个策略均正式评分成功，9 个新配置与扫描结果的最大绝对差为 `8.88e-16`，看板中的策略数量与 Top-10 核对一致。第一次测试遇到的 Windows 错误信息解码失败已由显式 UTF-8 修复，并非跳过该用例。未运行与本次离线研究变更无关的应用前后端与数据库集成测试。
