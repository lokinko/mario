# 2026-11-05 全用户共享分红资料验收

## 目标与设计增量

解决不同账号重复抓取分红、服务重启后不能复用其他账号已补齐资料的问题。沿用[架构说明](../architecture.md)第 3 节依赖方向、第 6 节观察数据流和第 7 节状态与事务归属，在同一 PostgreSQL 新增 `mario_market.dividend_histories`，以规范证券代码为主键，每只证券保存一份完整分红历史 JSON（事件、来源、覆盖日、采集时间）。分红稀疏，当前不额外建立逐日股息率表；TTM 每股分红和税前股息率继续由既有领域计算按行情日和收盘价重算。

`db/public_dividends` 负责公共事实持久化，`application/watch_market` 经行情端口编排复用和补抓，网络适配器仅负责来源查询。公共库不读取账号数据，账号表只保留自身观察采用的分红依据；账号备份导入不会写公共库。公开资料保存与账号观察事务独立，行情失败或账号事务回滚不会丢掉成功补抓的公共事实。

启动时事务初始化 202 份可用历史，共 3957 条已实施记录，整体日期范围 1991-03-11 至 2026-11-04，各股票覆盖长度不同。原始 210 只股票中，7 只来源无记录、1 只记录不完整，保持未知并按需补查；详见[资料整理审计](watch-dividend-bootstrap-20261105.md)。不自动扩充用户观察名单。

## 当前行为与迁移

- 所有账号复用同一公共库；缺失或覆盖日期不足时按观察检查请求补抓，成功立即落库。单进程同证券并发请求合并，当日成功结果供其他账号及重启后复用。
- 来源失败保留旧资料与原日期，并有 60 秒进程内重试退避；手动检查清除失败退避、刷新行情，仍复用已覆盖当日的分红。没有把无记录或失败当作零股息率。
- 新资料先比较覆盖日期，再比较采集时间，旧内置包不会覆盖更新事实。同日公共资料更新后，已检查账号下次检查会重算当前观察，不回写过去观察或已完成报告。
- 整站原生和加密备份包含 `mario_market`；旧备份无该 schema 时由新版启动重新初始化。回退使用更新前备份，保留新备份以保存新增公共资料，不能用旧恢复脚本处理新版包。
- API 返回 `publicDividendData: 1`，部署验收检查该标记。更新与恢复步骤见[部署文档](../deploy-madeagents.md#公开分红资料上线)。
