# 站点模型目录与默认来源验收（2026-11-16，历史记录）

本轮为设置页接入站点 OpenAI 项目的候选文本模型目录，并将未明确选择调用来源的账号统一默认到站点 OpenAI。型号按账号保存，管理员的 `OPENAI_MODEL` 保留为默认；密钥、官方地址与账号授权边界不变。当前规则及迁移行为见[站点配置](../self-hosting.md#站点提供的-openai)，上游字段依据 [OpenAI 官方模型目录接口](https://developers.openai.com/api/reference/resources/models/methods/list)。目录不提供 Responses、搜索或额度能力证明，不逐个执行付费探测。

## 工程验证

完整 `npm test` 通过：前端 417 项；Rust 420 项通过、9 项原有显式 ignored；架构、格式、Clippy、构建、跨语言契约、托管 HTTP、Web、模拟 Codex 桥接、财务迁移与原生备份恢复门禁通过，恢复核对 328 张表。站点模型选择的页面回归随后定向复测通过。

新增回归覆盖：

- 官方目录认证、候选筛选与去重、畸形响应、拒绝重定向和不转发上游错误正文；成功缓存、并发合并、过期刷新、凭据摘要隔离与失败退避。
- 无明确来源的旧账号默认站点，个人密钥仍保留；明确个人选择不自动改计费来源。
- 两账号型号偏好隔离、重新打开账号后恢复、个人导出不含模型偏好及密钥、型号与来源写入失败的事务回滚。
- 读取目录时释放账号锁；保存新型号前发现并发修改返回冲突，不覆盖当前账号数据。
- 目录失败时保留当前选择，并允许当前/管理员默认型号继续保存；未列出的新型号被拒绝。
- 页面自动加载、选择后保存所选型号、失败重试、卸载后的旧响应失效，以及保存/测试期间的控件禁用。

## 实际接口读取

使用本轮构建的 Mario API 和一次性 PostgreSQL，注册两个空账号，以用户授权的密钥通过临时进程环境配置站点服务。实际 `GET /api/model-config/models` 返回 46 个候选文本型号，`defaultModel=gpt-5.4`；第二个账号读取同一目录成功。两个账号初始 `source=server`，无需个人模型密钥。

账号 A 从返回目录选择 `gpt-5.4-mini` 并保存后，账号 B 仍使用站点默认 `gpt-5.4`；账号 A 的问答预览采用所选型号。配置、目录、预览与导出响应未出现原始密钥。真实验证未调用生成接口、不发送真实账本，不据此宣称所有候选均可推理或支持网页搜索。

未连接或修改云端 `.env`，未部署；用户继续自行部署。没有新增 schema 或备份版本，没有覆盖已有个人密钥或删除账号数据。

## 清理

编译与全部验收使用本轮专属 `.runtime/openai-catalog-build`。结束后确认仓库内绝对路径与进程占用，执行 Cargo 清理并确认目录删除；删除本轮目录验证脚本及检查、门禁日志。一次性 PostgreSQL 由既有测试工具停止并删除。原开发服务、`server/target`、开发数据库及其他任务的临时资料保留。
