# 复盘与规则闭环

mario 用两个不同层次的复盘，把一次投资经历转成可以跨周期复用的能力。

## 单笔决策复盘

新增决策用一个文本框保存当时的观点、顾虑和思考，保留完整原文与换行。决策复盘也只需要一段纯文本，自由写下想表达的内容、观点、顾虑和思考；正文保留完整原文与换行，单独保存，不覆盖原始决策。已有结构化决策保留原字段和规则检查。若草稿来自 AI 分析，保存原分析 ID 与行动序号，以便追溯。完整交接契约见 [从 AI 分析到用户决策](analysis-to-decision.md)。

旧复盘的结果、经验、逻辑状态、实际收益与评分会合并成一段正文展示和编辑。新复盘不要求评分或收益，缺少评分的记录不参与过程均值和规则评分关联统计。历史过程评分与收益结果分开：一次赚钱的违规交易仍然可以是坏过程；一次亏损但严格遵守风险预算、信息充分且概率合理的决定，也不应被简单判定为错误。

## 周期系统复盘

复盘记录使用一个自由文本框，只需写下用户想表达的内容、顾虑和思考，不要求复盘周期、纪律评分、下一步或下次复盘日期。历史记录按保存日期展示完整正文；旧结构化记录的所有文字、周期、评分和下次复盘日期会合并显示。投资规则保留在折叠区域，用户可以主动把一段复盘思考作为规则草稿的依据。

保存时，服务端同时冻结当时的组合市值、应急覆盖、集中度、风险状态、高风险项、目标进度、决策复盘完成度和有效规则数。以后查看这条记录时，不使用当前状态回填旧数据。

## 个人投资规则

一条可以执行的规则至少包含：

1. 类别：资产配置、风险、研究、仓位、行为或复盘；
2. 规则内容：触发时具体要做或不能做什么；
3. 触发条件：何时必须检查；
4. 依据：它来自什么证据、要避免哪种重复错误。

规则可以直接建立，也可以从一条周期复盘的经验转化。修改和停用都会产生新版本；旧版本不会被覆盖，因此未来能够判断“当时遵循的究竟是哪套规则”。停用不是删除，代表这条规则不再约束新决策，但仍属于历史证据。

## 决策前规则检查

新增纯文本决策不强制逐条确认规则，可以在正文中自由写下规则相关的顾虑和思考。以下检查状态属于历史结构化决策，仍用于复盘统计：

- `遵守`：本次决策符合规则；
- `偏离`：明知规则适用仍决定偏离，必须提前写明原因；
- `不适用`：规则的触发条件与本次决策无关。

兼容旧版结构化保存接口时，服务端不信任客户端提交的规则文字，而是按规则 ID 与版本核对当前有效规则，再把服务端保存的类别、内容和触发条件冻结进不可变决策快照。规则在之后修订或停用，不会改写旧决策当时检查的版本。旧版本客户端或过期页面缺少规则、重复规则、版本不一致时，服务端拒绝冻结并要求刷新。

## 规则有效性追踪

复盘中心按规则汇总决策前检查，展示覆盖决策数、适用规则遵守率、遵守与偏离样本数，以及有评分的历史复盘中的平均过程评分。至少有三个已复盘适用样本后，系统才给出初步观察信号；只有单边样本时会明确提示缺少对照。

这些指标只能发现关联，不能证明因果：遵守某条规则的决策可能本来就更容易，过程评分也可能直接受到“是否遵守规则”的影响。系统不以单笔盈亏判断规则优劣，也不自动修改或停用规则；反常信号只代表需要回到原始决策和证据进行人工复核。

## AI 的参与边界

AI 可以比较多期复盘、识别重复违规、检查当前行为与有效规则的冲突，并提出候选修订。但 AI 不得静默修改或自动启用规则，最终规则必须由用户明确保存。

“个人投资规则”和“周期系统复盘”是发送前预览中的独立数据组。关闭后不会进入基础上下文；启用时，当前有效规则和最近最多 8 期系统复盘会进入模型载荷，并参与上下文一致性指纹。

## 页面内复盘提示

Web 看板显示计划复盘日已到且尚未复盘的决策，以及到期的周期复盘。复盘中心保留到期队列与新建复盘入口。新增纯文本复盘没有默认到期日期，不会因日期为空反复触发周期提示。

提示只负责把用户带回原始判断和证伪条件，不包含行情、涨跌或交易刺激。

## 当前限制

- 规则观察依赖用户在决策前准确标记适用性，并存在选择偏差，尚不能做因果评估；
- 周期快照保存聚合指标，不保存完整持仓副本；
- AI 提议的规则修订仍需用户人工转录和确认。
