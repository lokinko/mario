# 复盘与规则闭环

mario 保留独立复盘记录和个人投资规则，用户可从复盘思考中整理规则。

当前主要使用场景是[买点观察](buy-watch.md)后的周末复盘：记录本周条件变化、长期持有理由是否变化，以及下周等待什么。买点观察页展示已保存的本周行情记录并可发起讨论；本页负责用户主动保存的个人文字，不自动生成模型周报或发送站外提醒。

## 自由文字复盘

页面提供“复盘记录”和“投资规则”两个分类。新建复盘使用一个自由文本框，只需写下用户想表达的内容、顾虑和思考，不要求复盘周期、纪律评分、下一步或下次复盘日期。历史列表按保存日期倒序读取最近 50 条，点击记录查看完整正文；早期结构化记录的文字、周期、评分和下次复盘日期合并为正文显示。“把思考沉淀为规则”会打开规则草稿，把旧记录的经验字段或完整正文填入依据，仍需用户补充并保存。

保存接口只接收 `{ "content": "完整复盘正文" }`，拒绝结构化表单字段；早期结构化记录通过只读适配展示。

保存时，服务端同时冻结当时的组合市值、应急覆盖、集中度、风险状态、高风险项和有效规则数。以后查看这条记录时，不使用当前状态回填旧数据。

## 个人投资规则

一条可以执行的规则至少包含：

1. 类别：资产配置、风险、研究、仓位、行为或复盘；
2. 规则内容：触发时具体要做或不能做什么；
3. 触发条件：何时必须检查；
4. 依据：它来自什么证据、要避免哪种重复错误。

规则可以直接建立，也可以从一条复盘的思考转化。修改、停用和重新启用都会产生新版本，原版本不被覆盖；历史入口可查看修订记录。停用的规则保留在列表并标明状态，不计入有效规则数。这些是用户手工维护的判断准则，不是观察规则配置，也不自动校验交易或限制下单。

## 与问答的关系

问答的冻结上下文不自动包含个人规则和复盘记录。“AI 辅助系统复盘”只进入问答并填入通用问题，不附带选中记录、规则正文或全部历史分析；需要讨论具体复盘时，用户须自行将相关文字粘贴到问题中。参考资料另按问答预设授权检索，不能由按钮文案推断已经发送哪些资料；实际输入以问答预览及[授权边界](ai-data-boundary.md)为准。AI 不修改或启用规则，规则只能由用户明确保存。

## 页面内复盘提示

页面保留到期周期复盘的提示和新建复盘入口。新增纯文本复盘没有默认到期日期，不会因日期为空反复触发周期提示。

提示只负责把用户带回复盘记录，不包含行情、涨跌或交易刺激。

## 当前限制

- 周期快照保存聚合指标，不保存完整持仓副本；
- 规则修订需用户人工整理和确认。

实现与接口归 [复盘页面](../client/src/features/reviews/ReviewCenter.tsx)、[HTTP 适配](../server/src/http/reviews.rs)及[账号仓储](../server/src/db/reviews.rs)：`GET/POST /api/system-reviews` 读取或保存复盘，`GET/POST /api/investment-rules` 读取或建立规则，`PUT /api/investment-rules/{id}` 修订规则，`GET /api/investment-rules/{id}/history` 读取版本。写入保留账号认证和 `If-Match` 校验。现有验证依据为[复盘交互回归](../client/src/features/reviews/ReviewCenter.test.tsx)、[仓储冻结与版本回归](../server/src/db/tests.rs)及[功能 API 验收](../scripts/test-functional-api.mjs)；文档核对不表示这些验收已重新执行或服务已部署。
