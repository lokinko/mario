# AI 域 spec

AI 域基于授权资料提供可追溯的分析，管理模型执行与讨论记忆。全局职责及代码映射见[架构](../architecture.md)；财务账本、研究资料与用户原则归[用户域](user.md)，公共行情归[市场域](market.md)。

本文记录已讨论采纳的行为；实现与验证范围在文末说明，文档确认本身不代替运行验收。

## 1. 模型连接与执行

管理个人模型配置、站点提供的模型、本机授权和桥接。模型目标与对应凭据一起确定，不能因配置并发变化把凭据发送到另一个地址。

执行器接收冻结任务，不直接读取账号数据库，也不写入用户账本。模型选择与执行能力不改变资料的业务授权。

实现依据：[模型配置用例](../../server/src/application/model_settings.rs)、[执行端口](../../server/src/ports/analysis.rs)、[模型管理端口](../../server/src/ports/model.rs)、[Agent](../../server/src/agent.rs)。

## 2. 资料授权与上下文冻结

按保存的设置选择收支、持仓、研究资料和长期记忆；方法论作为分析偏好使用，不能冒充财务事实。

发送时自动准备并校验上下文版本，不增加一次确认弹窗。准备后资料或授权发生变化，应重新准备，不能混用两个版本。模型执行期间使用已冻结的输入，完整分析结果由 AI 用例保存。

多轮讨论保留必要上下文；用户最新更正优先于旧回答，授权缩小时同步裁减历史模型内容和相关记忆。对话中的更正不能被描述为已经改写用户账本。

分析与记忆用例分别依赖[账号能力端口](../../server/src/ports/ai_account.rs)，不接收完整 Database。用户资料是只读来源，AI 历史和记忆只暴露所属写入操作；模型配置仅有明确的配置、密钥和桥接方法，不能按任意键读取账号设置。账号锁通过公共[账号端口](../../server/src/ports/account.rs)与[锁适配](../../server/src/db/account_access.rs)协调，冻结后释放、保存前重取的行为保持一致。AI 授权选择由适配层转换为用户来源的筛选参数，用户契约不依赖 AI 类型。用户域的授权投影只返回所选组的当前可用事实，AI 用例与上下文构建不再接收完整 Snapshot；授权选择本身参与冻结指纹。

分析、记忆、模型设置和桥接 HTTP 接口也分别取得自己的[请求上下文](../../server/src/http/context.rs)，不能取得用户记录写端口。历史查询与问答预设通过[AI 记录能力](../../server/src/ports/ai_records.rs)读写，不向业务路由暴露统一账号仓储。

AI 配置、预设和记忆进度使用[所属设置键](../../server/src/db/settings/ai.rs)，模型密钥只使用原有账号加密的 model 槽位。仓储只能写入所属 AI 表；用户来源由授权适配只读取得。个人备份可保留 AI 历史与记忆进度，模型连接、问答预设和密钥继续由当前接收账号保有。

实现依据：[分析用例](../../server/src/application/analysis.rs)、[上下文构建](../../server/src/context.rs)、[多轮上下文](../../client/src/features/advisor/previousTurn.ts)、[记忆选取](../../server/src/context/memory.rs)。

## 3. 简洁的当前持仓输入

讨论时只提供当前可用的持仓状态摘要，不提供账本明细、逐笔成交、历史交易列表、数据缺口报告或冗长的嵌套结构。用户不需要为了问答另外维护一套研究或持仓表格。

模型可读的业务输入采用简洁 Markdown 表格或其他紧凑文本，不采用 JSON。持仓默认使用紧凑表格，按标的展示当前状态；列从以下可用指标中选择：

| 指标 | 含义 |
| --- | --- |
| 标的 | 名称或代码，足以识别讨论对象 |
| 持仓规模 | 当前数量及必要单位 |
| 成本 | 当前持仓成本 |
| 市值 | 当前持仓估值及必要币种 |
| 浮动盈亏 | 当前持仓未实现盈亏 |
| 仓位 | 可用的组合占比 |

只发送可用数据，省略不可用字段，不补零、不发送 `null`、缺失原因或检查清单。必要币种和单位用于解释有效数值；不附加逐项质量说明。汇总和指标由账本确定性计算后提供，不要求模型重放交易。

共用市场价格不意味着合并不同上市证券或混算不同币种。个人持仓仍以所属账号的真实账本为依据；对模型展示的是精简后的当前状态。

CSV 可以作为同一摘要的替代表达；如使用 CSV 文件，其内容也仅包含上述当前状态。文本输入是默认方案，不为使用文件而额外展开账本数据。提供给模型的内容格式与 HTTP 请求封装、内部保存格式、模型输出校验分别处理。

未授权持仓时，不发送相应持仓摘要及其派生汇总。内部仍保留输入冻结和结果追溯能力，但不把内部校验与审计材料一并塞入模型上下文。

当前状态由用户域的[授权投影](../../server/src/models/accounting/analysis.rs)生成，同一标的与币种跨账户汇总，期权按合约和方向分别汇总；任一成员不可用时不把局部金额冒充完整汇总。内部字段用于引用与审计，发送给模型时通过 [Markdown 渲染](../../server/src/context/render.rs)呈现。

## 4. 研究资料与网页搜索

默认开启网页搜索，用户可以关闭。默认值适用于未保存预设的情况，已经保存的用户选择继续尊重。模型不支持搜索或搜索失败时明确说明，不声称完成了外部核查。

搜索请求只使用公开标的和研究主题，不携带个人持仓金额、身份和财务档案。

区分原始证据、网页线索和模型推断。搜索失败可以继续使用已有资料，但必须明确说明失败。历史问答中的网页摘录复用属于 AI 历史资料复用，不自动成为用户研究资料库中的正式记录。

实现依据：[问答预设](../../server/src/models/analysis.rs)、[公开研究主题](../../server/src/context/discussion.rs)、[搜索编排](../../server/src/ai/orchestrator.rs)、[供应商适配](../../server/src/ai/native_provider.rs)、[前端预设](../../client/src/features/settings/AnalysisDefaults.tsx)。

## 5. 问答与多代理评议

默认流程为：研究整理 → 三个方案视角 → 交叉评议 → 确定性计票选出结果。三个视角分别是稳健等待、条件执行和反方证伪。

校验输出结构和引用；无效输出只能进行有限修复。部分阶段失效后若仍能继续，必须标明降级情况。单一有效方案、平票或未完成评议，不能描述成一致共识。

回复区分事实、推断、假设和未知，不能把观察信号当成用户已经决定成交。输入精简不取消引用和输出校验，也不允许模型补造未提供的持仓或交易事实。

实现依据：[工作流](../../server/src/ai/workflow.rs)、[编排](../../server/src/ai/orchestrator.rs)、[计票](../../server/src/models/council.rs)、[输出校验](../../server/src/ai/structured_output.rs)。

公开[红利观察](../../client/src/features/watch/dividend-preview/DividendPreview.tsx)为内置样本提供逐股预生成解读，比较同一报告期的已实施派息并提出核查方向。解读使用归档中的公共分红数据并沿用其截止日期，分享长图包含完整解读、核查方向和详情二维码。工作台入口带入对应 A 股代码和可编辑的研究问题，由用户确认发送后执行问答流程。

## 6. 流式交互、失败与分析历史

区分进行状态、方案草稿、完整结果和错误。流式草稿不作为已验证结论；未完成内容不能冒充完整分析归档。

支持停止执行，限制超时与重试。完整结果保存对应的输入依据、模型、流程、引用和执行记录，方便回查。精简模型输入时，历史分析仍按各自保存的输入解释。

结构校验通过不等于分析质量合格，真实回复质量仍需单独验收。

实现依据：[问答页面](../../client/src/features/advisor/Advisor.tsx)、[流式适配](../../server/src/streaming.rs)、[执行限额](../../server/src/models/inference.rs)、[分析历史保存](../../server/src/db/analysis_history.rs)、[质量评测入口](../../server/tests/fixtures/qa_eval/README.md)。

## 7. 长期记忆与整理

记忆分为用户偏好、用户背景和讨论观点。偏好与背景必须有用户原话依据；讨论观点可以来自模型推断，但必须明确标记来源和适用条件，不能变成用户事实。

开启记忆后，在积累三次未整理的完整分析时自动整理，也支持手动触发。模型只提出变更，由程序筛选后保存；整理期间发生冲突则不覆盖已有修改。用户可以停用或删除记忆。

记忆不能替代账本，不保存行情快照、持仓金额或模型买卖建议作为长期事实。

实现依据：[记忆用例](../../server/src/application/memory.rs)、[记忆整理代理](../../server/src/ai/dreaming.rs)、[筛选规则](../../server/src/models/memory.rs)、[记忆界面](../../client/src/features/advisor/MemoryPanel.tsx)。

## 8. 现有实现差异

默认搜索已开启，已保存的关闭选择继续保留。分析请求省略 `webSearch` 时也按开启处理；虚构质量评测显式关闭搜索，防止把虚构公司送到真实来源。

当前工作流为 `investment-workflow-v18`。用户域提供授权当前状态，研究、方案、评议和记忆整理的业务材料使用 Markdown；HTTP 与内部审计仍可使用结构化 JSON，模型输出仍按结构契约校验。当前事实引用限于问题、用户历史原话以及可用 summary/holdings 字段；不再要求引用原始成交或缺口码。旧分析按保存时的版本和原始引用展示。

供应商仍使用文本消息，没有统一 CSV 文件输入通道；默认 Markdown 已满足当前输入方式，不能将可选 CSV 附件描述为现有能力。

回归覆盖：搜索默认值与已保存选择、供应商搜索能力提示、同标的当前状态汇总与可用值筛选、未授权组排除、交易明细与缺口不进入输入、Markdown 原文保留、引用与历史解释、授权变更指纹、阶段降级、停止执行和记忆冲突。真实模型回复质量与联网来源仍需单独验收；工程回归不证明真实回复质量已通过。
