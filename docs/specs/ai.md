# AI 域 spec

AI 域基于授权资料提供可追溯的分析，管理模型执行与讨论记忆。全局职责及代码映射见[架构](../architecture.md)；财务账本、研究资料与用户原则归[用户域](user.md)，公共行情归[市场域](market.md)。

本文记录已讨论采纳的行为；实现与验证范围在文末说明，文档确认本身不代替运行验收。

## 1. 模型连接与执行

管理个人模型配置、站点提供的模型、本机授权和桥接。模型目标与对应凭据一起确定，不能因配置并发变化把凭据发送到另一个地址。个人原生模型支持从所选接口拉取可用模型列表进行选择，并支持手动添加自定义模型名称；拉取目录不落库且绝不回退使用站点密钥。

执行器接收冻结任务，不直接读取账号数据库，也不写入用户账本。模型选择与执行能力不改变资料的业务授权。

实现依据：[模型配置用例](../../server/src/application/model_settings.rs)、[执行端口](../../server/src/ports/analysis.rs)、[模型管理端口](../../server/src/ports/model.rs)、[Agent](../../server/src/agent.rs)。

## 2. 资料授权与上下文冻结

按保存的设置选择收支、持仓、研究资料和长期记忆；方法论作为分析偏好使用，不能冒充财务事实。

发送时自动准备并校验上下文版本，不增加一次确认弹窗。准备后资料或授权发生变化，应重新准备，不能混用两个版本。模型执行期间使用已冻结的输入，完整分析结果由 AI 用例保存。

多轮讨论保留必要上下文；用户最新更正优先于旧回答，授权缩小时同步裁减历史模型内容和相关记忆。对话中的更正不能被描述为已经改写用户账本。

分析与记忆用例分别依赖[账号能力端口](../../server/src/ports/ai_account.rs)，不接收完整 Database。用户资料是只读来源，AI 历史和记忆只暴露所属写入操作；模型配置仅有明确的配置、密钥和桥接方法，不能按任意键读取账号设置。账号锁通过公共[账号端口](../../server/src/ports/account.rs)与[锁适配](../../server/src/db/account_access.rs)协调，冻结后释放、保存前重取的行为保持一致。AI 授权选择由适配层转换为用户来源的筛选参数，用户契约不依赖 AI 类型。用户域的授权投影只返回所选组的当前可用事实，AI 用例与上下文构建不再接收完整 Snapshot；授权选择本身参与冻结指纹。

分析、记忆、模型设置和桥接 HTTP 接口也分别取得自己的[请求上下文](../../server/src/http/context.rs)，不能取得用户记录写端口。历史查询与问答预设通过[AI 记录能力](../../server/src/ports/ai_records.rs)读写，不向业务路由暴露统一账号仓储。

AI 配置、预设和记忆进度使用[所属设置键](../../server/src/db/settings/ai.rs)，模型密钥只使用原有账号加密的 model 槽位。仓储只能写入所属 AI 表；用户来源由授权适配只读取得。个人备份可保留 AI 历史与记忆进度，模型连接、问答预设和密钥继续由当前接收账号保有。

实现依据：[分析用例](../../server/src/application/analysis.rs)、[上下文构建](../../server/src/context.rs)、[多轮上下文](../../client/src/features/advisor/previousTurn.ts)、[记忆选取](../../server/src/context/memory.rs)。

## 3. 简洁的当前持仓输入

讨论时只提供当前可用的持仓状态摘要，不提供账本明细、逐笔成交、历史交易列表、数据缺口报告或冗长的嵌套结构。用户不需要为了问答另外维护一套研究或持仓表格。

模型可读的业务输入采用简洁 Markdown 表格或其他紧凑文本，不采用 JSON。持仓默认使用紧凑表格，按标的展示当前状态；列从以下可用指标中选择：

| 指标 | 含义 |
| --- | --- |
| 标的 | 名称或代码，足以识别讨论对象 |
| 持仓规模 | 当前数量及必要单位 |
| 成本 | 当前持仓成本 |
| 市值 | 当前持仓估值及必要币种 |
| 浮动盈亏 | 当前持仓未实现盈亏 |
| 仓位 | 可用的组合占比 |

只发送可用数据，省略不可用字段，不补零、不发送 `null`、缺失原因或检查清单。必要币种和单位用于解释有效数值；不附加逐项质量说明。汇总和指标由账本确定性计算后提供，不要求模型重放交易。

共用市场价格不意味着合并不同上市证券或混算不同币种。个人持仓仍以所属账号的真实账本为依据；对模型展示的是精简后的当前状态。

CSV 可以作为同一摘要的替代表达；如使用 CSV 文件，其内容也仅包含上述当前状态。文本输入是默认方案，不为使用文件而额外展开账本数据。提供给模型的内容格式与 HTTP 请求封装、内部保存格式、模型输出校验分别处理。

未授权持仓时，不发送相应持仓摘要及其派生汇总。内部仍保留输入冻结和结果追溯能力，但不把内部校验与审计材料一并塞入模型上下文。

当前状态由用户域的[授权投影](../../server/src/models/accounting/analysis.rs)生成，同一标的与币种跨账户汇总，期权按合约和方向分别汇总；已清仓持仓与零余额账户不进入当前持仓输入，现金行省略无意义的零成本，任一成员不可用时不把局部金额冒充完整汇总。完整原始记录（含来源链接、抓取时间戳、观察原始结构等）仅保存在内部审计目录中；送入模型的资料在原始载荷阶段即剔除不可引用的审计元信息、重复免责样板与冗余开关，买点观察改为紧凑 Markdown 表格，方法论仅放在系统指令中不再重复送入用户消息，研究/方案/投票阶段按需裁剪已完成的核查清单与非证据线索。长 UUID 持仓与证据标识在单次模型调用内使用确定性短别名（`h1`、`e1`），校验与落库前自动还原为真实标识以保证前端与历史追溯一致。发送给模型与前端预览时均通过 [Markdown 渲染](../../server/src/context/render.rs)呈现。

## 4. 研究资料与网页搜索

默认开启网页搜索，用户可以关闭。默认值适用于未保存预设的情况，已经保存的用户选择继续尊重。模型不支持搜索或搜索失败时明确说明，不声称完成了外部核查。

搜索请求只使用公开标的和研究主题，不携带个人持仓金额、身份和财务档案，并优先检索最新估值、财报、现金流、分红拆分、核心商品价格/成本驱动与主要多空分歧。

区分原始证据、网页线索和模型推断：原始证据（`nativeWebEvidence` / `researchEvidence`）可写入 `facts.evidenceIds`；网页线索（`webLeads`，包含供应商检索摘要与无原文时的综合检索线索）严禁写入 `facts.evidenceIds` 或冒充一手原文，但分析正文应充分利用其中查明的公开信息并明确标注“据网页线索，待公告复核”。搜索失败可以继续使用已有资料，但必须明确说明失败。历史问答中的网页摘录复用属于 AI 历史资料复用，不自动成为用户研究资料库中的正式记录。前端将联网搜索开关与上下文资料范围控制直接集成在问答输入框底部，修改后即时持久化至账号分析预设并刷新上下文预览。

实现依据：[问答预设](../../server/src/models/analysis.rs)、[公开研究主题](../../server/src/context/discussion.rs)、[搜索编排](../../server/src/ai/orchestrator.rs)、[供应商适配](../../server/src/ai/native_provider.rs)、[问答上下文与搜索控制](../../client/src/features/advisor/Advisor.tsx)。

## 5. 问答与多代理评议

问答流程先基于冻结输入执行确定性**专业投研场景路由**、**投资规则与策略基准构建**和**复杂度自适应路由**，并在分析轨迹中记录所选场景、执行模式、各模块结论与汇总状态：

- **上下文投资规则与策略基准**：依据[投资策略基准](../../server/src/context/strategy.rs)，按通用决策铁律（结论先行、高信息密度、严禁把查报价/翻财报踢回给用户、浮亏补仓三条硬规则、卖出三类驱动、网页线索合理利用边界）叠加当前投研场景策略手册（覆盖红利、个股估值、减仓换仓、组合配置、现金流与负债、期权对冲、宏观行业等场景）；识别到铝/有色/煤炭/能源/化工等周期资源股时自动叠加【周期/资源股专项规则】（严禁按盈利高点低 PE 误判低估）。策略基准随系统指令注入各专业模块与策略总监，不与用户自定义方法论冲突（分析视角冲突时优先尊重用户方法论，但数据与引用底线不可覆盖）。
- **专业投研场景路由**：识别多市场公开标的（A 股、带后缀场内基金、港股 `.HK`、显式 `$TICKER` 及授权持仓/观察中的规范代码），将问题匹配到对应投研场景，加载该场景的核查清单、专业分析重点和仅含公开信息的网页检索重点。
- **完整分模块模式（`council`）**：所有专业投资决策、具体标的评估、含授权研究证据需交叉印证的问题、以及多轮/复合决策讨论均走分模块讨论与汇总流程：研究整理 → 三个专业模块并行深耕（`M1 基本面与估值定价`、`M2 组合策略与交易执行`、`M3 风险压力与反方证伪`）→ 首席投资策略总监综合三模块讨论结果与策略基准做出最终裁决并流式输出；单模块或研究简报验证失败时降级继续并在轨迹中标明降级状态，不伪造全模块完成。前端默认展示核心结论、可执行行动与各模块的一句话核心立场，按需展开每个模块的详细拆解、关键论点与触发/证伪条件，实现详略得当的阅读层次。
- **精简快速模式（`fast`）**：纯概念解释、纯资料状态或统计口径核查等轻量非决策问题自动走单次顾问直答（同样注入策略基准与场景重点），跳过研究简报与分模块讨论，在降低耗时与调用成本的同时保留完整的结构化与引用校验；界面顶部轻量标示场景与精简直答模式，不叠加模块卡片。

校验输出结构和引用；无效输出只能进行有限修复。部分阶段失效后若仍能继续，必须标明降级情况。

回复区分事实、网页线索、假设和未知，不能把观察信号当成用户已经决定成交。输入精简不取消引用和输出校验，也不允许模型补造未提供的持仓或交易事实。

实现依据：[策略基准](../../server/src/context/strategy.rs)、[场景路由](../../server/src/context/discussion.rs)、[工作流](../../server/src/ai/workflow.rs)、[编排](../../server/src/ai/orchestrator.rs)、[模块契约](../../server/src/models/council.rs)、[输出校验](../../server/src/ai/structured_output.rs)。

公开红利观察为内置样本提供逐股预生成解读。网页和分享长图共用三段内容。

1. **未来预期**定性分析市场环境和行业变化对公司的影响，不罗列数字。
2. **影响股息的关键数据**说明要跟踪哪些经营与财务指标、为什么要看，以及指标变化如何影响派息能力。
3. **分红与近一年股价**解读归档中的现金分红和近一年前复权股价表现，集中呈现三项摘要指标。数据口径见[市场域 spec](market.md#4-分红与公司行动)。

工作台入口带入对应 A 股代码和可编辑的研究问题，由用户确认发送后执行问答流程。实现见[公开红利观察](../../client/src/features/watch/dividend-preview/DividendPreview.tsx)。

## 6. 流式交互、失败与分析历史

区分进行状态、方案草稿、完整结果和错误。流式草稿不作为已验证结论；未完成内容不能冒充完整分析归档。

支持停止执行，限制超时与重试。完整结果保存对应的输入依据、模型、流程、引用和执行记录，方便回查。精简模型输入时，历史分析仍按各自保存的输入解释。

结构校验通过不等于分析质量合格，真实回复质量仍需单独验收。

实现依据：[问答页面](../../client/src/features/advisor/Advisor.tsx)、[流式适配](../../server/src/streaming.rs)、[执行限额](../../server/src/models/inference.rs)、[分析历史保存](../../server/src/db/analysis_history.rs)、[质量评测入口](../../server/tests/fixtures/qa_eval/README.md)。

## 7. 长期记忆与整理

记忆分为用户偏好、用户背景和讨论观点。偏好与背景必须有用户原话依据；讨论观点可以来自模型推断，但必须明确标记来源和适用条件，不能变成用户事实。

开启记忆后，在积累三次未整理的完整分析时自动整理，也支持手动触发。模型只提出变更，由程序筛选后保存；整理期间发生冲突则不覆盖已有修改。用户可以停用或删除记忆。

记忆不能替代账本，不保存行情快照、持仓金额或模型买卖建议作为长期事实。

实现依据：[记忆用例](../../server/src/application/memory.rs)、[记忆整理代理](../../server/src/ai/dreaming.rs)、[筛选规则](../../server/src/models/memory.rs)、[记忆界面](../../client/src/features/advisor/MemoryPanel.tsx)。

## 8. 每日自动复盘信息流

每日复盘作为独立一级模块运行，默认开启并在账号本地时区每日 `07:30` 自动复盘前一日（可修改开关、触发时间、跟踪范围「当前持仓 + 个人自选 / 仅当前持仓」与联网检索开关，并支持手动立即触发）。

- 后台任务按账号时区检查到期状态，每个复盘日自动执行一次；执行前先通过市场域刷新涉及 A 股的巨潮资讯官方公告缓存。
- 用例通过只读账号端口 `DailyReviewAccount` 冻结昨日组合与单标的变动、买点观察信号与用户方法论（不读取逐笔成交明细，不写入用户账本），并结合市场只读端口的官方公告与分红计划生成确定性事实与法定公告动态。
- 若账号或站点存在可用模型，在释放账号锁状态下调用 `AnalysisExecutor::daily_review`（可选先执行仅含公开标的代码/名称的联网检索）生成多条微博式信息流复盘动态；若模型未配置、不可用或调用失败，本次运行诚实标为 `degraded` 并说明原因，完整保留昨日持仓事实与官方公告动态。
- 信息流支持按动态类型、复盘日期、标的与未读状态筛选，支持单条/全部标为已读及一键带入「问答」追问；运行记录、动态条目与复盘偏好纳入原生个人备份（当前备份格式 v33、数据库 schema v22，已移除旧版手工投资规则与文字复盘表）。

实现依据：[每日复盘契约](../../server/src/models/daily_review.rs)、[每日复盘生成](../../server/src/ai/daily_review.rs)、[每日复盘用例](../../server/src/application/daily_review.rs)、[每日复盘仓储](../../server/src/db/daily_review.rs)、[每日复盘 HTTP](../../server/src/http/daily_review.rs)、[每日复盘页面](../../client/src/features/dailyReview/DailyReviewPage.tsx)。

## 9. 现有实现差异

默认搜索已开启，已保存的关闭选择继续保留。分析请求省略 `webSearch` 时也按开启处理；虚构质量评测显式关闭搜索，防止把虚构公司送到真实来源。

当前工作流已清理旧版前向兼容代码并重置为 `investment-workflow-v1`。用户域提供授权当前状态，研究、专业模块、策略总监汇总、精简直答和记忆整理的业务材料使用 Markdown；HTTP 与内部审计仍可使用结构化 JSON，模型输出仍按结构契约校验。当前事实引用限于问题、用户历史原话以及可用 summary/holdings 字段；不再保留旧版投票、`LegacyStructuredAnalysis`、`adviceGrounding` 或多草稿兼容分支。

供应商仍使用文本消息，没有统一 CSV 文件输入通道；默认 Markdown 已满足当前输入方式，不能将可选 CSV 附件描述为现有能力。

回归覆盖：搜索默认值与已保存选择、供应商搜索能力提示、网页检索综述线索保底与原文边界隔离、上下文投资规则与策略基准（含周期/资源股专项规则）、多市场标的识别与七类专业投研场景路由、复杂度自适应精简与分模块汇总分流、三专业模块并行讨论与策略总监汇总、场景化公开检索与系统指令注入、同标的当前状态汇总与可用值筛选、未授权组排除、交易明细与缺口不进入输入、审计元数据剔除与短别名双向还原、阶段上下文裁剪、买点观察紧凑 Markdown 与原文保留、引用与历史解释、授权变更指纹、模块与研究阶段降级、停止执行和记忆冲突。真实模型回复质量与联网来源仍需单独验收；工程回归不证明真实回复质量已通过。
