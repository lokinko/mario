# 买点观察助手

## 目标与使用方式

第一阶段只跟踪用户认可的沪深 A 股，支持已有持仓及尚未持有的公司。默认首页为“买点观察”，用户加入证券代码、名称及可选的关注理由；同一证券跨账户的持仓和交易直接关联原账本，不创建虚拟持仓。最多观察 50 家公司。

交易日收盘后检查变化，周末集中复盘。首次进入关注区间以及从关注区间退出时产生站内未读提醒；相同状态持续不重复提醒。已读状态按账号保存；关闭网站不影响服务器继续检查，但第一阶段没有站外推送。

第一阶段不发现陌生公司、不生成卖出建议、不自动交易，也不计算精确买入数量。基本面稳定、分红持续性和低估与否需要在研究讨论中核查，不由技术条件自动推断。研究 benchmark 继续独立运行，观察助手不调用研究 CLI，也不把当前规则写成一个新的 benchmark 参数变体。

## 明确规则

以下是用户选定的观察门槛，不是对收益的验证结论：

- TTM 税前股息率至少 **5%**，含边界。
- 日线和周线各用 BOLL(20,2)：20 期收盘均值，加减两倍总体标准差。
- 日线与周线必须**同时**满足 `abs(收盘价 / 下轨 - 1) ≤ 2%`，即各自下轨价格上下 2%，含边界。跌破下轨超过 2% 不满足“接近”；只在周中轨以下也不满足。
- 下轨不为正、历史不足或有缺口时，相关条件保留未知，不将未知视为通过或信号退出。
- 周线按 ISO 周聚合；本周未结束时，采用截至观察日的最后收盘，页面明确显示这一口径。跨周重新计算，不使用之后的周收盘。

行情使用 Yahoo 同源日线与调整收盘价；技术序列按最新调整系数归一到当前价格单位。上证指数日线仅提供实际已有的交易日期参考，缺少证券行时不补零、不假设停牌或沿用旧价。每条观察保存实际行情日及来源，供应商延迟时不能声称已经取得当日收盘。

分红使用东方财富 `RPT_SHAREBONUS_DET` 已实施记录，以除息日落在 `(观察日−365天, 观察日]` 为窗口，排除预披露和未来实施记录。税前每十股金额换算到每股，并按窗口内后续送股和转增归一到当前股数单位；供应商已实施记录中的空分项表示该分配方案没有相应分项。股息率包含特别分红，不预测下一次分红，也不把个人账户收到的分红金额作为公司每股分红。分页或身份不完整时只停用股息率部分。TTM 和门槛比较使用十进制，BOLL 使用浮点指标运算。

## 检查、讨论与复盘

服务器进程每 30 分钟检查账号名单。北京时间 19:00 后可采用当日收盘，此前以昨日为截止日；保存 `checked_for` 与实际检查时间，避免早上的补查阻止当天晚间检查。来源失败、缺项或交易日晚间尚未取得当日数据时可重试。仅对来源实际交易日期保存观察，周末不伪造交易日。单次刷新上限 120 秒、外部请求并发最多 2；关闭服务时取消后台任务，重新启动后补查当前截止日。

观察结果和检查状态在账号锁内事务保存，网络期间释放账号锁；保存前核对观察条目仍存在且未被修改。删除后不因在途刷新重建条目，不让较早数据覆盖较新的状态。获取失败保留先前结果及其日期，单只证券失败不阻塞其他公司。

“结合我的交易讨论”将公司、用户关注理由与规则带入现有问答。按原问答预设授权：持仓事实卡增加每项最近 20 笔已录入交易（日期、同日顺序、原始股数和价格、金额、费税、账户、备注），现金按币种提供原值和核对状态。原始成交价保留成交时股数口径，不能跨拆合股直接比较。修改交易使新分析的冻结指纹变化，历史分析仍保留原输入。

已保存的相关观察作为带来源与日期的研究证据冻结，不通过问题文字冒充已核验事实。关闭研究证据授权则不发送观察证据；关闭持仓授权则不发送持仓和交易。基本面研究沿用供应商搜索设置，需要用户发起问答；后台检查不自动调用模型或要求个人电脑桥接持续在线。

本周汇总由已经保存的逐日观察生成，显示每家公司的日期和状态，不回填加入名单之前的历史。周末一键进入复盘讨论；受当前证据上限约束，一次先讨论名单前 5 家，更多公司可逐项讨论。页面的周内状态表包含全部观察公司。后续可以在“复盘记录”保存个人总结。

## 模块、接口与数据归属

沿用[架构说明](architecture.md)第 3 节分层、第 6 节数据流、第 7 节状态归属。`models/watch` 拥有规则、契约与纯计算；`ports/market::WatchMarketProvider` 提供公开行情输入，`market_data/watch` 负责来源读取与有界公共缓存；`application/watch` 编排账号检查，`composition` 管理后台任务生命周期。`db/watch` 拥有名单、观察历史、提醒状态和事务，AI 仍只读取冻结资料。

`features/watch` 管理页面草稿与交互；应用壳负责导航和快照生命周期，通过 `onAsk` 进入问答，观察页不引用其他功能实现。交易事实由既有 `context/fact_sheet` 生成，观察证据由分析应用层装配。

| 接口 | 行为 |
| --- | --- |
| `GET /api/watch` | 返回名单、最新观察、未读状态和本周逐日汇总；无写入副作用 |
| `PUT /api/watch` | 保存 `{symbol,name,thesis}`；`.SH` 规范为 `.SS`，证券代码为账号内唯一键 |
| `DELETE /api/watch/{symbol}` | 移除观察条目与观察历史，不修改持仓或交易 |
| `POST /api/watch/refresh` | 手动检查并返回最新观察；当日 19:00 前使用上一日截止数据 |
| `POST /api/watch/{symbol}/read` | 标记该公司的既有变化提醒为已读 |

所有写接口沿用认证、账号隔离、`If-Match` 与版本同步，没有新增免版本检查例外。数据问题以 `price_unavailable`、`daily_history_incomplete`、`weekly_history_incomplete`、`dividend_unavailable`、`non_positive_band` 传递；前端只在对应公司附近展示一次并提供重新检查入口。

## 数据升级与验证

账号 schema 版本 12 增加 `watch_entries`、`watch_observations`；备份 v24 包含名单、检查状态、观察原值与已读状态。旧 v23 及以前的备份按原版本恢复，观察名单为空；不从持仓自动创建名单。导入在原单一事务中校验，错误回滚并保留原数据。升级前保留原备份；回退旧程序需配套升级前备份，另行保留 v24 或完整 PostgreSQL 备份以保存新增观察资料。

验证覆盖数值边界、日周同时满足、未来数据隔离、缺失与恢复、提醒去重和重入、账号隔离、在途删除、重启/备份恢复、旧版导入、导入失败回滚、交易授权与指纹，以及真实 HTTP 的认证和版本冲突。完整交付执行仓库 `npm test`，按仓库规范清理本次 Rust 产物。
