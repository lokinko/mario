# 买点观察助手

## 目标与使用方式

这是当前首要使用闭环，目标是减少重复检查，让已有投资记录和 AI 分析真正服务于个人买点判断。产品取舍见[产品主线](product-vision.md)；行业浏览仅提供明确选定的小型公司目录，不自动扫描或扩充市场。

个人自选只跟踪用户认可的沪深 A 股，支持已有持仓及尚未持有的公司；公共目录提供有限的行业比较。默认首页为“买点观察”的“自选”标签，用户加入证券代码、名称及可选的关注理由；同一证券跨账户的持仓和交易直接关联原账本，不创建虚拟持仓。最多观察 50 家公司。

交易日收盘后检查变化，周末集中复盘。首次进入关注区间以及从关注区间退出时产生站内未读提醒；相同状态持续不重复提醒。已读状态按账号保存；关闭网站不影响服务器继续检查，但第一阶段没有站外推送。

市场是否进入关注区间与是否适合个人买入分开处理：前者按当前账号的规则计算，后者结合已有持仓、现金和真实交易讨论。用户希望股息支持长期持有，并关注经营与长期需求稳定性；这些理由需要证据，不因近期持仓上涨自动成立。

当前只在人工维护的公共目录内支持行业浏览，不自动发现陌生公司、不生成卖出建议、不自动交易，也不依据观察信号分配买入数量；股息网格仅按用户设置生成可编辑的股数档位并测算计划。基本面稳定、分红持续性和低估与否需要在研究讨论中核查，不由技术条件自动推断。研究 benchmark 继续独立运行，观察助手不调用研究 CLI，也不把当前规则写成一个新的 benchmark 参数变体。

## 明确规则

观察规则按账号统一保存，自选与全部行业列表共用；这是用户选定的关注条件，不是对收益的验证结论。默认值与原规则一致：

- TTM 税前股息率至少 **5%**，含边界。
- 日线和周线各用 BOLL(20,2)：20 期收盘均值，加减两倍总体标准差。
- 日线与周线必须**同时**满足：日线 `abs(日收盘价 / 日下轨 - 1) ≤ 2%`，即日下轨价格上下 2%，含边界；周线 `周收盘价 ≤ 周中轨`，含相等，不要求接近周下轨。日线跌破下轨超过 2% 不满足“接近”；周线低于周下轨仍可满足周条件。
- 所选参考轨不为正、历史不足或有缺口时，相关条件保留未知，不将未知视为通过或信号退出。
- 周线按 ISO 周聚合；本周未结束时，采用截至观察日的最后收盘，页面明确显示这一口径。跨周重新计算，不使用之后的周收盘。

页面顶部“观察规则”可配置最低股息率，以及日线、周线各自的参考轨（上轨／中轨／下轨）、比较方式和偏移；BOLL 的 20 期与两倍总体标准差保持统一。三项条件仍须同时满足，均包含边界。比例最多保留两位小数：最低股息率 0.01%–100%，附近偏离 0%–99%，单向偏移 −99%–100%。具体含义为：

| 比较方式 | 判断公式（参考轨价格为 R，收盘价为 P，配置百分比为 x） |
| --- | --- |
| 附近 | `abs(P / R − 1) ≤ x / 100`，即 R 上下 x% 内 |
| 不高于 | `P ≤ R × (1 + x / 100)`；x 可为负值 |
| 不低于 | `P ≥ R × (1 + x / 100)`；x 可为负值 |

例如日线上轨附近 1.5%、周线不高于中轨下移 2%、最低股息率 3.3%，会分别使用上轨 ±1.5%、中轨 ×98% 作为上限，以及精确的 ≥3.3%。距离始终相对所选轨道的原始价格显示，偏移只调整条件。配置由服务端提供默认值，支持恢复默认后再保存。保存后用已有行情立即投影当前结果，不额外请求行情，也不将规则调整当作价格进出；旧提醒清除，新收盘变化按新规则比较。历史周内记录保留检查当时的规则，悬停可见；同一行情日再次实际检查仍按原每日最新观察的覆盖方式保存。编辑草稿不被后台轮询覆盖，另一窗口改过配置时保存返回冲突并保留输入，可主动重新读取。

行情优先使用东方财富日线：未复权收盘价用于股息率，同源后复权收盘价用于技术序列，并按观察日调整系数归一到当日价格单位。该组来源请求或校验失败时，整组回退到 Yahoo 同源日线与调整收盘价；不同供应商的价格、复权序列与交易日期不拼接。来源切换可能使 BOLL 数值略有差异，规则门槛不变，每条观察保存实际采用的来源 URL。上证指数日线仅提供实际已有的交易日期参考，原始与复权日线按日期对齐，缺少证券行时不补零、不假设停牌或沿用旧价；缺少复权行只停用受影响的 BOLL，仍可计算价格和股息率。每条观察保存实际行情日，供应商延迟时不能声称已经取得当日收盘。

分红使用东方财富 `RPT_SHAREBONUS_DET` 已实施记录，以除息日落在 `(观察日−365天, 观察日]` 为窗口，排除预披露和未来实施记录。税前每十股金额换算到每股，并按窗口内后续送股和转增归一到当前股数单位；供应商已实施记录中的空分项表示该分配方案没有相应分项。股息率包含特别分红，不预测下一次分红，也不把个人账户收到的分红金额作为公司每股分红。分页或身份不完整时只停用股息率部分。TTM 和门槛比较使用十进制，BOLL 使用浮点指标运算。

## 分红日历

解决的具体障碍：观察已认可公司时，需要集中查看接下来一个月已披露的分红安排，避免逐家公司反复查询公告。入口为买点观察页的“分红日历”；默认合并当前公共目录和本账号自选，也可只看其中之一，按证券去重。私人名称和自选标记只来自当前账号，其他账号的自选不进入结果。

默认展示北京时间今天起连续 30 天（含首尾），可前后翻页；股权登记日、除权除息日和派息日分别展示。只有来源已公布实施安排、且实际日期落在窗口内的计划进入日期格。未确定日期的预披露、董事会预案、已批准计划及进度待核实项另列“日期待定”，仅保留近一年公告；取消与不分配不进入日历。不根据往年日期推测下一次分红，空日历只表示已获取资料中没有相应安排，不能证明未来不会新增公告。

当前直接读取东方财富 `RPT_SHAREBONUS_DET` 公开结构化分红方案，不调用大模型、不要求 API 密钥。逐条校验沪深证券身份、完整分页、公告日期、方案状态、十进制金额与日期顺序，保留报告期、原始进度、分配方案、来源及实际获取时间。报告期只是所属期间，老报告期后来公布的真实实施安排仍可进入日历。该来源暂未提供可靠派息到账日，保持“来源未提供”，不以除息日替代；现金金额缺失保持“未披露”，不写成零。异常日期或金额只停用该部分，在对应计划提供重新抓取入口。

分红计划按证券每隔至少 24 小时自动抓取一次，范围为当前公共目录和各账号自己的自选；同一标的合并在途请求。沿用启动及每 30 分钟的既有调度检查是否到期，未满 24 小时只读缓存、不访问分红计划来源；成功或失败均以上次实际尝试时间计时，到期后的下一轮调度再抓取。尝试时间持久保存，服务重启不重复抓取未到期的公司；新增且尚无资料的公司在下一轮首次抓取。手动更新绕过时效，仍合并同一时刻的并发请求。每轮最多 120 秒，和现有价格、历史分红共用最多 2 个来源请求并发；来源故障保留上次计划及原获取时间，页面展示逐公司覆盖情况及重试入口。页面每 30 秒读取已保存快照，读取本身不触发外部查询。新增公共公司无需逐人添加即可纳入下轮；移除后不再出现在公共范围，仍为个人自选时继续在其账号范围展示。

计划快照独立存于 PostgreSQL `mario_market.dividend_plan_snapshots`，没有账号 ID、关注理由、持仓或交易字段。它不写已实施历史、个人采用依据、资产和到账记录，不推进账号数据版本，不改变现有买点门槛。整站 PostgreSQL 备份保留计划资料，个人 JSON 备份无需携带可重新获取的公共缓存。

登录后可调用同源接口：

- `GET /api/watch/dividend-calendar?scope=all&from=2026-11-07`：只读 30 天快照；`scope` 可为 `all`、`public`、`favorites`，日期省略则为北京时间今天。
- `POST /api/watch/dividend-calendar/refresh?scope=all&from=2026-11-07`，JSON `{}` 检查该范围全部公司，`{"symbols":["600036.SS"]}` 只重试指定公司。证券必须属于当前公共目录或本账号所选范围；不允许任意代码扩池。该接口只更新公共事实缓存，在服务端和客户端显式免个人数据版本校验。
- 返回 `start`、`end`、`asOf`、`scope`、`entries`（已定日期）、`pending`（日期待定）、`coverage`（逐公司尝试/成功时间及失败状态）；金额为十进制字符串，未知值为 `null`。刷新后重新读取本账号当时的自选，避免在途移除恢复旧名单。

此功能只整理已经披露的安排，不承诺每家公司都会在未来 30 天分红，也不计算个人预计到账金额。当前生产路径使用结构化来源，不启用模型解析。

## 分红事件存储与股息率重算

解决的具体障碍：分红事件低频，但过去每次行情检查都重新抓取，重启后不能独立复用原始资料，也难以区分已确认无分红与读取失败。

- 公共库 `mario_market.dividend_histories` 按证券代码保存一行事件集，所有账号复用；账号 `watch_dividends` 保留最后采用的分红依据（JSON 文本，沿用仓储契约），而非每天复制分红表或只保存供应商股息率。事件包含报告期、除息日、税前每十股现金、送股与转增比例；元数据包含来源分页 URL、采集时间和覆盖截止日。使用十进制字符串保存金额与比例。
- 来源完整分页并核对证券身份、总数和重复事件后，整份替换该证券的已实施历史；保留窗口外的历史事件，供以后重新滚动计算。提案和未来除息不进入事件集。新抓取可以纠正旧数据，避免逐笔追加造成重复；这是最新来源快照，不宣称历史时点可知性。每日观察仅冻结当次 TTM 使用的事件与来源日期。
- 检查按截止日复用公共库的完整资料；缺失或过期时即时查询来源，成功立即保存到公共库，其他账号与进程重启后可直接复用。同一进程合并同一标的的并发抓取；失败保留旧资料并作 60 秒退避，后续检查重试。手动“重新检查数据”清除失败退避、更新行情，对已覆盖当日的成功分红继续复用。账号采用的资料与观察结果在原账号事务内保存；行情获取失败不撤销已保存的公开分红，删除或编辑在途条目不会恢复账号旧数据，较慢的旧请求不覆盖新结果。
- 每次成功取得价格都按 `TTM 每股税前现金分红 ÷ 该日未复权收盘价 × 100%` 重算。TTM 窗口随实际行情日滚动，分红到期自动移出，送转仍调整每股单位；不把上次股息率直接沿用到新价格。现有行情是收盘日线，页面明确标注行情日，当前未提供盘中行情推送。
- 已成功核验的空事件集可以得到 0%；网络或协议失败不能写成空集。失败保留旧事件和原采集时间；旧覆盖截止日不足以覆盖新行情日时，当前股息率为未知、观察不能通过，但价格和 BOLL 仍可计算。详细卡片展示分红覆盖日期，详情依据区展示参与计算的事件，讨论冻结同一份分红依据。
- 公共分红与账号名单分开保存：部署启动即载入已核验资料；新增抓取只针对用户认可的观察公司，不自动扫描市场。移除观察公司会删除该账号的观察与分红依据副本，公共库继续供其他用户复用；原账本的真实分红到账记录保持独立。整站备份包含公共库，单账号备份只包含自己的观察及采用依据。此次明确授权整理的公开原件经离线核验后形成内置资料包；运行时不访问研究目录。

### 已有采集资料的接入

公开资料包位于 `server/data/watch-dividends-20261104.json`，随程序发布；整理过程和覆盖数字见[接入审计](audits/watch-dividend-bootstrap-20261105.md)。离线工具 `scripts/prepare-watch-dividends.py` 验证来源归档的逐文件哈希、证券身份、完整分页、事件唯一性与日期，以所有保留的原始响应恢复已实施历史，不局限于原五年汇总；未来实施与提案不计入。金额和送转沿用线上同一来源的空分项与十进制契约。

`server/data/watch-dividends-20261107.json` 补充复核 21 个当前标的，按证券和资料新旧合并，其他证券保留原覆盖日期；导出同样使用各证券实际覆盖日。[三年明细审计](audits/watch-dividend-history-20261107.md)记录范围、105 条三年事件、来源和复现方式。

API 启动时，`market_data/watch_archive` 验证资料包，`composition` 将可用历史事务载入 PostgreSQL 公共库，所有用户无需分别导入。`application/watch_market` 通过行情端口封装公开仓储与来源查询，按标的合并当前进程的并发抓取；已有且覆盖当日的数据直接复用，缺失或过期时抓取并持久化。初始化仅写公开事实，不创建用户观察名单、持仓或交易，不覆盖较新的公共资料；运行时不访问研究目录或调用研究 Python。

账号检查从公共资料和自己最后采用的依据中选择较新版本，并将本次采用依据及观察结果存回账号事务；公共资料有更新时，同日已经检查过的账号也会重新计算。来自账号 JSON 备份的依据只用于该账号，不写入公共主资料库。资料未覆盖新行情日且补抓失败时，股息率保持未知并继续补查。

公开库没有来源历史的股票（包括内置资料标为无记录或缺日期的标的）仍按当前观察请求即时查询；来源可用并校验通过后写公共库。未知来源不写成零分红，失败不会清空已有事件。公共库初始化、跨账号复用和整站备份的升级说明见[部署指南](deploy-madeagents.md#公开分红资料上线)。

报告期只作为来源分配方案的标识，不作为实施时间。部分旧记录以年末标记报告期，实际除息日可能在该年较早月份；这种记录按有效除息日计算，不因报告期标签晚于除息日而停用整只股票。已实施记录缺少除息日仍保持未知，不猜测实施日期。

可直接导出 210 只股票的分红参考清单：

```bash
cargo run --manifest-path server/Cargo.toml -- --export-watch-dividends 分红参考.csv
```

这是离线公开资料导出，不连接账号库。CSV 使用与线上相同的 TTM 计算器，列出资料截止日、每股税前 TTM 分红、恰好满足默认 5% 股息率的参考价格、来源及待核查原因；未知金额保持空白，不伪造 0%。参考价格只对应股息率门槛，仍须结合日周 BOLL 和基本面核查；CSV 不含当前行情，不代表通过完整买点规则。输出拒绝覆盖已有文件。

`server/data/watch-catalog.json` 保存当前初始化目录、格式版本、目录日期、唯一代码、名称、比较领域及公开来源；61 家均已匹配交易所公司资料和巨潮年报全文链接，逐公司保留 `sourcesCheckedOn` 日期。线上目录保存在 PostgreSQL `mario_market.watch_catalog`；初次建库载入，已有目录只执行明确的一次性升级，之后重启不会覆盖人工维护的名单。领域是用户选择的比较分组，不冒充标准行业评级；入池不要求当前满足账号观察规则，也不代表分红持续性或基本面已获认可。

公司身份确认后，服务端自动取得交易所资料入口并查询巨潮最近可用的年报全文公告；匹配代码、组织标识、公告时间与报告类型，排除摘要、英文版、其他公司及未来公告，不猜测 PDF 地址。报告尚缺或来源请求失败时保留已确认身份和已有来源，`sourcesCheckedOn` 留空，允许保存；这只作为“公开来源待补充”的元数据，不阻止价格、股息与 BOLL 各自计算。详情继续显示实际已有链接，年报链接不等于已完成基本面研究。

#### 目录扩充的历史证据

2026-11-07 的人工扩充在既有领域核对 26 家后纳入 8 家，既有 43 家未被本批重新评级。使用 2026-11-06 未复权收盘及此前 365 天已实施分红，以严格 >4% 作为本批筛选门槛；该数值不参与当前日常观察。逐公司金额、实施公告、报价时间戳、原始响应哈希、财报依据及全部排除理由以[筛选审计](audits/watch-catalog-screening-20261107.json)为准。以下历史说明用于解释目录来源，不构成持续扩池政策、基本面评级或新增待办。

人工筛选曾参考经营、现金流、银行资产质量与资本、分红和派息时点；个别 TTM 包含两期中期及一期末期分红。原审计保留这些风险和排除理由，不据该日股息率推断稳定年化回报，也不把入池视为永久基本面认可。

同日为补充券商比较分组，按用户指定范围核对 16 家、纳入 10 家，严格 >3% 只用于本批入池筛选。金额口径与价格日期同上；所有候选、实施记录、年报链接、证券身份、响应哈希和排除原因见[券商筛选审计](audits/watch-catalog-brokers-20261107.json)，原件归档保留于 `.runtime/broker-catalog-20261107/raw/`。券商盈利和分红受市场周期及监管资本约束，不能把单日 TTM 当作稳定年化承诺。

两批筛选都不自动写入个人自选，不复用离线快照作为运行中的当日观察。当前目录可由超级账户维护，日常是否进入关注区间统一按账号规则判断；目录数量、当日价格与股息率不由上述历史快照决定。

`mario_auth.users.is_superuser` 保存权限，服务器在每次认证后读取，前端根据目录返回的 `canEdit` 显示入口。此次升级只在首次添加权限字段时将**已有的** `lokinko.cs@gmail.com` 账号设为超级账户，既有会话刷新页面即可使用；普通注册及之后注册同名邮箱均不自动获得权限，重启不会恢复已撤销权限。超级账户当前仅增加公共目录维护能力，不能访问其他账号的资产或交易。普通账号仍可浏览目录和管理自己的自选，越权维护返回 403。

目录有独立的 `revision`，保存时由公共仓储事务锁定目录、比较版本并同时更新内容、版本、操作者 ID 与时间。过期返回 409 并保留当前草稿，不自动重试；用户可确认放弃草稿后“重新读取目录”，核对最新内容再编辑。后台读取不会偷偷提高草稿的提交版本；公共目录版本不推进个人账号数据版本，也不受个人资料版本阻塞。

“自选”直接沿用原个人观察名单，原有理由、置顶、网格、提醒和历史完整保留。行业行提供“加入自选／已在自选”；添加使用现有保存入口的 `ifAbsent: true`，由仓储在原事务中保留已存在条目，避免其他页面并发添加时覆盖理由或网格。最多 50 家，自选之外仍可手动添加公司。添加后重新读取个人名单，不复制公共观察为个人历史；自选为空时可按行业浏览或手动添加。

公共详情仅展示价格、股息参考价、日周 BOLL、分红事件、行情来源与行业来源。个人网格、交易讨论、未读提醒和完整周内复盘从自选进入；行业浏览不创建这些记录。

页面默认用紧凑列表并排展示公司、实际行情日、收盘价、TTM 股息率、当前门槛对应的股息参考价、距日周所选参考轨和观察状态；可切换详细卡片。当前分组统计可直接筛选全部、股息达标、日线达标和周线达标，日线与周线分别计数；进入关注区间、未读变化和待补齐数据在观察状态列与默认排序中体现，不再单独设筛选卡；搜索覆盖名称、代码，自选中还覆盖关注理由，并可叠加已持有/未持有筛选。默认未读变化与关注区间优先。可用排序菜单或点击表头，按收盘价、TTM 股息率、距日线或周线所选参考轨双向排序；菜单也可按公司名称排序。日周距离按绝对百分比从近到远或从远到近，数值仍显示正负以区分轨道上方和下方。

列表和卡片都可置顶或取消置顶。置顶公司在符合当前筛选的结果中排在最前，置顶与未置顶两组各自按所选指标排序，缺失指标排在各自组末尾。置顶随账号保存并随账号备份恢复。排序、筛选和展示方式只属于当前页面；这些操作不改变观察状态、提醒、后台检查或完整周内汇总。

打开公司详情可查看 4%、5%、6%、7% 及当前自定义门槛（去重）的股息率参考价、日周 BOLL 位置图、分红事件、来源和原账本最近交易。参考价由服务端以 `TTM 每股分红 ÷ 目标股息率` 十进制计算，向下取到人民币分，避免显示高于对应股息门槛的价格。当前配置的门槛单独标记，其他档位用于对比；是否达标按未舍入的十进制值判断，显示参考价仍向下取分。这些参考价不生成买卖建议或改变账号规则。没有有效正分红时不生成正股息参考价，没有价格时不判断是否已达；资料不足只停用相关部分。

BOLL 图同时展示下轨、中轨、上轨与收盘位置，日周阴影分别按当前所选参考轨、比较方式和偏移标注显示区间，以服务端结果显示是否满足；绘图坐标仅作展示，不按带宽判断通过。周内足迹按已保存观察组成日期矩阵，空白格不补造记录。分红事件表展示以实际行情日向前 36 个日历月、包含起止日的所有已实施方案，按除息日倒序列出报告期、税前当次每十股派现、送股与转增，并标记哪些事件属于 TTM 窗口。三年明细独立于 365 天 TTM 计算，不推测未来除息日或年度分红。旧观察未保存三年明细时只标为 TTM，下一次成功检查补齐；旧资料仍显示原覆盖日期，缺失不当作零分红。

### 股息网格与价差测算

公司详情先填写该标的的配置金额（人民币元，大于 0、不超过一万亿元、最多两位小数），再填写各股息率档位的买入、卖出股数。每档为 0 至 10 亿之间的整数股，留空视为不操作，至少一档买入股数须大于 0。股价下跌、股息率上升时按档买入；股价上涨、股息率下降时按档卖出。股息率范围与间距由用户设置；1 至 100 档之间，档位不重复，每档精度为 0.01 个百分点，股息率在 0.01%–100% 之间。

批量生成时填写最低/最高股息率、间距（股息率百分点）、首档买入与卖出股数，以及两个方向各自的股数递增比例。间距须整除范围，比例可为 -100% 至 1000%。生成的买入从最低档的上一档向更高股息率排列，卖出从最高档的下一档向更低股息率排列；最低档默认不买、最高档默认不卖。股数为「首档股数 ×（1＋递增比例）的档次幂」，每档四舍五入为整数股。生成设置随方案保存；生成后仍可修改任意档位和股数、添加或删除档位。已有股数时重新生成须明确确认替换；只修改生成设置不点击生成，不改变已配置档位。

服务端按最近已保存且覆盖有效的正 TTM 每股税前分红计算「每股分红 ÷ 档位股息率」参考价、每档用款和回款。对每个已有累计买入股数的触及档位，测算先下跌到该档，再反弹到方案中的最低股息率档位：下跌依次买入，反弹只经过严格低于最深触及股息率的卖出档位，每档每轮最多操作一次。按用户填写股数计算，不因预算不足静默缩减买入；展示累计投入和预算余额，负数表示资金缺口。卖出最多使用本轮买入余股，超出数量在情景中明确列为卖出不足股数，不从真实持仓中补足。未卖余股按最低档参考价估值，不强制清仓。展示卖出回款、余股数量、含余股估值的盈亏，以及按已投入/总预算计算的收益率。无有效正分红时保留金额、档位和股数，仅停用价格、用款和收益测算。

这是一轮价差情景，假设每股分红保持不变、按档位理论参考价成交，不计持有期实际分红、税费、滑点、整手约束或达到反弹价格的概率。网格不参与账号规则的观察判定或提醒，也不读取现金或持仓来下单，不写入真实交易账本。

### 公共行业收盘检查

公共目录的最新结果保存在 `mario_market.watch_snapshots`，只包含公开观察及检查状态，不包含账号信息、关注理由、置顶、网格、提醒或交易。所有已登录用户复用这些公开事实，接口返回前按认证账号的规则只读投影状态和参考价，不将个人配置写回公共库；是否已加入自选由前端与本账号名单匹配。行业页每 30 秒读取最新快照，读取不抓取来源或写库，目录读取失败不阻止使用已有自选。

服务器启动即补查目录，每 30 分钟再次检查，沿用北京时间 19:00 的截止规则、原行情供应商选择、统一行情指标与参考价计算。当前截止日已完整检查则跳过；来源失败、数据缺失或交易日实际行情滞后继续重试。相同公司在途公共检查合并，公共和个人流程共用行情供应商的缓存与请求预算（价格及分红请求最多并发 2 个），单轮最多 120 秒。手动按当前行业重新检查，成功的当日分红仍复用，失败退避清除；浏览和读取不等待后台检查完成。

公共分红只从公开仓储或来源读取，不采用任何账号恢复的分红依据。行情失败保留原结果及其实际日期；首次失败保持未知，单只公司失败不阻塞其他公司。价格成功但分红失败时保留价格与 BOLL，当前股息未知且可重试。较慢的旧写入不能覆盖更新的快照，非交易日不补造观察日期。公共更新不推进任何账号版本，也不写个人观察历史或提醒。

### 个人自动检查

服务器进程每 30 分钟检查账号名单。北京时间 19:00 后可采用当日收盘，此前以昨日为截止日；保存 `checked_for` 与实际检查时间，避免早上的补查阻止当天晚间检查。来源失败、缺项或交易日晚间尚未取得当日数据时可重试。仅对来源实际交易日期保存观察，周末不伪造交易日。单次刷新上限 120 秒、外部请求并发最多 2；关闭服务时取消后台任务，重新启动后补查当前截止日。

观察结果和检查状态在账号锁内事务保存，网络期间释放账号锁；保存前核对观察条目仍存在且未被修改。删除后不因在途刷新重建条目，不让较早数据覆盖较新的状态。获取失败保留先前结果及其日期，单只证券失败不阻塞其他公司。个人详情在观察依据旁说明本次来源失败及所保留的行情日期，并提供“重新检查数据”；首次失败明确尚无结果，重新检查期间禁用重复操作。

“结合我的交易讨论”将公司、用户关注理由与规则带入现有问答。按原问答预设授权：持仓事实卡增加每项最近 20 笔已录入交易（日期、同日顺序、原始股数和价格、金额、费税、账户、备注），现金按币种提供原值和核对状态。原始成交价保留成交时股数口径，不能跨拆合股直接比较。修改交易使新分析的冻结指纹变化，历史分析仍保留原输入。

已保存的相关观察作为带来源与日期的研究证据冻结，不通过问题文字冒充已核验事实。关闭研究证据授权则不发送观察证据；关闭持仓授权则不发送持仓和交易。基本面研究沿用供应商搜索设置，需要用户发起问答；后台检查不自动调用模型或要求个人电脑桥接持续在线。

同一公司在不同账户的真实交易仍保留账户归属，不从信号推算交易，也不预设加仓次数、仓位上限或资金比例。

本周汇总由已经保存的逐日观察生成，显示每家公司的日期和状态，不回填加入名单之前的历史。周末一键进入复盘讨论；受当前证据上限约束，一次先讨论完整自选名单按证券代码排列的前 5 家，更多公司可逐项讨论。该批次不随页面的置顶、搜索、条件筛选或指标排序重新选择；周内状态表沿用完整名单的代码顺序，包含全部观察公司。讨论后可在已有“复盘记录”保存个人总结，不要求结构化评分。

## 模块、接口与数据归属

沿用[架构说明](architecture.md)第 3 节分层、第 6 节数据流、第 7 节状态归属。`models/watch` 拥有规则、契约与纯计算；`ports/market::WatchMarketProvider` 提供公开行情输入，`market_data/watch` 负责来源读取与有界公共缓存；`application/watch` 编排账号检查，`composition` 管理后台任务生命周期。`db/public_dividends` 拥有公开主资料，`application/watch_market` 编排共享查询和补抓；`db/watch` 拥有名单、最后采用的分红依据、观察历史、提醒状态和账号事务，AI 仍只读取冻结资料。

`features/watch` 管理页面草稿与交互；应用壳负责导航和快照生命周期，通过 `onAsk` 进入问答，观察页不引用其他功能实现。交易事实由既有 `context/fact_sheet` 生成，观察证据由分析应用层装配。

| 接口 | 行为 |
| --- | --- |
| `GET /api/watch/catalog` | 返回十一个领域的当前公司、独立 `revision`、`canEdit`、公共最新观察、参考价和检查状态，含目录及行情来源；无写入副作用 |
| `POST /api/watch/catalog/resolve` | 超级账户提交 `{query}`，只查公司身份及来源、返回公司契约；不写目录、无账号版本要求，越权 403 |
| `PUT /api/watch/catalog` | 超级账户提交 `{catalog, revision}` 替换公司目录；独立版本校验，过期 409、越权 403，不改个人资料 |
| `POST /api/watch/catalog/refresh` | 接受 `{industryId}`，只重新检查该行业；认证和 `If-Match` 保留，公共更新不推进账号版本 |
| `GET /api/watch` | 返回当前账号 `rules`、服务端 `defaultRules`、名单（含 `entry.pinned` 和可选的 `entry.gridPlan`）、网格测算、最新观察、逐公司 `dividendPrices` 参考价、未读状态和本周逐日汇总；无写入副作用 |
| `PUT /api/watch/rules` | 接受 `{rules, expectedRules}`，保存账号规则并返回重算后的自选视图；保留 `If-Match`，同时核对打开草稿时的规则，过期返回 409；公共行情不被改写 |
| `PUT /api/watch` | 保存 `{symbol,name,thesis}`，可附 `ifAbsent: true` 仅添加不存在的条目；`.SH` 规范为 `.SS`，证券代码为账号内唯一键，编辑保留置顶与网格方案 |
| `PUT /api/watch/{symbol}/pin` | 保存 `{pinned}` 并返回更新后的条目；沿用认证与 `If-Match` 版本检查，公司不存在则返回 404 |
| `PUT /api/watch/{symbol}/grid` | 保存公司网格并返回更新后的观察桌面；传 `null` 清除，沿用认证与版本检查 |
| `DELETE /api/watch/{symbol}` | 移除该账号观察条目、采用的分红依据与观察历史；公共分红继续保留，不修改持仓或交易 |
| `POST /api/watch/refresh` | 手动检查并返回最新观察；当日 19:00 前使用上一日截止数据 |
| `POST /api/watch/{symbol}/read` | 标记该公司的既有变化提醒为已读 |

所有接口保留认证。公共目录 `PUT` 使用自身 `revision`；公司来源查询和分红计划刷新免账号版本校验，前者不写库，后者只更新公共缓存。其余观察写接口沿用账号 `If-Match`，公共行业行情刷新也保留版本检查。个人写入保持账号隔离和版本同步，公共刷新只更新共享公开快照。数据问题以 `price_unavailable`、`daily_history_incomplete`、`weekly_history_incomplete`、`dividend_unavailable`、`non_positive_band` 传递；前端只在对应公司附近展示一次并提供重新检查入口。

## 数据升级与验证

账号规则保存于既有 `settings` 表的 `watch.rules`，结构为整数基点（1 基点 = 0.01%）；不新增表或账号 schema 版本。保存规则与清除旧规则提醒同一事务提交，失败整体回滚；无变化的保存不清除提醒。v28 个人备份包含规则，导入时校验枚举、范围和整数基点；v27 及更早备份没有该项时恢复默认值，不沿用目标账号原配置。旧程序不能读取 v28，回退应恢复升级前备份；新版导入失败保留配置和数据。每条新观察冻结 `rules` 与精确的 `yieldMatchesRule`；旧观察缺少规则时按当时默认规则解释，当前列表则用当前账号规则只读投影，不追溯改写历史或已完成 AI 分析。在途旧请求保存时重新读取账号规则，避免将已过期条件写回。公共快照按默认规则计算公开事实，HTTP 返回前用当前账号规则重新投影，不把账号配置写入公共库。

启动时事务创建 `mario_market.watch_catalog`，缺少目录行时初始化 61 家公司。目录发布 v1 → v2 的一次性迁移依据 `server/data/watch-catalog-additions-20261107.json` 中明确授权的 33 个代码合并名单：煤炭与石油石化合并到能源，高速公路调整为运输，家电更名为白色家电，新增保险、中药、消费。保留既有自定义公司及其资料，不恢复未被本次点名且此前已删除的公司；此次明确添加的公司按请求分组归入。迁移、目录版本推进在同一公共事务内完成，失败回滚；迁移成功后删除的公司不会在下次启动重新出现。v2 → v3 另按 `server/data/watch-catalog-screened-additions-20261107.json` 一次性补入本轮核验的 8 家；不重放 v1 的 33 家添加清单，保留 v2 中已有的手动删除、自定义名称及公司资料。v3 → v4 按 `server/data/watch-catalog-broker-additions-20261107.json` 新增“券商”领域及十家符合本批 >3% 筛选的公司，按全目录代码去重，保留已存在公司的领域、名称及来源，不重放旧批次清单。三个升级步骤均可从旧整站备份事务执行；运行目录统一为 v4，之后移除本批新增公司不会在重启时复活。旧版本解析只服务迁移/恢复，停止支持旧整站备份后方可移除。`watch_snapshots` 继续保存公开行情。认证库一次性添加 `is_superuser` 并升级指定已有账号，不修改账号 schema 或个人备份格式。迁移失败不保留部分目录或部分权限字段；修复数据库问题后重启重试。整站备份包含目录、权限和公共快照，旧整站备份恢复后由启动迁移；仅恢复账号 JSON 不修改公共目录或权限。升级前保留整站备份。旧程序不支持权限和维护后的目录，回退前应保留新版整站备份以保存维护结果，不删除公共表或用户记录。推送代码不会升级正在运行的服务，部署须沿用根目录 `deploy.sh`。

公共库 `mario_market` 在 API 启动时事务创建并载入内置资料，不依赖逐账号登录；旧版本账号与备份无需重录名单或个人数据。缺少公共库的旧整站备份恢复后由启动初始化并按需补抓，新的整站备份保留公共数据。账号 schema 版本 15，备份格式为 v28。置顶与股数网格保存在名单 JSON 中，恢复前校验配置金额、档位、整数股数及生成设置。schema 15 升级和 v24–v26 旧备份导入在原事务内将旧比例网格原样移动到 `previousGridPlan` 历史参考，移除旧 `gridPlan`，不推测配置金额或股数；界面提供原分母、比例和原 4% 清仓规则供重新设置时核对。历史参考随新版备份保留，保存或清除新网格不删除该参考。旧比例计算与编辑入口已删除，仅保留迁移读取和历史展示，停止支持这些旧数据/备份后可移除适配。缺少置顶或网格字段的记录仍默认为未置顶或未配置。轨道契约使用 `reference`（`lower`／`middle`／`upper`）、相对参考轨的 `distancePct` 和 `matchesRule`，不再输出 `nearLower`。升级与 v25/v24 旧备份导入在原单一事务中，按已保存的收盘价、精确分红和轨道重算全部旧观察条件与状态，保留行情事实与日期，清除旧条件提醒、允许当前行情日重新检查。已完成分析中的冻结依据和答案不追溯重写。迁移失败整次回滚；回退旧程序须恢复升级前备份，不可将 v28 导入旧程序。升级不从旧观察明细推断完整历史或无分红：首次检查从来源补齐独立事件集，旧观察的行情事实保留。v24 备份仍恢复名单与观察，分红事件集为空并在下次检查补齐；v23 及以前恢复为空观察名单，不从持仓自动创建。导入在原单一事务中校验金额非负、报告期与除息日期、覆盖日期和唯一性，失败回滚并保留原数据。升级前保留原备份；回退旧程序须配套升级前备份，同时保留 v28 或完整 PostgreSQL 备份以保存新增资料。
