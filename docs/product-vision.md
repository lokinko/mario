# mario：产品目标与当前主线

本文决定功能取舍；实际行为以[买点观察助手](buy-watch.md)和各领域文档为准，工程边界以 [AGENTS.md](../AGENTS.md) 与[架构说明](architecture.md)为准。

## 要解决的实际问题

创建 mario 是为了辅助自己的投资理财。投资信息录入提供个人事实，AI 问答帮助分析，benchmark 用于验证策略；三条线各自扩张后，维护和开发占用了注意力，实际投资使用却没有形成习惯。

当前目标是：**让 mario 持续照看自己认可的公司，在出现值得研究的价格条件时提醒自己，并结合真实持仓和交易帮助判断下一步。** 先完成这条日常使用路径，再根据实际缺口决定是否增加能力。

## 认可公司的投资逻辑

用户看重三个条件：股息足够高，愿意长期持有；公司经营与长期需求相对稳定；价格进入合意的技术区间。富贵策略提供了研究思路，近期持仓表现提供了使用动机，但短期上涨不构成策略有效性的验证。

观察规则由用户按账号统一配置，自选与行业列表共用。默认值为：

- 已实施现金分红 TTM 税前股息率至少 5%；
- 日线、周线均采用 BOLL(20,2)：日收盘价在日线下轨价格上下 2% 内，周收盘价在周线中轨及以下（≤），两个条件必须同时满足；
- 公司是否值得长期持有、分红是否可持续，需要有来源的基本面研究；BOLL 位置不等于内在价值或低估证明。

日线与周线可分别选择上轨、中轨、下轨，以及附近、不高于、不低于和百分比偏移；TTM 最低股息率也可调整。三个条件始终同时满足才进入关注区间。改配置立即重算当前视图，历史记录保留当时规则；配置调整本身不产生进出提醒。这些是用户选定的观察门槛，不是收益承诺或 benchmark 最优参数。具体计算、部分周线和特别分红口径见[观察规则](buy-watch.md#明确规则)。研究版富贵策略与线上观察规则分开，不能混用成绩或自动迁移参数。

## 最小使用闭环

```text
认可公司名单 → 收盘检查 → 变化提醒 → 结合真实交易讨论 → 周末复盘
       ↑                                                    │
       └────────────── 更新关注理由与等待条件 ────────────────┘
```

默认入口是买点观察，首先打开个人“自选”。跟踪用户认可的沪深 A 股，包括已有持仓和尚未持有的公司；另提供十一个固定领域的公共公司目录（初始 61 家），供按行业比较股息与价格条件并主动加入自选。公共目录由超级账户人工维护增减，公开来源由系统查询及补充，不自动扩充，不因入池认定公司已经通过基本面核查。

持仓、现金、买卖和分红在原账本维护，观察名单不另造资产。买点有两个层面：市场是否达到观察条件，以及对自己的现有仓位、现金和已发生交易是否合适。确定性观察计算前者，后者交给带授权上下文的讨论。用户可在公司详情手工设置股息网格的配置金额与买卖股数，比较单轮价差情景；该方案不由观察信号决定，不读取真实现金和持仓来安排交易，不写入账本。具体边界见[股息网格](buy-watch.md#股息网格与价差测算)。

用户平日看变化，周末集中复盘。没有变化时无需为了使用产品而反复提问；讨论后继续等待也是有效结果。复盘采用自由文字，不强制填概率、评分、目标权重或整套研究表单。

## 各项能力的职责

| 能力 | 应承担的工作 | 不由它决定的事 |
| --- | --- | --- |
| 确定性观察 | 按统一数据口径和账号保存的规则计算股息率与日周 BOLL，保留日期、来源和状态变化 | 不直接判定基本面稳定、低估或必须买入 |
| 真实账本 | 提供持仓、现金和成交背景，保留精确原值及更正记录 | 不从观察信号生成成交 |
| AI | 核查分红与经营证据，指出反方观点，结合个人交易讨论等待或行动的理由 | 不自动改写资产、下单或把历史模型答案当事实 |
| benchmark | 在独立研究环境检验明确的问题，记录数据、参数和样本局限 | 不用排名代替个人适用性，不阻塞观察助手使用 |

已有风险、再平衡、每日资产和资料管理继续按需使用；它们的存在不意味着必须扩展成完整财务规划平台。基本面目前通过用户发起的研究讨论核查，不声称已有自动监控或可靠性评分。

## 当前不扩展的方向

陌生公司自动发现、盘中盯盘、站外通知、卖出与机动仓管理、自动交易，以及通用 Agent 评测平台、大规模策略搜索和无具体问题驱动的数据扩库，均不属于当前实施范围。也不把工作流拆分、多模型协作、费用看板或投资能力评分设为预定路线图。

保留已有研究成果、运行任务和数据维护说明；新的扩充须由实际使用问题或用户明确任务驱动。历史文档中的“下一步”不自动成为当前任务。

## 判断是否有用

先观察实际使用能否回答以下问题，不把它们机械做成打分页面：

1. 是否减少了逐家公司反复查价格、股息和日周线的工作？
2. 有变化时，能否看清哪项条件变化、数据截至何时、哪些仍未知？
3. 讨论是否真正用上已有交易与仓位，而非每次重新讲个人背景？
4. 周末能否说清下周继续等待什么，以及长期持有理由是否变化？

收益可以记录，但近期涨幅、调用次数、策略数量和开发完成量都不能单独证明产品有效。

## 数据与工程边界

账号数据由自建 PostgreSQL 隔离保存，模型只消费用户授权并冻结的输入；可预览实际发送内容并追溯引用。观察后台只读取公开行情和分红，不自动调用模型。未知数据不当作通过，失败保留先前结果与原日期，修复入口靠近受影响公司。

优先复用现有账本、问答、复盘和部署路径，避免增加第二套事实来源。文档必须区分当前实现、研究局限和历史决定；取消的设计直接移出当前方案，审计事实保留在明确标注的历史记录中。
