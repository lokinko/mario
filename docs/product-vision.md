# 知衡：产品目标与长期原则

> 本文是知衡的产品宪章。功能、界面、模型和数据源可以持续变化，但若一项改动与本文冲突，应先明确修改本文及其理由，而不是让产品在功能堆叠中悄然偏航。

## 我们最开始要解决的问题

AI 时代并不缺内容，投资领域尤其不缺行情、K 线、新闻、观点和周报。真正稀缺的是：在信息过载、结果噪声和情绪诱惑中，仍能形成独立判断，并把判断变成可执行、可证伪、可复盘的长期方法。

知衡要做的不是另一个“告诉用户买什么”的内容入口，而是一款可安装、本地优先、由投资方法论约束的 AI-native 投资决策助手：

- 用户输入自己的财务状况、目标、持仓和投资判断；
- 用户使用自己选择的模型与 API Key；
- AI 在稳定的方法论和确定性风险规则下工作，而不是自由生成荐股结论；
- 系统保留当时的判断、假设、仓位和证伪条件，在未来用真实结果校准认知；
- 模型层保持可替换，为长期记忆、多轮检索、纠错反思和多方案探索保留演进空间。

最终目标是提高决策质量、风险生存能力和长期目标实现概率。产品不承诺收益，也不把短期盈亏包装成能力证明。

## 北极星

**帮助用户建立一套属于自己的、能够跨周期迭代的投资操作系统。**

这套系统先回答“我能承担什么风险、为什么做这个决定、错了会怎样”，再回答“可能赚多少”。它训练的是可迁移能力，而不是对某个模型、博主或行情阶段的依赖。

## 用户长期需要积累的能力

1. **目标与约束**：区分安全、目标和成长资金，理解期限、流动性和损失承受力。
2. **生存与风险**：管理现金流、应急资金、债务、集中度、相关性和不可逆损失。
3. **独立研究**：理解资产、回报来源、定价假设、反方证据和能力圈边界。
4. **估值与概率**：用区间、情景和赔率代替单点预测与确定性叙事。
5. **组合与仓位**：让仓位反映置信度、犯错成本、目标期限和整体风险预算。
6. **行为与纪律**：识别追涨、损失厌恶、确认偏误和计划外交易。
7. **记录与校准**：区分好过程与好结果，通过决策日志和复盘持续修正规则。

## 产品闭环

```text
财务底座 → 目标与期限 → 资产配置 → 独立研究 → 决策与仓位 → 复盘校准
     ↑                                                        │
     └────────────── 更新约束、规则、能力圈与下一次行动 ───────┘
```

每个主动投资决定至少应留下：

- 投资命题和回报来源；
- 最强反方观点；
- 关键未知项与待验证证据；
- 置信度、仓位及其理由；
- 证伪条件、风险边界和复盘日期；
- 到期后的结果、过程评分和规则修正。

## AI-native，不是 AI 替用户下结论

AI 的价值在于扩大思考带宽，而不是制造权威感。知衡中的 AI 应当：

- 把模糊问题拆成可验证假设；
- 根据当前任务检索必要的个人上下文和历史记忆；
- 主动寻找反方证据、遗漏和过度自信；
- 比较多条可行路径及各自适用条件；
- 将结论表达为事实、假设、未知项、行动和证伪条件；
- 从长期复盘中识别重复错误，并帮助用户修正流程。

工作流必须模块化：模型 Provider、上下文构建、记忆检索、方案探索、反思和最终整合彼此解耦。更换模型不应改变产品方法论；增加能力不应绕过确定性风险规则。

## 产品护栏

知衡不会把以下方向作为产品中心：

- K 线盯盘、行情刷新、热点聚合和交易刺激；
- 无来源、无时间戳的“实时事实”；
- 复制大 V、周报或模型结论的一键跟单；
- “稳赚”“必涨”或以确定性口吻表达的收益承诺；
- 只因短期赚钱就奖励错误过程，或只因短期亏损就否定正确过程；
- 通过制造焦虑提高打开频率、交易频率或用户时长；
- 未经用户明确动作上传本地投资数据，或把 API Key 写入业务数据库。

知衡不是券商交易终端、持牌投顾替代品、税务或法律意见提供者。未来若接入交易执行，决策与执行之间仍需保留清晰确认和风险边界。

## 本地优先与数据边界

- 财务档案、目标、持仓、决策和复盘默认保存在本机；
- 服务仅监听本机回环地址；
- 模型 API Key 由操作系统钥匙串管理；
- 仅在用户主动发起分析时，发送完成当前任务所需的最小上下文；
- 接入外部行情和基本面数据后，事实必须携带来源与时间；
- 数据库加密、发送内容预览、审计、签名公证和安全更新是正式发布前的必做项。

## 衡量产品是否走在正确方向

首要指标是用户的决策过程是否改善，而不是页面停留或交易次数：

- 应急资金覆盖和债务风险是否改善；
- 目标、期限与资产配置是否一致；
- 组合集中度、流动性和期限错配是否受控；
- 决策卡完整率、证伪条件覆盖率和复盘完成率；
- 计划外交易、规则违反和不必要换手是否下降；
- 概率判断是否经过足够样本后逐渐校准；
- 用户能否解释自己的判断，而不是只复述 AI 的答案。

收益率是必要的结果信息，但必须在风险、期限、基准和决策过程的上下文中理解，不能作为单一北极星指标。

## 阶段路线图

### 已形成的基础

- 客户端与本地服务端解耦的桌面架构；
- 本地 SQLite 与系统钥匙串；
- 财务档案、目标、持仓维护和确定性风险检查；
- 目标路径模拟、风险预算和基于用户目标权重的再平衡提示；
- 决策卡、不可变原始快照、独立复盘记录和初步概率校准；
- 可替换模型接口，以及计划、记忆检索、多方案、反思、整合工作流；
- 可选择的数据发送预览、候选记忆冻结、上下文一致性校验与本地审计；
- 本地安装包与基础自动化测试。

### 下一阶段

1. 完善周期复盘提醒、组合级回顾和规则修订记录。
2. 接入带来源与时间戳的可信行情、基本面和宏观数据。
3. 升级长期记忆：结构化标签、向量检索、时间衰减和冲突证据。
4. 增加 AI 分析的可信引用、延迟与成本可观测性。
5. 完成数据库加密、威胁建模、应用签名、公证和安全自动更新。

## 每次重要改动的验收问题

合并重要功能前，至少回答：

1. 它提高了哪一种长期投资能力或降低了哪一种明确风险？
2. 它是否让用户更独立，还是更依赖信息流、模型或他人结论？
3. 哪些是确定事实，哪些是模型推断，哪些仍然未知？
4. 它是否保留了原始决策、证伪条件和未来复盘所需的数据？
5. 它发送或新增保存了哪些数据，用户是否知情并可控制？
6. 失败、缺少数据或模型不可用时，产品能否安全降级？
7. 我们将用什么过程指标判断它真的有效？

若这些问题没有清晰答案，该功能还没有准备好进入产品主线。
