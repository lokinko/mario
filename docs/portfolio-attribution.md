# 组合变化归因

## 为什么先记录变化，而不是先展示收益率

组合市值上涨可能来自投资标的升值，也可能只是用户追加了资金；市值下降也可能来自主动取款。若不把外部现金流分开，产品会把储蓄行为误当成投资能力，或者把取款误判为亏损。

mario 因此使用两层不可变记录：组合流水记录期间发生了什么，周期检查点冻结期末组合和本期汇总。每笔流水冻结事件类型、关联资产、原币金额、折算汇率、汇率来源与观察日、当时基准币种、发生日期和说明。事件类型分为：

- 入金与出金：真正进入或离开整个投资组合的外部现金流；
- 分红与利息：组合内部现金收入；
- 费用与税费：组合内部成本；
- 买入与卖出：账户内部交易额，只用于观察换手，不改变组合总值。

流水只追加。创建检查点后，服务端拒绝向最近估值日及以前回填记录，避免已经冻结的归因被后来的编辑静默改变。发现历史漏项时，应保留纠正说明并明确建立新基线。第一个检查点是基线，没有前一期可比较，也不消费此前流水。

批量 CSV 使用同一领域校验，并增加写入前预览、来源交易编号幂等去重、同编号内容冲突检测、预览版本复核和整批事务提交。完整字段和失败语义见 [组合流水 CSV 导入](portfolio-event-import.md)。

## 当前计算

每次检查点冻结当时的持仓、资产类别、原币市值、折算汇率及其来源与观察日、基准币种、估值日期和目标权重。对相邻两个检查点，系统选择满足“发生日期晚于上期估值日且不晚于本期估值日”的流水，并计算：

```text
组合总变化 = 本期总市值 - 上期总市值
估值/数据残差 = 组合总变化 - 本期净外部现金流
```

其中净外部现金流只包含入金减出金；分红、利息、费用和税费保留为单独汇总，并自然留在组合变化结果中；买卖额只累计为换手。检查点冻结实际使用的流水 ID，便于以后核对。

日期和口径完整时，系统还计算 Modified Dietz 期间近似回报：

```text
近似回报 =（期末市值 - 期初市值 - 净外部现金流）
          /（期初市值 + Σ 外部现金流 × 期内剩余天数权重）
```

它比忽略现金流时点的简单收益率更诚实，但仍不是严格时间加权收益率。若期初资本加权现金流后的分母不为正，系统不输出该数值。

系统先按各检查点冻结的汇率折算到当时的基准币种，再按资产类别聚合两个检查点的市值和组合占比，展示市值变化与占比百分点变化。历史检查点不会随当前持仓编辑而改变。全部持仓必须具有同一估值日期；外币汇率缺失、日期缺失或日期不一致时拒绝创建检查点。基准币种或估值口径发生实质变化时，用户必须明确建立一条新的比较基线，不能跨口径计算差额。

“估值/数据残差”和“近似回报”都使用保守命名。当前数据不足以将其解释为精确业绩归因，因为它仍可能混合：

- 资产价格和已实现交易影响；
- 未记录、重复记录或错误分类的分红、利息、费用和税费；
- 汇率变化，以及用户填写的汇率与真实市场汇率之间的偏差；
- 只有日期而没有日内时点，以及现金流发生前后的精确组合估值；
- 漏填持仓、重复录入和其他数据错误。

因此这些指标适合触发问题，例如“变化是否主要来自新增现金”“费用和换手是否过高”“哪类资产占比漂移最大”“是否需要核对录入”，不适合做收益排名、超额收益声明、能力证明或投资承诺。

## AI 与云端边界

最近最多 12 个检查点与最近最多 100 笔组合流水是发送前预览中的两个独立数据组，用户可以分别关闭。模型固定策略禁止把残差称为收益率，并禁止把 Modified Dietz 近似回报称为时间加权收益率或能力证明。

组合检查点与流水属于端到端加密云同步白名单。同步结构 v2 开始包含检查点，v3 为持仓补充折算汇率和估值日期，v4 增加组合流水，v5 为导入流水增加来源、稳定交易编号和去重指纹，v6 冻结汇率来源和观察日期；v1–v5 包仍可恢复。导入标识留在本地和加密同步包内，不发送给模型。模型 API Key、账户令牌、恢复密钥和设备本地设置仍不进入同步包。

## 下一步

要计算严格时间加权收益率，还需要在每个外部现金流时点取得流入前或流出后的可靠组合估值，并接入可信价格与汇率来源。后续还应增加券商原始格式适配、冲正语义、基准指数和费用口径。在这些前提可验证之前，产品只展示变化归因与明确标注的 Modified Dietz 近似值。
