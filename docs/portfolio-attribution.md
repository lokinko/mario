# 组合变化归因

## 为什么先记录变化，而不是先展示收益率

组合市值上涨可能来自投资标的升值，也可能只是用户追加了资金；市值下降也可能来自主动取款。若不把外部现金流分开，产品会把储蓄行为误当成投资能力，或者把取款误判为亏损。

知衡因此先建立不可变的周期检查点。每次检查点冻结当时的持仓、资产类别、市值和目标权重，并要求用户显式填写自上一个检查点以来的净外部现金流：

- 入金为正数；
- 出金为负数；
- 没有外部现金流时填写 0；
- 非零现金流必须留下说明，便于未来核对。

第一个检查点是基线，没有前一期可比较，因此外部现金流必须为 0。

## 当前计算

对相邻两个检查点：

```text
组合总变化 = 本期总市值 - 上期总市值
估值/数据残差 = 组合总变化 - 本期净外部现金流
```

系统还按资产类别聚合两个检查点的市值和组合占比，展示市值变化与占比百分点变化。历史检查点不会随当前持仓编辑而改变。

“估值/数据残差”是有意保守的名字。当前数据不足以将其解释为投资回报或精确业绩归因，因为它可能混合：

- 资产价格和已实现交易影响；
- 分红、利息、费用和税费；
- 汇率变化与多币种直接相加；
- 不同资产的估值日期错位；
- 期中入金、出金的具体时点；
- 漏填持仓、重复录入和其他数据错误。

因此该指标适合触发问题，例如“变化是否主要来自新增现金”“哪类资产占比漂移最大”“是否需要核对录入”，不适合做收益排名、能力证明或投资承诺。

## AI 与云端边界

最近最多 12 个检查点是发送前预览中的独立数据组，用户可以在每次 AI 分析时关闭。模型固定策略禁止把残差称为收益率，并必须说明数据限制。

组合检查点属于端到端加密云同步白名单。同步结构 v2 开始包含该集合；v1 包仍可恢复，但没有历史组合检查点。模型 API Key、账户令牌、恢复密钥和设备本地设置仍不进入同步包。

## 下一步

要计算可比较的时间加权或资金加权收益率，需要先补齐统一基准币种、可靠行情与汇率、估值时间、交易和现金流时间点、费用税费及分红处理。在这些前提可验证之前，产品保持当前的变化归因口径。
