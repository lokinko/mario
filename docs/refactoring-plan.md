# mario 重构与产品收敛

目标：让用户少理解工具配置、多理解自己的判断；代码围绕明确领域和状态流组织，而非继续堆积页面。

## 不变边界

- 保留既有投资域数据及同步兼容，不删除用户历史。
- 决策原始快照、周期复盘、流水和规则版本的历史边界保持不变。
- 本地优先；账户和 AI 可选；确定性计算不依赖模型。
- AI 发送预览、逐组授权、证据来源和加密同步边界不能因简化界面而隐藏。
- 不引入微服务或无职责的通用抽象；文件长度不是质量指标。

## 已实现

### 1. 可靠性与交互测试

- 账户初始化失败可重试，忽略过期请求；核心快照与可选模型配置独立加载。
- 同步恢复使用应用级数据刷新，不重载窗口，清除旧跨页草稿引用。
- 统一请求总时限和取消；仅对读取的网络失败重试，写入不重放。
- 决策规则未加载成功时禁止冻结，重试不覆盖草稿。
- 研究历史、发送预览和分析结果防止陈旧请求覆盖当前选择；服务端已接受的写入不宣称被撤销。
- 财务保存失败保留输入并显示错误；流水、证据、记忆和复盘读取失败有可见状态及重试。
- 20 项前端测试覆盖上述关键状态、无账户/模型的人工决策和复盘、首页行动排序、校准样本口径与未填收益的显示。

### 2. 按领域分离

- 应用壳只负责启动、导航与跨页面交接；全部页面按领域放入 features，共享导航、格式、日期、小组件及请求生命周期工具独立。
- 数据库建表与迁移、领域读写、同步格式与兼容、导入校验、业务校验和快照计算分离。
- 保留 Database 对外接口、SQL 执行顺序、事务与同步版本。原有数据库测试单独维护。
- 添加源代码格式检查，使用显式依赖导入，不以压缩源码隐藏复杂性。

### 3. 产品主线收敛

- 三个主入口：“现在、决策、复盘”；辅助能力保留在“资料与工具”，旧 hash 入口兼容。
- 首页按目标、估值口径、高风险与到期复盘给出下一步；未知待办明确显示未知，无待办允许不行动。
- 移除持仓数量和模型密钥加分的准备度分数，改为资料状态。
- 概率判断展示明确成立/失效样本的均方误差和有效样本数，不将少量自评样本包装成能力分。
- 研究提供检查风险、寻找反证、准备复盘任务入口，技术选项收进高级设置；数据授权和发送前确认仍可见。
- 已配置账户的提供商参数收进高级设置；未配置时保留完整设置指引。
