# mario 重构与产品收敛

目标：让用户少理解工具配置、多理解自己的判断；让代码围绕明确领域和状态流组织，而非继续堆积页面。

## 不变边界

- 保留所有既有投资域数据及同步兼容，不删除用户历史。
- 决策原始快照、复盘和规则修订历史不可变。
- 本地优先；账户和 AI 可选；确定性计算不依赖模型。
- AI 发送预览、逐组授权、证据来源和加密同步边界不能因简化界面而隐藏。
- 不为重构引入微服务，也不为了缩短文件创建无职责的通用抽象。

## 实施与验收

### 1. 可靠性与交互测试（进行中）

已实现：账户初始化错误与重试、过期初始化结果忽略；本地启动与可选模型配置解耦；同步恢复通过回调更新应用数据；请求总时限、取消和只重试读取；决策种子不再因规则响应变化重新覆盖编辑。

本轮验收通过：11 项前端测试覆盖失败→重试、模型不可用仍可访问应用、恢复后重新取数、拉取前显式确认、迟到规则响应保留草稿编辑、不依赖账户或模型保存人工决策；请求覆盖超时、取消、读取重试及写入不重试。完整 `npm test` 通过：另有 4 项认证页面测试、92 项服务端测试、2 项桌面测试及本地鉴权冒烟。依赖审计为 0 个已知漏洞。上述组件测试使用模拟 API，不代替最终实机和真实同步回归。

### 2. 按领域分离（进行中）

已提取账户与决策日志页面、公共页面标题/数字输入、日期函数和请求传输层；`App.tsx` 从 2,177 行降至约 1,665 行（包含未使用导入清理）。后续分离财务底座、流水、复盘、研究与模型设置。统一业务数据更新和请求生命周期，避免页面跳转后的陈旧结果。

第二轮已将剩余页面全部迁入 `features/`：首页、财务底座、流水、证据、研究室、报告、复盘、记忆和设置；共享导航、日期、显示口径及小组件有独立模块。应用壳只负责启动、导航和跨页交接。引入源代码格式检查，不以压缩行数衡量简洁性。新增可复用请求有效性保护，历史分析快速切换时只有最后一次结果可以展示，并验证迟到结果不会覆盖新选择。

后端按迁移、领域数据访问、同步序列化与兼容、业务校验逐步分离。先保留原事务和接口，再迁移规则；不要在代码搬迁中悄然改变数据含义。

数据库建表和兼容迁移已迁入 `server/src/db/schema.rs`，保留原 SQL 与执行顺序；92 项服务端测试通过。其余数据库职责拆分与各页面异步状态一致性仍待完成。

### 3. 产品主线收敛（进行中）

已移除以持仓数量和模型密钥加分的准备度分数，改为资料状态；首页优先设目标/检查复盘；已配置账户的提供商参数收进高级设置。

后续将导航围绕“现在、决策、复盘”组织，保留旧入口的可达性；研究、证据、流水和记忆作为辅助能力。补充有数据依据的下一步行动，明确无需行动也是有效结果。区分资料完整度、过程纪律与足够样本下的判断校准，不制造综合能力分。

第二轮已收敛为三个主导航，其余入口收入“资料与工具”，旧 hash 地址仍兼容。首页行动按目标、估值口径、高风险检查和到期复盘排序；到期状态未知时不能显示无待办，确认没有上述待办时不要求用户生成分析或交易。新增行动规则与分析竞态测试后，前端共 15 项测试通过。仍需整体验证移动/桌面布局及进一步改善校准指标和研究任务入口。

### 4. 最终验收（待完成）

- 全量 Rust/前端/认证页面测试、构建及静态检查。
- 不配置模型、不登录账户也能完成决策与复盘。
- 原有数据/同步协议兼容与核心用户流程回归。
- 桌面和移动端页面检查、客户端打包。
- 更新架构和发布记录，通过后提交并推送远端；不将阶段性修改描述成全部重构完成。
