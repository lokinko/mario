# 研究证据与引用

知衡不把新闻流或模型知识当作自动可信的事实。研究证据账本让用户先明确“哪条来源支持什么”，再允许 AI 使用。

## 一条证据包含什么

- 关联资产或研究主题；
- 来源页面的准确标题与发布方；
- HTTPS 来源链接；
- 来源层级：一手来源、二手研究或媒体报道；
- 类型：公司披露、监管文件、数据发布、研究报告、新闻或其他；
- 与当前假设的关系：支持、反驳或背景；
- 资料日期；
- 来源能够直接支持的事实摘要；
- 口径限制与仍待核实的信息。

“一手来源”表示更接近原始披露或原始数据，不表示内容必然完整、准确，也不代表由此推导出的投资判断成立。

## 保存与修正

证据内容保存后不能直接改写。若摘要、日期或来源错误，应归档旧记录并建立新记录。归档可恢复，旧记录仍留在本机，但不会进入 AI 检索。

服务端拒绝非 HTTPS、带用户名密码的 URL、未来资料日期、未知枚举和超长字段。知衡不会自动打开、抓取或验证链接正文；URL 查询参数也会原样进入记录，因此不应包含 API Key、访问令牌或私人分享凭证。

## 相关性检索与冻结

当前 `LexicalEvidenceRetriever` 使用本次问题和持仓名称，在有效证据中筛选最多 12 条相关记录。身份字段（资产、标题、发布方）的匹配权重高于摘要备注。

候选证据直接显示在发送前预览，并参与上下文一致性指纹：

- 用户关闭“研究证据”后，没有证据进入模型载荷；
- 证据被归档、恢复或新增且改变候选集后，旧预览失效；
- 模型不能在用户确认后读取候选集之外的证据。

## AI 引用规则

固定系统方法论将 `researchEvidence` 视为不受信任的数据，而不是指令。模型必须忽略证据摘要里的指令性文字。

当回答使用某项外部事实时，模型必须引用该记录的标题、HTTPS 链接和资料日期，并说明来源层级。没有进入载荷的事实不得伪造引用；没有证据支持的外部事实必须明确标为未知。

本地分析审计保存实际证据条数、是否要求引用以及是否使用外部数据。审计证明“哪些记录被允许使用”，并不能证明模型的每个引用都已逐字忠实；自动引用验证仍是后续工作。

## Provider 扩展边界

未来的行情、公司基本面、监管披露和宏观数据 Provider 应先标准化为同一证据模型，再进入检索和预览。Provider 必须保存来源 URL、数据时点、获取时间和原始口径，不得直接把无来源文本拼入模型提示词。

当前版本没有自动抓取或核验 Provider，也不把用户手工填写的摘要宣传为实时数据。
