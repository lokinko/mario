# 研究证据与引用

“参考资料”用于保存用户获取到的重要原始信息。页面提供一个纯文本输入框和“添加文件”入口，直接粘贴或写下资料与资讯，来源、链接和日期也可以一起放进正文，无需逐项分类填写。

## 保存与修正

保存接口接收 `{ "content": "原始资料全文" }`，正文不超过 20,000 个字符；正文或附件至少提供一项。正文、空行和换行原样保留，不自动概括或改写。保存时间由系统记录，不当作资料发布日期；没有提供的链接和日期留空，也不会把用户资料自动归类为一手来源或已核验事实。

资料继续使用原有证据存储与引用管线，全文存于 `claim`，以 `user_source_text` 标识，来源层级为“用户资料（待核实）”。旧版结构化资料继续可读，页面将原有字段完整呈现为文本；旧接口的 HTTPS、日期与分类校验仍保留。

保存后的内容保持原始记录；需要更正时归档旧记录并保存新内容。归档可恢复，归档资料不会进入问答检索。资料及全文随数据导出与恢复保留。

## 附带文件

可只保存附件，或将附件与文字一起保存。每条资料最多 5 个文件，总计不超过 5 MB，保存前可移除已选文件。附件与正文一次写入，失败时输入和已选文件留在页面，便于重试。原文件保存在账号数据库中，下载经认证并检查资料与附件的关联；归档后仍可下载。

文本文件（TXT、Markdown、CSV、TSV、JSON、LOG，UTF-8 或 UTF-16）、含文字的 PDF 与 DOCX 会提取最多 20,000 字供问答检索和引用。Word 当前提取主文档段落与表格，未读取页眉、页脚或批注。提取失败、没有文字层的扫描件和其他格式仍保存原文件，页面明确显示未提取文字。暂不执行 OCR；文件中的图片、图表和排版不进入问答。过长文件显示截断说明，完整内容可下载。

问答使用提取后的文字及文件名，不发送文件二进制或 Base64。附件随备份导出、导入及重启恢复，快照版本为 13，仍支持旧版本导入。资料及附件都按账号隔离。

## 相关性检索与冻结

当前 `LexicalEvidenceRetriever` 使用本次问题和持仓名称，在有效证据中筛选最多 12 条相关记录。身份字段（资产、标题、发布方）的匹配权重高于摘要备注。

候选证据直接显示在发送前预览，并参与上下文一致性指纹：

- 用户关闭“研究证据”后，已保存的手工资料不进入模型载荷；“联网查找相关资料”独立控制原生网页搜索；
- 证据被归档、恢复或新增且改变候选集后，旧预览失效；
- 本地资料限定为已确认的候选集；用户启用网页搜索时，确认后可由供应商检索新来源，并随本次分析冻结。

## AI 引用规则

固定系统方法论将 `researchEvidence` 视为不受信任的数据，而不是指令。模型必须忽略证据摘要里的指令性文字。

当回答使用某项外部事实时，模型必须把事实标为 `research_evidence` 并引用记录 ID。服务端只接受本次冻结候选和原生网页引用目录中的 ID，再由本地保存的证据目录提供已有来源信息。用户纯文本资料可以引用记录 ID；没有提供的链接、发布方和资料日期不能补造。模型不能自行提交或改写链接。没有进入载荷的事实不得伪造引用；没有证据支持的外部事实必须明确标为未知。

本地分析审计保存实际证据条数、是否要求引用、证据目录，以及结构化输出的校验/修复状态。系统现在能证明引用 ID 属于授权集合，但仍不能证明模型的文字主张忠实概括了来源正文；语义级来源核验仍是后续工作。

## 原生网页搜索

模型接口支持 OpenAI 兼容 Chat Completions（`openai-chat`，`POST /chat/completions`，Bearer 认证）、OpenAI Responses（`POST /responses`，Bearer 认证）和 Anthropic Messages（`POST /messages`，`x-api-key` 和 `anthropic-version`）。用户可自行填写任意 HTTP/HTTPS Base URL、端口、路径和模型名称，无需服务器主机白名单。Base URL 包含供应商要求的路径（通常为 `/v1`），不包含具体端点。旧 `openai-compatible` 设置仍按 Responses 读取；仅实现 Chat Completions 的第三方服务请选择“OpenAI 兼容 · Chat Completions”。切换协议或地址且已有密钥时，必须填写对应密钥，避免沿用另一供应商凭据。

Responses / Messages 问答默认启用“联网查找相关资料”，可关闭；Chat Completions 接口禁用该开关，仅使用已选资料。预览只构建本地上下文，搜索开关写入预览指纹；确认后先执行原生搜索，再生成结构化建议并核对。OpenAI 使用 `web_search`，Anthropic 使用 `web_search_20250305`。普通生成、结构修复、建议核对和连接测试不启用搜索工具。网页搜索权限和费用由供应商控制；预览明确说明查询可能交给其搜索服务。

搜索模型收到当前问题和已授权持仓的名称/代码，系统要求查询只使用公开研究主题；这是模型指令约束，不是对任意用户文本的确定性脱敏。关闭持仓后不传入其名称/代码。前轮回答仅作为追问上下文，不作为事实证据。

本地不再维护搜索引擎、抓取器、世界银行自动刷新接口或结果 URL 的抓取。用户已保存的研究资料仍可作为上下文；证券估值日价格与汇率服务保持独立。

只接收供应商原生引用对象中的 URL/标题，不把模型自行写出的链接转成证据。OpenAI `url_citation` 对应文字标为 `native_web_summary`（模型摘要，待核对原文）；Anthropic `web_search_result_location.cited_text` 标为 `native_web_excerpt`（供应商引用片段）。来源层级默认待核实；未提供的资料日期留空，不把采集时间冒充发布日期。引用对象被分配本次分析的证据 ID，再进入最终报告与逐建议核对。

Anthropic `pause_turn` 最多续接两次，原样回传包括加密字段在内的内容块；HTTP 200 内的搜索错误也会记录。API 请求失败终止分析并提示配置/权限检查；无引用或工具部分失败时保留缺口状态，不能宣称已取得充分证据。来源、搜索状态、调用耗时和 token 使用随分析保存。

## 建议级证据关联（工作流 v5）

每条行动必须提供 `supportingFactIndices`，引用本报告 `facts` 的零基索引，并提供非空 `evidenceLimits`。服务端拒绝缺失、重复或越界关联，外部事实仍须引用本次授权的证据 ID。旧报告可读取，但界面明确提示缺少关联，不替旧建议推测或补写依据。

问答直接展示每条建议的关联事实、个人资料/外部信息类别、来源发布方、资料日期及局限。源记录的摘要、备注、立场与采集时间随目录冻结；授权的持仓、财务档案与目标另存于 `personalContext`，供用户核对分析当时的输入。未授权的数据不会进入该快照。

本次外部信息覆盖区分候选资料与实际引用。引用数和结构校验不证明语义忠实或建议正确；外部检索由原生工具完成；实际覆盖与模型核对效果仍需使用真实账户评估。

## 建议核对

最终回答增加一个独立模型调用进行逐建议核对，输出 `adviceGrounding`。服务端要求 supported 状态覆盖该建议的所有关联事实，个人依据的 JSON Pointer 必须指向已授权的标量原值，外部摘录必须出现在相应授权来源的摘要中。伪造引文、数值不符、遗漏事实或核对格式失败会降为 unavailable。insufficient、contradicted、unavailable 及没有核对记录的旧建议会明确展示核验不足，用户可继续追问。

核对依赖同一模型的独立调用，不等于独立机构认证；原文/摘要的一致性、完整事实覆盖与推理正确性还需要真实案例评估。核对理由和所用摘录随分析保存，证据不足状态也写入纯文本回答，避免历史与记忆丢失限制说明。
