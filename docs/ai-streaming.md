# 问答流式回复

问答页面通过带认证和 `If-Match` 的 `POST /api/analysis/stream` 接收 SSE。请求仍需携带 `/api/analysis/preview` 返回的 `previewRevision`。原有 JSON 接口 `/api/analysis` 保留，供非流式调用使用。

事件的 `data` 是 JSON，`type` 分为：

- `status`：`message` 表示当前研究或核对阶段。
- `draft`：`answer` 是当前草稿全文，每次替换上一份草稿。结构化 JSON 中的正文在生成过程中转为可读文字，引用路径等内部字段不会混入正文。修复结构化输出时草稿会重新生成。
- `complete`：`result` 是通过原有结构、来源和建议核对流程，并已保存到历史记录的 `AnalysisResult`。页面用它替换草稿，供后续追问使用。
- `error`：`message` 是失败说明。草稿不是已完成报告，不写入历史记录，也不作为后续追问的已完成上下文。

快速问答流式生成报告；深度问答先发送阶段状态，在最终综合报告生成时流式显示正文。网页搜索、方案研究和建议核对继续使用原有调用流程。支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和本地 Codex App Server；Codex 凭证仍由 Codex 管理。

独立 AI Agent 提供 `/execute/stream`，后端转发 `status` 和 `draft`，收到完整结果后由后端保存，再向页面发出 `complete`。前后端和 Agent 都要求明确的结束事件，连接关闭不能当作成功。流式请求不会自动重试。

SSE 定期发送心跳，响应包含 `X-Accel-Buffering: no`，避免 Nginx 默认缓存。部署时必须同时更新后端、Agent 和 Web 静态资源；自定义代理也应允许 SSE 即时转发。

发送后，按钮变为“停止生成”，准备资料和流式生成期间均可点击。停止会取消流式请求、立即恢复输入，保留已收到的草稿和原问题，显示“已停止生成”；停止后的迟到事件或结果不会更新页面，也不会干扰下一次发送。准备阶段停止后不再发起模型请求，中止的草稿不作为后续追问的完整回答。

页面关闭或卸载也会取消正在读取的回复；服务端执行由响应正文持有，连接取消时释放执行任务和并发名额。失败或超时保留草稿和问题，可先查历史记录再重试。账号切换后，旧账号的后续事件和结果不会发布到当前页面。模型阶段或本地数据校验之前仍可能需要等待。
