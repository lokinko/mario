# 线上网页使用个人电脑的 Codex

调用链：线上 Mario 问答 → 已配对账号的临时请求通道 → 个人电脑上的桥接进程 → 本机 Codex App Server。电脑主动通过 HTTPS 长轮询接收任务，不开启本机 HTTP 端口，不需要穿透 NAT。凭据由本机 Codex 保管和刷新，不读取或上传 `auth.json`。

## 部署和使用

1. 将包含此功能的源码更新到服务器，在项目目录执行 `sudo bash deploy.sh`。脚本构建前后端并验证 `api/server` 的 `codexBridge: 1`；不需要给服务器安装 Codex。
2. 执行 `bash deploy.sh check` 验证公网入口、网页资源及桥接鉴权。现有 `/mario/` 反向代理覆盖新增接口，不需要 WebSocket 配置或额外公网端口。
3. 在个人电脑准备同版 Mario 源码、Node.js、Rust，以及已通过 ChatGPT 登录的 Codex。运行 `codex login` 可建立 CLI 登录；仅浏览器登录 ChatGPT 不等于 CLI 已登录。
4. 登录线上 Mario，在设置的模型接口选择 **Codex 本机桥接（线上网页）**，点击 **生成配对码**。
5. 在个人电脑的 Mario 项目目录运行 `npm run codex:bridge`。默认地址为 `https://www.madeagents.ai/mario/`；其他入口使用 `npm run codex:bridge -- https://your-host/mario/`。
6. 等待检查 Codex 完成，粘贴网页配对码并回车。配对码通过标准输入传入，不作为命令行参数或环境变量保存。保持窗口运行，网页显示在线后点击 **启用本机 Codex**，然后 **测试已保存连接**。
7. 正常使用问答和流式回复。关闭电脑或桥接进程后问答会提示不可用。**撤销配对**会中止当前调用并阻止该进程接收后续任务。

如果 CLI 安装在自定义位置，可设置 `MARIO_CODEX_BIN` 为原生 `codex.exe` / `codex` 的绝对路径。桥接不执行 `.cmd` 或 shell 命令来传递提示词。Codex 模型默认由本机 `model/list` 检测；成功的连接测试才确认该模型能实际推理。

## 切换模型

在设置中选择 **Codex 本机桥接（线上网页）**，待本机在线后，在 **模型名称** 下拉框选择模型并点击 **保存配置**。后续问答和连接测试使用所选模型；正在执行的请求继续使用启动时的模型。列表显示 Codex 返回的模型名称、说明和默认标记，具体可调用范围取决于本机 Codex 和账号权限，不能保证与 ChatGPT 网页的模型菜单一致。

桥接启动时读取模型列表并上传非敏感的模型元数据。更新本机 Codex 或更换登录后，重新配对并重启 `npm run codex:bridge` 可更新列表；网页每 3 秒刷新连接和列表状态。断线不会清除已保存的模型，再次启用桥接也会保留仍在列表中的选择。旧版本机桥接只提供默认模型，请同步更新本机源码。直接连接本地 Mario 后端的 **Codex 本机登录** 也支持下拉选择及重新读取列表。

## 边界与生命周期

- 配对码是随机 256 位的 Mario 通道凭证，不是 ChatGPT 登录令牌；请只粘贴进自己电脑的桥接进程。网页仅临时显示，服务端通道只保存摘要。普通账号请求不能指定其他账号的桥接 ID。
- 配对等待 10 分钟后过期；已连接的配对最长有效 12 小时。重新配对、撤销、服务重启都会使旧通道失效；重启本机进程也需重新配对。网络短断可以由同一进程重连，已经开始的推理不会自动重放。
- 初版面向个人自用、单 API 进程部署，通道保存在进程内存中。多副本负载均衡需要后续共享通道或固定路由支持，不能直接扩容使用。
- 每个配对同时执行一个模型请求；另一个请求得到忙碌提示。正常执行仍经过 Mario 原有上下文预览、结构化校验和结果保存流程，只有完整成功的回答入库。
- 本机每 500ms 发送结果片段或心跳。浏览器停止生成后，服务端取消请求，本机下一次结果提交会发现取消并释放 Codex 子进程；网络不可用时最多等待当前 HTTP 请求的 25 秒期限。配对撤销也会终止正在执行的请求。
- 本机进程仅接收模型、文本消息和是否联网搜索，不接收任意命令、工作目录或工具配置。沿用只读临时会话，关闭文件、终端、MCP、应用和子代理工具。
- 这是用户个人电脑的执行桥接；不是在托管服务器上共享个人 Codex 登录。公开或商业化服务还需按 OpenAI 当前允许的集成方式和适用范围另行评估。

## 验证

`cargo test --manifest-path server/Cargo.toml bridge` 检查隔离、流式结果、取消、撤销、过期和安全 URL。`npm run test:codex-bridge` 使用一次性本地数据库和模拟本机工作进程验证 HTTP 全链路；加 `-- --live` 会启动真实本机 Codex、消耗本机账号额度并验证连接及流式问答。

如需验证多账号托管模式，设置 `MARIO_TEST_DATABASE_URL` 指向一次性 PostgreSQL 数据库，然后运行 `npm run test:codex-bridge -- --hosted`。不要使用生产数据库。此测试会创建临时账号，检查账号隔离、独立 Agent 绕过、SSE 保存、浏览器取消和重启失效；这些账号留在测试数据库中，测试结束后可删除整个一次性数据库。

本地全链路验证不能替代公网 Nginx、线上 PostgreSQL 和真实账号部署验收。
