# 可审计的 AI 分析档案

mario 把成功完成的 AI 分析保存为本地研究档案，不把它们当作聊天流，也不因为时间过去就自动改写。档案的用途是回答三个问题：当时问了什么、模型实际使用了什么、用户后来基于它做了什么。

## 保存内容

每条分析冻结：

- 用户当时的问题、生成时间和确定性渲染后的最终回答；
- Provider、模型、上下文分组、记忆与证据数量、调用耗时和可用的 token usage；
- 工作流版本、研究计划、实际采用的长期记忆、独立候选方案、风险审查与调用轨迹；
- 通过校验的结构化报告、当时允许引用的证据目录和输出修复记录。

模型 API Key、云端登录令牌和恢复密钥从不进入分析档案。

## 浏览与重新使用

`GET /api/analyses` 返回最近 50 条索引，用于客户端历史列表；`GET /api/analyses/{id}` 按不可变 ID 读取完整记录。单条读取不受“最近 50 条”限制，因此很久以前的决策仍能回到它引用的原分析。

问答页的“历史对话”只展示问题和时间，打开后与新回答共用完整 report 展示，不显示工作流轨迹、审计面板或决策草稿操作。后台仍保留完整档案，可通过上述 API 读取。

客户端允许：

- 重开结构化报告及其来源链接；
- 在历史 report 后继续追问，附上旧问题与回答摘要，并按设置中的预设使用当前资料；
- 选择“新对话”清空当前对话上下文；
- 从决策日志中的来源标签直接打开对应分析。

旧 report 保留当时的内容。继续追问会重新构建和冻结当前资料指纹，不复用旧载荷。资料范围、记忆与联网选项在“设置 → 问答预设”一次配置，提问时自动执行准备与指纹检查。

## 认识论边界

历史分析始终标记为“未经结果验证”。它记录模型当时说了什么，不证明：

- 当时的事实摘要正确或完整；
- 推断在逻辑上成立；
- 今天的财务状态、持仓和外部环境没有变化；
- 相关行动适合当前用户；
- 未来收益有任何保证。

只有带来源研究证据可以支持外部事实；只有用户确认后冻结的决策才代表用户当时真正采用的判断；只有未来复盘能为该判断增加结果证据。
