# AI 问答工作流契约

## 目标与执行路径

问答服务于红利投资的观察讨论、结合真实交易的判断与复盘。它要区分市场观察条件、分红与经营证据、个人现金和交易适用性，回答当前问题，并说明结论何时需要改变。产品范围见[产品目标](product-vision.md)，授权范围见[AI 数据边界](ai-data-boundary.md)。

唯一生产路径是 `council`（多代理评议，版本以[实现](../server/src/ai/workflow.rs)为准，当前 `investment-workflow-v17`）：API 按账号读取并冻结已授权资料与长期记忆 → 可选供应商原生网页搜索 → 研究代理整理研究简报 → 三个方案代理并行独立作答 → 方案代理交叉匿名评分 → Rust 确定性计票 → 原样采纳胜出方案 → 保存成功结果。每个结构化输出各自校验，失败时至多一次格式修复。评议细节见[多代理评议](#多代理评议)；长期记忆的选取、整理与边界见[长期记忆](ai-memory.md)。

请求体只接受当前字段：`workflow` 必须为 `council`；已退役的 `useMemory`、`informationSelection`、`alternatives`、`critique` 等选项不再被静默丢弃，而是以校验错误拒绝，避免调用方误以为它们仍然生效。

API 的准备与执行共用 `AnalysisService::prepare`。准备返回实际载荷与指纹；执行重新构建并比较指纹，资料变化时在模型调用前拒绝。模型执行期间释放账号锁，完成后重新取锁保存报告；失败不保存分析。AI 只消费冻结输入，不读取账号数据库、不修改持仓和现金、不执行交易。

## 对话上下文

`question` 只保存本轮用户问题。`previousTurn` 分开携带上一轮用户问题、模型结论与建议，原有摘要总计最多 800 个 Unicode 字符：客户端分别取问题 200、结论 300、最多三条建议各 100。

`earlierQuestions` 只保留用户原始问题，最多五条、每条最多 300 个 Unicode 字符，按时间顺序保留首轮与最近四条，去重且排除上一轮问题。打开历史报告后，从冻结的用户问题恢复已有线索；不从模型回答推测历史用户表达。`pendingQuestion` 只取上一轮当前结构化报告的追问，最多 200 字，帮助理解“三年”等简短回答。旧报告没有该字段时不从正文猜测。

用户对本次讨论的最新明确更正优先于旧的对话条件和档案中的一般默认条件，但对话不自动改写档案或账本；某笔资金的用途更正也不扩大为全部资产的新期限。历史用户原话可按允许路径回查，引用抽屉标为“用户声明（未改写档案）”。上一轮模型结论、建议与追问仅作交流线索，不能作为事实引用。任一资料组关闭时，服务端从实际载荷移除这三个模型生成字段，避免先前授权的个人信息经摘要重新进入模型；保留用户主动输入的问题。新对话和从其他页面接受的新公司问题清空旧对话。失败或中止的草稿不进入后续上下文。预览与发送使用同一构建工具，发送前仍重新读取账号预设并冻结。

## 公司检索与红利研究能力组合

领域层的[讨论上下文](../server/src/context/discussion.rs)只消费本轮问题、有限用户历史问题、授权候选资料与事实卡。公司选择先看本轮明确对象；本轮没有明确公司时，按用户历史从近到远承接，不从上一轮模型结论提取公司。本轮切换公司后不继续混入旧公司资料。主题公司优先于其他持仓背景参与本地资料检索。

`discussionGuide` 与其他输入一起进入预览、指纹和审计。其 `publicResearch` 只包含筛选后的合法证券代码和固定研究主题；个人金额、账户、现金、身份、原问题及历史回答不复制到搜索请求。可解析的公开公司来自生产观察证据，或问题明确匹配且已授权的持仓等规范身份；不把自由资料字段视为已核实证券身份，自由填写的名称只用于本地匹配，不进入搜索载荷。无公司身份时只使用与本题相关的固定公开主题。

红利讨论组合以下相关核查能力，不要求每题填满所有项目：

- 分清已实施 TTM、年度分红、普通与特别分红、未来方案与个人到账；缺少原披露时不猜分红性质，不用 TTM 承诺未来年化收益。
- 依据行业核查利润、经营现金流、资本开支、债务或监管资本约束，以及长期需求和反方证据；银行等行业不机械套用同一现金流指标。
- 分清当前市场股息率、持仓成本口径、税费与总回报；参考价格保留日期和复权口径。
- 结合本次授权的精确当前股数、现金、真实成交讨论个人适用性，缺少资料时说明本题的核查项或等待条件，不从技术信号生成股数或仓位规则。

红利组合只在本轮问题或承接主题出现“股息、分红、红利、派息、买点、BOLL”，或讨论对象是已保存观察的公司时启用；“长期持有”“稳定”等泛化表述本身不触发。普通理财问题使用对应的通用核查主题，不强制转为红利模板。联网关闭时仍可依据本地资料使用核查指引，但不能声称已核实外部资料。固定指引是分析方法，不是可引用事实或完成核查的证明；研究代理对每项核查给出明确状态，缺资料就标为 `missing_source`。

### 网页搜索的证据分级

联网搜索消费同一份公开研究主题包，结果按供应商实际返回的内容分为两级：

- 供应商返回的网页原文片段（如 Anthropic `cited_text`）成为本次分析的 `native_web_excerpt` 证据，分配证据 ID，可被事实引用。
- 供应商生成的带引用摘要（如 OpenAI `url_citation` 对应文字）只作为 `webSearch.leads` 待核实线索，以 `webLeads` 进入模型输入，不分配证据 ID，不能作为事实引用；“评议过程”中标为“供应商生成的摘要，不是网页原文，未作为回答依据”。

搜索状态为 `completed`、`incomplete`（未报告搜索调用或没有取得可引用原文）或 `failed`。搜索请求失败不终止整次分析：轨迹记录失败与警告，阶段写“网页检索失败，改用本地资料继续”，模型被告知外部信息未核实。

## 多代理评议

评议只为一个目的服务：在给用户一个答案之前，先让不同视角对同一份冻结资料独立作答并互相挑错，把最站得住的方案交给用户，同时如实展示其他代理的质疑。所有代理读取同一份冻结输入，任何代理都不读取账号数据库、不写入资产或交易。

| 步骤 | 执行者 | 产出与校验 | 失败处理 |
| --- | --- | --- | --- |
| 研究 | 研究代理（1 次调用） | `ResearchBrief`：`findings` 最多 10 条，引用规则与报告 `facts` 共用同一段提示（只引非空标量原值，缺失值改引问题码），校验错误会写明是未授权、不存在、指向对象还是空值，供唯一一次修复对照改正；`counterpoints`、`unknowns` 各最多 6 条、每条 300 字；`checks` 对 `discussionGuide.researchChecks` 每项恰好一条，状态为 `covered`、`not_applicable` 或 `missing_source` | 两次校验失败时记录失败原因，方案代理直接使用冻结资料继续；供应商错误（认证、额度、网络）终止本次分析 |
| 方案 | P1 稳健等待、P2 条件执行、P3 反方证伪（3 次并行调用） | 各自生成完整的当前报告契约，单独校验 | 每个方案独立修复一次；仍失败的方案退出评议并留下失败原因；三个都失败才终止 |
| 投票 | 每个通过校验的方案代理（并行） | 只看到其他方案的 ID 与内容，不看到视角标签；对每个方案按事实、引用、推理、反方、可执行性五维各打 0–2 分（2 分表示该维度找不到可指出的缺陷，质疑所指维度不给 2 分），必须写一条具体质疑，严重缺陷可附理由否决；另须在展示方案中选出一个愿原样采纳的 `preferred`，不能选自己否决的方案，只有全部否决时为 null | 选票校验失败只作废该票；没有有效票时按方案顺序采纳 |
| 计票 | `models::council::tally`（确定性） | 获否决票达到评审人数一半即淘汰；排序依次为未淘汰、已获评审、首选票多、平均分高、否决少、修复少、方案顺序 | 结果状态为 `voted`、`tied`、`contested`、`single` 或 `unvoted`；胜出方案与次名在首选票、平均分和否决数上都相同时为 `tied`，阶段与“评议过程”写明按方案顺序采纳，不呈现为评审偏好 |
| 采纳 | 编排器 | 胜出方案的结构化报告原样成为最终报告，`answer` 由该报告渲染 | 不另做合成或改写 |

否决只用于：编造或错引事实与来源、结论与自身事实矛盾、迎合用户倾向而回避相反证据、越过账本自行生成交易或仓位规则。评分按证据与推理而非立场、语气或是否与自己方案一致；代理不为自己的方案投票。

三个视角是分工而非预设结论：稳健等待须说明继续等待的理由与代价，资料充分时直接给出行动结论；条件执行须给出可核实的触发条件、复核时点与放弃条件，不编造阈值；反方证伪先寻找能推翻用户倾向或常见结论的事实，反方不成立时明确说明。

`stages` 只记录实际执行的步骤及其数量，例如“研究代理：N 条可引用发现，N 条反方，N 项缺口”“方案代理：3 个方案中 N 个通过校验”“交叉投票：N 张有效票，采纳 P1（稳健等待）”；跳过的步骤不写入。轨迹 `research`、`proposals`、`vote` 保存研究简报、每个方案的报告或失败原因、每张选票与计票表，供报告下方“评议过程”回查。报告正文之后单列“其他方案代理的质疑”，展示其他代理对采纳方案的质疑与否决理由，不因采纳而隐藏反对意见。

一次完整评议最多 7 次生成调用（研究 1、方案 3、选票 3），另加各自至多一次修复，整体受 25 分钟执行上限约束。方案与选票默认并行；配对桥接一次只处理一个请求并拒绝重叠请求，执行端以 `accepts_concurrent_calls` 声明后，编排器按同一顺序逐个执行，结果与计票不变，耗时约为并行时的三倍，超过执行上限时按超时结束、不保存。模型调用失败（如执行端繁忙、网络错误）与格式校验失败在阶段中分开计数。评议增加了交叉核查与反方覆盖，但各代理可能共享同一模型的错误，计票通过不证明结论正确；语义质量仍按[实际回复质量验收](#实际回复质量验收)由主负责人亲审。

## 表述与不迎合

固定系统策略要求：用户的倾向、期待和记忆中的偏好只说明想讨论什么、希望怎样沟通，不是事实依据，也不改变证据分量；记忆中模型归纳的观点须按本轮资料重新检验，不能作为事实引用。证据不支持用户倾向时直接说明并给出理由，不为顺从弱化风险、拔高结论或回避反方，也不为显得独立而刻意反对。

表述按“结论—依据—推理—最强反方—会改变结论的条件”组织，让用户能逐步复核并被理由说服，而不是被安抚。投票的否决条件包含“迎合用户倾向而回避相反证据”，使这一要求成为计票约束。

## 证据投影与冻结

最多选择五条本地证据，优先当前讨论公司的已保存观察；普通资料用同一讨论检索线索选取最多 2000 字连续原文。完整原文、附件和模型片段共同冻结，目录与来源可回查。

生产观察证据使用 `watch_observation` 类型及明确结构标识，保存最新完整原值和本周真实记录。领域层专门投影最新规则、价格、股息口径、日周指标和本周记录，规则按结构去重，模型片段最多 4000 字；按完整事件或记录裁剪并显式保留总数及省略数量，不对 JSON 文本作任意截断。完整原始观察仍留在冻结目录，不能把已省略事件当作没有发生。历史记录按各自保存的规则解释，观察信号不证明低估或分红持续性。

## 结构化输出契约

当前生成只接受 `answer`、`suggestions`、`facts` 和可选 `question` 的报告：

| 字段 | 约束 |
| --- | --- |
| `answer` | 非空，最多 1200 字；先回答本轮问题，再说明关键事实、推理、判断和不确定性 |
| `suggestions` | 1–3 条；每条行动最多 240 字、理由最多 800 字、推翻条件最多 400 字 |
| `facts` | 1–8 条；每条事实正文最多 1000 字，基于本次授权的个人原值或研究来源 |
| `factIndices` | 每条建议非空、无重复、不越界，引用本报告事实 |
| `question` | 最多一个追问、200 字；没有则为 `null` |

个人事实的 `basis=user_data`，`sourceRefs` 非空且每条最多十二项，`evidenceIds` 为空。原值引用只能是本轮 `/question`、历史用户原话 `/previousTurn/question` 或 `/previousTurn/earlierQuestions/{从0开始的规范索引}`，以及本次授权事实卡中的非空标量；空字符串、`null`、对象和数组无效，合法的数值 `0` 与布尔 `false` 仍可引用。历史模型摘要和研究核查指引均不可作个人事实来源。

研究事实的 `basis=research_evidence`，只引用本次允许的证据 ID，`sourceRefs` 为空。引用路径校验保证存在、授权和可回查，不保证模型文字与来源在语义上一致。长期记忆、网页线索与历史模型摘要都不能作为事实来源。

每个结构化输出（研究简报、方案报告、选票）最多 30000 字，各自仅允许一次修复；修复接收原输出、校验错误与允许的证据 ID，不重发全部个人上下文。修复提示只允许改动校验错误涉及的字段，必须保留原输出的结论、立场、数字和引用，无法不改变含义地修复时删除该项。被替换的首次输出保存在 `outputValidation.rejectedOutput`，状态为 `repaired`；两次都失败时状态为 `failed` 并保留两次错误，审计时可对比修复是否改写了主张。

回答按本题需要展开，不强制每个建议带金额或比例。依赖可选目标或假设的行动，先明确条件再说明金额与动作；资料不足时给出本题可执行的核查、计算公式或等待条件，不能用无关财务安排凑建议。用户只问资料状态、口径或计算影响范围时，不另设储备目标或配款、交易计划。新仓位或减仓目标须解释所选幅度的依据、保留风险和流动性后果；只有“降低集中度”的方向性理由时，不能用任意比例锚定倾向性交易额，可给待确认目标的公式或非默认算例。行动句本身须包含影响执行额的口径条件，与理由和例外一致；月结余只另扣尚未包含的付款，不能靠理由补救行动句中的重复扣款。按目标权重给交易公式或金额时，行动句先说明卖款留在组合内或转出，以及费用假设；固定总值公式不能直接用于提款、消费或还债，须按转出后的组合总值和现金缺口统一重算。来源要求同样适用于正文、建议和追问，不能将无来源的具体法规、监管、保障限额、税率或交易单位等外部数字放在`facts`之外；可解释一般概念，缺少本轮依据时只说明要核对的适用条款，不从模型记忆确定报数。研究中的现金覆盖未披露或未核实，只能表述为覆盖未知或资料缺口；正文及理由也不能将其简称为公司已有现金流缺口、资金不足或依赖融资。只有本轮原文或明确情景下的可复核计算支持时，才说明相应不足，并区分实际、预算与假设；已证实的风险也不能淡化为仅缺资料。保留来源条件、可能性和概念提醒的语气，不能从“X不代表Y”断定公司已有X，须有本轮明确事实依据。财报或预算只给金额单位、未说明报告币种时，沿用原单位并说明币种未提供，不从中文单位、证券代码或用户本位币推定报告币种。

## 连接失败与重试边界

普通模型API只对明确的可重试HTTP拒绝和 `reqwest::Error::is_connect()` 判定的连接建立失败进行有界重试，共最多三次传输尝试、两次退避，同一45秒重试预算，进度可取消。请求发出后的响应超时、流中断或已输出内容不自动重放；认证、配额和结构化证书HTTP错误仍按原分类拒绝。连接尝试次数不等于已计费生成次数；持续DNS、代理或TLS故障仍可能使问答不可用，重试不保证恢复。

## 实际回复质量验收

影响提示词、对话承接、事实引用、证据或模型协议的更新，需要按相关固定场景真实生成、主负责人逐题审阅完整回复、定位缺陷、修改和复测。独立复核辅助查错，不能代替主负责人亲审，不能把另一次模型评分或格式通过当作质量通过。

逐题核对事实、引用忠实、推理、关键反方与未知、具体行动条件；每维0–2，2表示满足本题要求，通过须五维均为2，且第一句直接回答、每条建议均有用、无编造。关键算错、错误承接、无依据事实或来源、假前提命令、授权越界、摘要冒充原文、观察信号直接推出买量、公司TTM冒充个人到账，任何一项直接否决，平均分不能抵消。调用失败、依赖跳过或未亲审属于未完成。网络失败复测与语义失败复测分别记录，不覆盖失败报告或挑最好的一次充当完整通过。

固定题集、调用方式与人工记录见[问答评测](../server/tests/fixtures/qa_eval/README.md)；一次性实际结果及剩余边界写入审计，不把闭网虚构场景通过外推为真实市场研究正确或收益保证。

## 流式回复

问答页面通过带认证和 `If-Match` 的 `POST /api/analysis/stream` 接收 SSE，请求须携带 `/api/analysis/preview` 返回的 `previewRevision`；非流式调用使用 JSON 接口 `/api/analysis`。事件 `data` 为 JSON，`type` 分为：

- `status`：`message` 为服务端当前步骤，如“研究代理正在核对资料…”“三位方案代理正在独立作答…”“方案代理正在交叉评审…”。
- `draft`：`proposal` 为方案 ID，`answer` 为该方案草稿全文，每次替换同一方案的上一份草稿。三个方案并行生成，页面按方案分别显示，均标注“未校验”。研究简报与选票不产生草稿。
- `complete`：`result` 为通过校验并已保存的 `AnalysisResult`，页面用它替换全部草稿。
- `error`：`message` 为失败说明；草稿不写入历史，也不作为后续追问的上下文。

独立 Agent 的 `/execute/stream` 转发 `status` 与 `draft`，后端收到完整结果并保存后再发出 `complete`。前后端和 Agent 都要求明确的结束事件，连接关闭不能当作成功；浏览器与后端都不重发整次问答。SSE 每 15 秒发送心跳，响应带 `X-Accel-Buffering: no`。网页总期限 30 分钟、流空闲期限 60 秒；完整问答执行上限 25 分钟、Agent HTTP 上限 26 分钟、单次模型调用 180 秒。本机桥接重试分类见[本机桥接](codex-bridge.md#超时失败与重试)。

界面将状态映射为“准备资料 → 研究 → 方案 → 投票 → 完成”的步骤条，无法识别的状态保留原文；步骤条只是展示，仍只接受 `complete` 为成功。发送后可随时“停止生成”：取消请求、保留已收到的草稿与原问题，迟到事件不再更新页面。若上一轮回答后触发的记忆整理仍在进行，下一次发送先显示“正在整理长期记忆…”并等待其结束，避免两次写入竞争数据版本。

## 历史读取、验证与局限

新增的对话与轨迹字段有缺省值，旧报告仍可读取；不修改已完成报告。历史只读报告契约与当前生成契约分开，见[分析历史](analysis-history.md)。冻结轨迹记录实际工作流版本、输入、来源、各代理产出与校验结果，不记录模型隐藏推理。

行为回归覆盖多轮主题承接、切换公司、授权缩小、完整观察与紧凑投影、精确当前股数、搜索公开字段与证据分级、搜索失败降级、研究简报校验与降级、方案部分失败、选票作废、计票排序与否决淘汰、修复保留首次输出，以及只记录实际执行的阶段。完整工程门禁按[模块边界](module-boundaries.md)执行。真实模型质量评阅仍需显式配置和独立留证，不能把单元测试、计票通过或引用路径通过称为投资建议质量已获证明。
