# AI 分析工作流契约

知衡的 AI 分析不是一条不断膨胀的提示词，而是“工作流定义、执行器、模型 Provider、记忆检索与上下文构建”相互独立的本地服务模块。这样可以单独替换某个阶段，而不改变投资方法论、HTTP API 或密钥存储。

## 模块边界

```text
ContextBuilder ── 冻结最小数据载荷与候选记忆
      │
      ▼
AnalysisWorkflow ── 定义阶段职责、视角与提示契约
      │
      ▼
InvestmentOrchestrator ── 执行、检索、计时、汇总、审计
      │
      ▼
ModelProvider ── 适配用户选择的模型 API
```

- `ai/workflow.rs`：只定义阶段和提示契约。当前实现是 `InvestmentWorkflowV3`。
- `ai/orchestrator.rs`：只负责调用阶段、在冻结集合中二次检索记忆、汇总结果与生成轨迹。
- `ai/provider.rs`：定义统一模型响应，包括正文和可选 token 用量。
- `memory.rs`：定义可替换的结构化记忆检索接口；当前实现同时考虑概念、复盘状态、冲突与时间衰减。
- `context.rs`：负责用户可见的数据选择、发送前预览和一致性指纹。

编排器提供 `with_workflow` 注入点。未来可以新增事实核验、估值情景或规则冲突检查工作流，而无需让工作流读取数据库或 API Key。

## 深度工作流 v3

```text
确定性风险检查
   ↓
研究计划 ──→ 第二轮本地记忆检索
   ↓
┌─ 稳健基准方案：资本保护、保持不动、最小行动
└─ 目标推进方案：目标达成概率、风险预算、机会成本
   ↓
独立风险审查：证据漏洞、极端风险、过度自信、规则冲突
   ↓
最终综合裁决：取舍、可逆行动、未知项和证伪条件
```

两个候选方案分别调用模型。第二个方案不会读取第一个方案，避免“一个回答里假装列出多个选项”；只有独立风险审查与最终综合阶段能同时看到候选方案。关闭“多方案探索”时仍保留稳健基准方案，确保系统始终比较“保持不动”。关闭“纠错反思”时会跳过风险审查，并在最终阶段明确标记这一事实。

快速工作流仍为一次模型调用，适合低成本问题；它不会读取历史记忆，也不会伪装成完成了多方案或独立审查。

## 可审计工作产物

每次成功分析返回并在本地保存：

- 工作流版本；
- 研究计划；
- 最终实际采用的结构化记忆、命中原因与检索轮次；
- 每个独立候选方案的名称、视角和正文；
- 独立风险审查；
- 每次模型调用的阶段、耗时，以及 Provider 返回时的输入/输出 token；
- 最终综合答案与原有上下文审计。

这些内容是知衡显式要求模型输出的研究工作产物，不是模型隐藏的思维过程。客户端默认突出最终裁决，中间产物由用户主动展开检查。模型没有返回 usage 时显示“token 未返回”，系统不会估算或伪造成本。

SQLite 的 `analyses.trace` 保存完整工作流轨迹，`analyses.audit` 保存聚合审计。幂等迁移会为既有数据库增加可空字段；旧记录缺少轨迹或新增审计字段时仍可读取。

## 失败与安全语义

- 任一必需模型阶段失败时，本次分析整体失败，不把半成品当作最终建议保存。
- API Key 只由 Provider 写入 Authorization 请求头，不进入提示词、轨迹或审计。
- 候选方案、批判与最终裁决均继承固定投资方法论和证据引用约束。
- 本地上下文、历史记忆和上游模型产物统一视为不可信数据；只有当前用户问题与固定系统契约能定义任务，跨阶段文本不能改写角色或跳过护栏。
- 工作流只能访问发送前预览中已冻结的上下文和候选记忆。
- 被用户逐条排除的记忆不进入授权候选池；选择变化后必须重新预览并确认新指纹。
- 模型产物不会自动写入个人投资规则或执行交易；用户仍需独立确认并记录正式决定。

## 后续扩展

1. 为失败阶段增加可恢复的本地 checkpoint，而不是重新执行已完成调用。
2. 引入结构化输出校验，确保事实、推断、未知项和引用能被机器检查。
3. 为不同任务选择不同模型，例如低成本规划器与高可靠裁决器。
4. 增加真实费用估算，但必须基于用户确认的模型价格表与实际 usage。
5. 使用离线评测集比较工作流版本，避免只凭主观观感升级提示词。
