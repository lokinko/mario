# AI 分析工作流契约

mario 的 AI 分析由工作流契约、执行器、模型 Provider 与上下文构建分层实现。当前实现是 v9 的可选原生搜索、单次报告生成及至多一次格式修复；执行器可运行于 API、独立 Agent 或经账号配对的本机桥接。模型工作流只消费冻结输入，不读取账号数据库或写入资产。

## 模块边界

```text
ContextBuilder ── 冻结最小数据载荷与候选资料
      │
      ▼
AnalysisWorkflow ── 定义阶段职责、视角与提示契约
      │
      ▼
InvestmentOrchestrator ── 执行、计时、汇总、审计
      │
      ▼
ModelProvider ── 适配用户选择的模型 API
```

- `ai/workflow.rs`：只定义阶段和提示契约。当前实现为 `InvestmentWorkflowV9`，持久化版本号为 `investment-workflow-v9`。
- `ai/orchestrator.rs`：只负责调用阶段、汇总结果与生成轨迹。
- `ai/provider.rs`：定义统一模型响应，包括正文和可选 token 用量。
- `ai/structured_output.rs`：解析并校验最终分析，不允许模型自由改变字段、来源类型或引用边界。
- `context.rs` 与 `context/fact_sheet.rs`：负责授权数据选择、去重的精确事实卡、预览和一致性指纹。估值计算链只经 `valuationEvidence` 冻结并写入轨迹审计，不进入提示词。

编排器提供 `with_workflow` 注入点，供现有工作流替换和测试使用；该扩展点不代表计划增加模型阶段，工作流始终不能读取数据库或 API Key。

## 单次工作流 v9

默认关闭网页搜索。单次生成结构化报告，通过确定性引用与格式校验后保存；格式不合格只修复一次，再失败则整次拒绝。

用户启用网页搜索时，在生成前调用供应商原生搜索，最多保留5个来源、每个最多2000字连续相关原文，入选来源的完整返回内容留在轨迹目录。本地资料由应用层关键词检索取前 5 条，ContextBuilder 确定性截取每条最多 2000 字的连续相关原文。资料和搜索结果直接进入生成，不调用模型筛选；普通路径仅 1 次生成，格式修复时为 2 次，主动搜索另增加一次搜索调用。搜索状态和告警只保存在 `trace.webSearch` 并显示在折叠的依据区，不拼接回答前缀。

`researchPlan`、`alternatives`、`critique`、`adviceGrounding`、`informationSelection` 只为 v7 及更早历史记录保留读取契约，当前流程不生成这些阶段产物。历史报告及引用仍可打开，完整旧轨迹经详情 API 读取；问答页面不提供旧阶段的独立审计面板。存储的预设在读取时把工作流规范为 `quick`，新请求不接受退役的 `deep` 流程。

## 追问输入

当前问题只使用 question。previousTurn 是确定性截取的上一轮问题、结论和建议动作，总长度上限 800 字符；服务端在预览、执行及 Agent 入口校验，摘要变化会使冻结指纹失效。摘要是不可信会话线索，不能作为 sourceRefs 事实原值；历史报告仅通过只读适配取结论与动作。没有摘要模型阶段。

## 结构化输出契约

确定性检索和摘录不改写原始记录。`BuiltContext.evidenceCatalog` 冻结原文及附件，进入 `trace.evidenceCatalog` 供引用核对；payload 只携带至多 5 条原文片段，不重复发送附件正文。预览与模型消费同一片段；原文与片段共同纳入冻结指纹。

新分析只返回 `answer`、`suggestions`、`facts` 和可空的 `question`。结论先直接回答，再按问题需要说明关键事实如何支持判断、相关反方与证据局限；复杂问题可以比较不同路线的紧迫性、代价和适用条件，简单问题不要求扩写。行动必须紧扣本题，明确现在做什么或等待什么、何时重新判断；补齐具体缺口后再核对判断条件或计算，也可以是有用建议，不能为凑条数转去无关财务安排。

回答上限为 1200 字符；建议 1–3 条，每条 `action` 最多 240、`why` 最多 800、`unlessWhen` 最多 400 字符；事实 1–8 条，单条最多 1000 字符；可选追问最多一个、200 字符，完整 JSON 仍不超过 30000 字符。上限是防失控预算，不是最低字数目标。建议用非空且不重复的 `factIndices` 关联事实，理由说明事实、推导和取舍。只在问题确有需要且数据支持时给金额或比例，并使计算可复核；若依赖某个目标或假设，行动句先明确“若采用……”，再写相应金额或动作，不能只把假设藏在理由或例外中。建议目标和未提供的目的／偏好不当作用户已经确认的事实，不因缺资料编造幅度、买量或仓位上限。计算可安排资金时，已包含在结余中的支出或正常还款不能重复扣除，只另计尚未包含的额外付款。

问题要求结合交易且本轮已授权提供时，选择与判断相关的原始成交日期、账户、数量和原价引用并解释；只复述当前成本／市值不能代替交易分析，也不能由盈亏恢复当时的买入动机或完整业绩。原始数量／价格保留成交时单位，跨拆合股不得直接混比。公司 TTM 每股分红乘当前股数只可作明确标注的情景，不是用户历史到账；没有到账记录也不证明实际没有收到。已发生的经济损失不会因卖出才新增，持有与卖出的取舍按未来风险、费用税务及机会成本说明，不把避免实现账面亏损当独立持有理由。

服务端拒绝契约外字段、越界索引与未经授权的引用。默认显示回答、建议和可选追问，事实与来源折叠；纯文本摘要按同一顺序渲染。v8 的同形报告按原文保留读取，不重新生成；本次没有新增报告字段、财务写入或存储版本。

`models/analysis_history.rs` 独立读取历史报告结构，保留判断、事实、推断、未知项、方案、行动与复盘条件；历史结构不能作为新分析通过校验。历史列表 API 通过统一只读标题接口返回摘要，当前页面列表显示问题与时间，无需改写数据库或备份格式。长期记忆已退役，升级或导入会清理专属元数据，但保留历史问题、回答和引用；不把旧回答重新注入新分析。

每条事实必须声明 `basis`：

- `user_data` 表示来自用户本次授权的本地数据，不允许附带研究证据 ID；每条事实的 `sourceRefs` 必须非空且最多 12 项，不同账户或成交按事实组织、只选择必要原值，指向 `/facts/summary`、`/facts/holdings/<id>`、`/facts/dataIssues` 或 `/facts/options` 中实际使用的原值（本轮用户陈述可引用 `/question`），服务端校验所属资料组和非空标量是否存在，客户端从冻结档案显示原值；
- `research_evidence` 表示使用研究证据，必须引用本次冻结候选中的 ID；
- 引用最终入选集合之外、重复或空缺的证据 ID 都会失败。

上述门禁校验引用路径存在及授权，不证明事实文字与数值在语义上完全一致。引用原值须为非空标量：拒绝 `null`、对象、数组及空白字符串，数值 `0` 和布尔 `false` 仍是合法原值。建议质量和数值错配仍须在评测中逐题核对。引用约束作用于新生成结果，已保存报告按原文读取。

首次失败时，编排器只把原输出（最多覆盖完整 JSON 的 30000 字符预算）、校验错误、允许的证据 ID 和固定契约交给格式修复模块；修复的系统消息仅要求“只修复格式，不添加新事实”，不重复注入方法论或整套系统规则。第二次仍不合格时返回模型错误，不保存分析。兼容仅会自动包裹 JSON 代码块的模型，但不会接受 JSON 前后的解释性文字。

## 可审计工作产物

每次成功分析返回并在所属账号保存：

- 工作流版本；
- 每次模型调用的阶段、耗时，以及 Provider 返回时的输入/输出 token；
- 通过校验的最终结构、证据目录、校验状态和修复错误；
- 由结构化结果确定性渲染的答案与上下文审计。

这些内容是 mario 显式记录的工作产物，不是模型隐藏的思维过程。客户端默认突出回答与建议，可展开事实和来源；完整审计与调用轨迹通过详情 API 读取。模型没有返回 usage 时相应字段保持未知，系统不会估算 token 或伪造成本，也不声称当前问答页提供独立费用面板。

账号 PostgreSQL schema 内的 `analyses.trace` 保存完整工作流轨迹，`analyses.audit` 保存聚合审计；两者可为空，缺少时记录仍可读取。

问答页可按不可变 ID 重新打开历史报告和引用；完整轨迹由历史详情 API 提供。继续提问使用当前资料重新准备并冻结上下文，页面可主动查看预览，发送时不增加一次人工确认。详见 [可审计的 AI 分析档案](analysis-history.md)。

## 失败与安全语义

- 任一必需模型阶段失败时，本次分析整体失败，不把半成品当作最终建议保存。
- 最终输出必须通过机器契约；至多自动修复一次，失败后不会降级保存自由文本。
- API Key 只由 Provider 用于协议认证：OpenAI 使用 Bearer，Anthropic 使用 `x-api-key`；不进入提示词、轨迹或审计。
- 生成使用账号已保存并冻结的投资方法论，格式修复只修复原输出；用户从左侧“投资方法论”编辑全文，保存后下一轮生效。系统证据引用与输出约束独立保留。
- 本地上下文、网页及修复输入统一视为不可信数据；只有当前用户问题、已保存的投资方法论与固定系统契约能定义任务，资料文本不能改写角色或跳过护栏。
- 工作流只消费发送前冻结的上下文、本地候选资料，以及用户已授权搜索在本次执行中取得的来源；不回读账号数据库。
- 模型产物不会自动写入个人投资规则或执行交易。用户可独立记录复盘思考，并主动保存规则。

## 现有工作流评测

固定虚构快照及场景输入的 15 题[问答评测集](../server/tests/fixtures/qa_eval/README.md)用于比较现有工作流版本：原有 12 题覆盖通用理财，另 3 题提供公司观察、两账户原始成交、支持与反方材料、关闭个人授权及周末历史。场景必须实际进入冻结输入，不能仅在问题中声称已有资料。`npm run eval:qa` 仅在显式配置真实模型后执行，逐题保存输入、输出和调用轨迹；子集的题目 ID 与追问依赖先校验，缺依赖在付费调用前失败，上游实际失败时后续追问仍跳过。

评测复用生产 ContextBuilder、编排器、Provider 和引用校验，使用默认方法论／问答预设及各场景明确的授权变体，不读取真实账号数据库；不能据此声称当前账号资料、HTTP／Agent／入库完整链路已经用真实模型验收。评分脚本统计资源，语义质量另逐题核对：直接回答、事实与计算正确、推理和取舍、有效反方／未知、相关且有条件的下一步。只在问题需要且数据支持时要求金额幅度，合理核查或继续等待可合格；字数增加和格式通过都不代表质量通过。尚未评阅、调用失败或缺失的题目不能计为通过，编造／越权／错误数字不能被平均分抵消。

当前优先检验问答是否用上观察与真实交易、是否说明证据和未知项。checkpoint、多模型分工和费用估算没有列入当前实施计划。

## 原生联网研究

启用 `webSearch` 时，预览冻结搜索授权；普通 API 的 Responses / Messages，以及支持搜索的本机桥接可执行 `native_web_search`，Chat Completions 不提供搜索。搜索结果在执行期间追加冻结为 `nativeWebEvidence` 和 `evidenceCatalog`，不冒充预览时已经取得的内容；生成和修复仅可引用本次目录中的 ID。`webSearch` 审计记录完成/缺口、搜索次数与工具告警。搜索发生在单次生成之前，生成不重复搜索。没有本地网页抓取或研究数据源刷新任务。

## 实现与验证依据

当前契约由 [workflow](../server/src/ai/workflow.rs)、[orchestrator](../server/src/ai/orchestrator.rs) 和 [structured_output](../server/src/ai/structured_output.rs) 实现；[analysis 应用层](../server/src/application/analysis.rs) 冻结授权、释放网络期间的账号锁并在成功后保存。编排器同文件测试覆盖单次生成、一次修复、再次失败拒绝、方法论冻结、原生搜索引用和候选集边界；[context 测试](../server/src/context.rs) 核对预览与实际 payload、精确值和授权指纹。这些非忽略 Rust 用例由 `npm run test:server` 及完整 `npm test` 执行。真实模型质量另经上面的显式评测入口检查，不能用模拟通过代替。
