# AI 分析工作流契约

mario 的 AI 分析不是一条不断膨胀的提示词，而是“工作流定义、执行器、模型 Provider 与上下文构建”相互独立的本地服务模块。这样可以单独替换某个阶段，而不改变投资方法论、HTTP API 或密钥存储。

## 模块边界

```text
ContextBuilder ── 冻结最小数据载荷与候选资料
      │
      ▼
AnalysisWorkflow ── 定义阶段职责、视角与提示契约
      │
      ▼
InvestmentOrchestrator ── 执行、计时、汇总、审计
      │
      ▼
ModelProvider ── 适配用户选择的模型 API
```

- `ai/workflow.rs`：只定义阶段和提示契约。当前实现为 `InvestmentWorkflowV7`，持久化版本号为 `investment-workflow-v7`。
- `ai/orchestrator.rs`：只负责调用阶段、汇总结果与生成轨迹。
- `ai/provider.rs`：定义统一模型响应，包括正文和可选 token 用量。
- `ai/grounding.rs`：定义逐建议核对契约，检查原值和引文，不把模型核对等同独立认证。
- `ai/structured_output.rs`：解析并校验最终分析，不允许模型自由改变字段、来源类型或引用边界。
- `context.rs`：负责用户可见的数据选择、发送前预览和一致性指纹。

编排器提供 `with_workflow` 注入点。未来可以新增事实核验、估值情景或规则冲突检查工作流，而无需让工作流读取数据库或 API Key。

## 深度工作流 v7

```text
确定性风险检查与冻结授权候选
   ↓
模型自动分类、时效判断与最多10条联合筛选
   ↓
研究计划
   ↓
┌─ 稳健基准方案：资本保护、保持不动、最小行动
└─ 目标推进方案：目标达成概率、风险预算、机会成本
   ↓
独立风险审查：证据漏洞、极端风险、过度自信、规则冲突
   ↓
最终综合裁决：取舍、可逆行动、未知项和证伪条件
   ↓
结构化校验 ──失败──→ 独立修复一次 ──再校验──→ 通过或整次拒绝
   ↓
逐建议证据核对：个人原值、外部摘要摘录、事实支持与局限
   ↓
资料范围内支持 / 证据不足 / 矛盾 / 核对不可用
```

两个候选方案分别调用模型。第二个方案不会读取第一个方案，避免“一个回答里假装列出多个选项”；只有独立风险审查与最终综合阶段能同时看到候选方案。关闭“多方案探索”时仍保留稳健基准方案，确保系统始终比较“保持不动”。关闭“纠错反思”时会跳过风险审查，并在最终阶段明确标记这一事实。

有候选资料时，快速和深度工作流都先增加一次信息分类与时效筛选调用。输出最多 10 条逐字摘录及内部元数据，来源、摘录、日期依据和数量通过机器校验，失败只修复一次，再失败则中止问答。没有候选时跳过该阶段。

快速工作流在筛选之后正常调用两次模型：生成结构化回答，然后逐建议核对证据；最终输出不合格时会增加一次修复调用。不执行深度研究计划、多方案或独立风险审查。

## 结构化输出契约

自动筛选不会改写原始记录、个人档案或已确认规则。`trace.informationSelection` 随分析保存当次元数据，`trace.evidenceCatalog` 保留完整原始内容与附件信息；后续分析只接收最多 10 条选中原文片段。候选预览有字符预算，长正文按问题取连续相关片段，未展示部分不能作为筛选依据。逐建议核对只收到已选来源与授权个人档案，不会再次收到未入选资料。

快速分析和最终综合必须返回同一份 JSON 契约，包含：当前判断、已知事实、合理推断、未知项、方案及取舍、带理由和复盘条件的行动、全局复盘/证伪条件。服务端对未知字段、必填项、数组数量和文本长度进行校验，并把有效结构渲染为可读摘要。

每条事实或推断必须声明 `basis`：

- `user_data` 表示来自用户本次授权的本地数据，不允许附带研究证据 ID；`sourceRefs` 指向实际使用的授权个人原值，服务端校验路径所属资料组及标量值是否存在，客户端从冻结档案显示原值；
- `research_evidence` 表示使用研究证据，必须引用本次冻结候选中的 ID；
- 引用最终入选集合之外、重复或空缺的证据 ID 都会失败。历史模型回答沿用同一引用 ID 契约；历史模型回答仅可为合理推断/追问线索提供引用，出现在已知事实的依据中会被拒绝。

首次失败时，编排器只把原输出、校验错误、允许的证据 ID 和固定契约交给独立修复模块；修复模块不得添加新事实。第二次仍不合格时返回模型错误，不保存分析。兼容仅会自动包裹 JSON 代码块的模型，但不会接受 JSON 前后的解释性文字。

## 可审计工作产物

每次成功分析返回并在本地保存：

- 工作流版本；
- 研究计划；
- 每个独立候选方案的名称、视角和正文；
- 独立风险审查；
- 每次模型调用的阶段、耗时，以及 Provider 返回时的输入/输出 token；
- 通过校验的最终结构、证据目录、校验状态和修复错误；
- 由结构化结果确定性渲染的答案与原有上下文审计。

这些内容是 mario 显式要求模型输出的研究工作产物，不是模型隐藏的思维过程。客户端默认突出最终裁决，中间产物由用户主动展开检查。模型没有返回 usage 时显示“token 未返回”，系统不会估算或伪造成本。

SQLite 的 `analyses.trace` 保存完整工作流轨迹，`analyses.audit` 保存聚合审计。幂等迁移会为既有数据库增加可空字段；旧记录缺少轨迹或新增审计字段时仍可读取。

客户端提供本地分析档案：历史报告可以按不可变 ID 重新打开，检查当时的结构化结论、证据目录和工作流；重新使用旧问题时仍必须基于当前数据生成新的发送前预览。详见 [可审计的 AI 分析档案](analysis-history.md)。

## 失败与安全语义

- 任一必需模型阶段失败时，本次分析整体失败，不把半成品当作最终建议保存。
- 最终输出必须通过机器契约；至多自动修复一次，失败后不会降级保存自由文本。
- API Key 只由 Provider 写入 Authorization 请求头，不进入提示词、轨迹或审计。
- 候选方案、批判与最终裁决均继承固定投资方法论和证据引用约束。
- 本地上下文和上游模型产物统一视为不可信数据；只有当前用户问题与固定系统契约能定义任务，跨阶段文本不能改写角色或跳过护栏。
- 工作流只能访问发送前预览中已冻结的上下文和候选资料。
- 模型产物不会自动写入个人投资规则或执行交易。用户可独立记录复盘思考，并主动保存规则。

## 后续扩展

1. 为失败阶段增加可恢复的本地 checkpoint，而不是重新执行已完成调用。
2. 为不同任务选择不同模型，例如低成本规划器与高可靠裁决器。
3. 增加真实费用估算，但必须基于用户确认的模型价格表与实际 usage。
4. 使用离线评测集比较工作流版本，避免只凭主观观感升级提示词。

## 原生联网研究

启用 `webSearch` 时，预览冻结搜索授权，确认后增加 `native_web_search` 阶段，使用配置的 Responses 或 Messages 服务端工具。原生引用形成 `nativeWebEvidence` 并合并到冻结的 `evidenceCatalog`，结构化生成和修复仅可引用此目录中的 ID。`webSearch` 审计记录完成/缺口、搜索次数与工具告警；不开启搜索时保持原有调用路径。搜索发生在快问答与深度流程之前，后续生成和逐建议核对均不重复搜索。没有本地网页抓取或研究数据源刷新任务。
