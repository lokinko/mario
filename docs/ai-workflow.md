# AI 分析工作流契约

mario 的 AI 分析不是一条不断膨胀的提示词，而是“工作流定义、执行器、模型 Provider 与上下文构建”相互独立的本地服务模块。这样可以单独替换某个阶段，而不改变投资方法论、HTTP API 或密钥存储。

## 模块边界

```text
ContextBuilder ── 冻结最小数据载荷与候选资料
      │
      ▼
AnalysisWorkflow ── 定义阶段职责、视角与提示契约
      │
      ▼
InvestmentOrchestrator ── 执行、计时、汇总、审计
      │
      ▼
ModelProvider ── 适配用户选择的模型 API
```

- `ai/workflow.rs`：只定义阶段和提示契约。当前实现为 `InvestmentWorkflowV8`，持久化版本号为 `investment-workflow-v8`。
- `ai/orchestrator.rs`：只负责调用阶段、汇总结果与生成轨迹。
- `ai/provider.rs`：定义统一模型响应，包括正文和可选 token 用量。
- `ai/structured_output.rs`：解析并校验最终分析，不允许模型自由改变字段、来源类型或引用边界。
- `context.rs` 与 `context/fact_sheet.rs`：负责授权数据选择、去重的精确事实卡、预览和一致性指纹。估值计算链只经 `valuationEvidence` 冻结并写入轨迹审计，不进入提示词。

编排器提供 `with_workflow` 注入点。未来可以新增事实核验、估值情景或规则冲突检查工作流，而无需让工作流读取数据库或 API Key。

## 单次工作流 v8

默认关闭网页搜索；反思和多方案探索开关、deep 请求入口已删除。单次生成结构化报告，通过确定性引用与格式校验后保存；格式不合格只修复一次，再失败则整次拒绝。研究计划、独立候选、风险审查与模型证据核对的生成实现已经删除。

用户启用网页搜索时，在生成前调用供应商原生搜索，最多保留5个来源、每个最多2000字连续相关原文，入选来源的完整返回内容留在轨迹目录。本地资料由应用层关键词检索取前 5 条，ContextBuilder 确定性截取每条最多 2000 字的连续相关原文。资料和搜索结果直接进入生成，不调用模型筛选；普通路径仅 1 次生成，格式修复时为 2 次，主动搜索另增加一次搜索调用。搜索状态和告警只保存在 `trace.webSearch` 并显示在折叠的依据区，不拼接回答前缀。

`researchPlan`、`alternatives`、`critique`、`adviceGrounding`、`informationSelection` 仅为 v7 及更早历史记录保留只读反序列化和展示，不再产生新的中间内容。没有数据库破坏性迁移，旧答案、引用和审计原文仍可打开；恢复旧设置时工作流规范为 `quick`，退役分析选项反序列化后忽略且不再出现在预设接口中，已保存的网页搜索授权保持不变。

## 追问输入

当前问题只使用 question，原 currentUserMessage 字段删除。previousTurn 是确定性截取的上一轮问题、结论和建议动作，总长度上限 800 字符；服务端在预览、执行及 Agent 入口校验，摘要变化会使冻结指纹失效。摘要是不可信会话线索，不能作为 sourceRefs 事实原值；历史报告仅通过只读适配取结论与动作。没有摘要模型阶段。

## 结构化输出契约

确定性检索和摘录不改写原始记录。`BuiltContext.evidenceCatalog` 冻结原文及附件，进入 `trace.evidenceCatalog` 供引用核对；payload 只携带至多 5 条原文片段，不重复发送附件正文。预览与模型消费同一片段；原文与片段共同纳入冻结指纹。`trace.informationSelection` 仅供读取历史筛选元数据，不再由当前流程写入。

新分析只返回 `answer`、`suggestions`、`facts` 和可空的 `question`。回答最多 300 字，建议 1–3 条、每条行动最多 120 字，事实 1–8 条；建议用非空且不重复的 `factIndices` 关联事实，并说明数字依据和可选前提。服务端拒绝旧生成字段、越界索引与未经授权的引用。默认显示回答、建议和可选追问，事实与来源折叠；纯文本摘要按同一顺序渲染。

`models/analysis_history.rs` 独立读取旧结构，保留旧正文、八个报告板块与引用；旧输出不能作为新分析通过校验。历史列表通过报告的统一只读标题接口显示摘要，无需改写数据库或备份格式。

每条事实必须声明 `basis`：

- `user_data` 表示来自用户本次授权的本地数据，不允许附带研究证据 ID；`sourceRefs` 指向 `/facts/summary`、`/facts/holdings/<id>`、`/facts/dataIssues` 或 `/facts/options` 中实际使用的原值（本轮用户陈述可引用 `/question`），服务端校验所属资料组和非空标量是否存在，客户端从冻结档案显示原值；
- `research_evidence` 表示使用研究证据，必须引用本次冻结候选中的 ID；
- 引用最终入选集合之外、重复或空缺的证据 ID 都会失败。历史模型来源仅保留旧报告的读取展示，新分析不产生或召回这类来源。

首次失败时，编排器只把原输出、校验错误、允许的证据 ID 和固定契约交给格式修复模块；修复的系统消息仅要求“只修复格式，不添加新事实”，不重复注入方法论或整套系统规则。第二次仍不合格时返回模型错误，不保存分析。兼容仅会自动包裹 JSON 代码块的模型，但不会接受 JSON 前后的解释性文字。

## 可审计工作产物

每次成功分析返回并在本地保存：

- 工作流版本；
- 每次模型调用的阶段、耗时，以及 Provider 返回时的输入/输出 token；
- 通过校验的最终结构、证据目录、校验状态和修复错误；
- 由结构化结果确定性渲染的答案与原有上下文审计。

这些内容是 mario 显式要求模型输出的研究工作产物，不是模型隐藏的思维过程。客户端默认突出最终裁决，中间产物由用户主动展开检查。模型没有返回 usage 时显示“token 未返回”，系统不会估算或伪造成本。

账号 PostgreSQL schema 内的 `analyses.trace` 保存完整工作流轨迹，`analyses.audit` 保存聚合审计。幂等迁移会为既有数据库增加可空字段；旧记录缺少轨迹或新增审计字段时仍可读取。

客户端提供本地分析档案：历史报告可以按不可变 ID 重新打开，检查当时的结构化结论、证据目录和工作流；重新使用旧问题时仍必须基于当前数据生成新的发送前预览。详见 [可审计的 AI 分析档案](analysis-history.md)。

## 失败与安全语义

- 任一必需模型阶段失败时，本次分析整体失败，不把半成品当作最终建议保存。
- 最终输出必须通过机器契约；至多自动修复一次，失败后不会降级保存自由文本。
- API Key 只由 Provider 写入 Authorization 请求头，不进入提示词、轨迹或审计。
- 生成使用账号已保存并冻结的投资方法论，格式修复只修复原输出；用户从左侧“投资方法论”编辑全文，保存后下一轮生效。系统证据引用与输出约束独立保留。
- 本地上下文、网页及修复输入统一视为不可信数据；只有当前用户问题、已保存的投资方法论与固定系统契约能定义任务，资料文本不能改写角色或跳过护栏。
- 工作流只能访问发送前预览中已冻结的上下文和候选资料。
- 模型产物不会自动写入个人投资规则或执行交易。用户可独立记录复盘思考，并主动保存规则。

## 后续扩展

1. 为失败阶段增加可恢复的本地 checkpoint，而不是重新执行已完成调用。
2. 为不同任务选择不同模型，例如低成本规划器与高可靠裁决器。
3. 增加真实费用估算，但必须基于用户确认的模型价格表与实际 usage。
4. 使用固定虚构快照和 12 题的 [问答评测集](../server/tests/fixtures/qa_eval/README.md) 比较工作流版本。`npm run eval:qa` 仅在显式配置真实模型后执行，逐题保存冻结输入、输出和调用轨迹；评分脚本统计资源，建议质量、直接回答与编造情况人工评分。尚未评阅或调用失败不能视为通过。

## 原生联网研究

启用 `webSearch` 时，预览冻结搜索授权，确认后增加 `native_web_search` 阶段，使用配置的 Responses 或 Messages 服务端工具。原生引用形成 `nativeWebEvidence` 并合并到冻结的 `evidenceCatalog`，结构化生成和修复仅可引用此目录中的 ID。`webSearch` 审计记录完成/缺口、搜索次数与工具告警；不开启搜索时保持原有调用路径。搜索发生在单次生成之前，生成不重复搜索。没有本地网页抓取或研究数据源刷新任务。
