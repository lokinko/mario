# Benchmark 持续维护

本清单维护离线研究数据及其证据。HF输入和标签仓库按用户要求保持公开；不自动改变现有可见性，公开分仓不限制标签访问，未来结果仍不得进入历史决策或训练输入。日线脚本与 GitHub 定时执行方式见 [每日行情自动更新](benchmark.md#每日行情自动更新)；当前覆盖以 HF 固定提交的 `config.json`、`coverage.json` 和 `manifest.json` 为准，验收记录放在 `docs/audits/`，不把一次性统计写入架构说明。

## 每日检查

1. 核对 GitHub 每日行情任务的实际运行结果、最后交易日和 HF 主分支提交，不能只依据绿色任务状态判断数据完整。
2. 校验远端文件全集与 manifest，并核对内容标识；中证A50、上证50当前名单各50只，两种价格口径均覆盖最新交易日。退出成员与已退市证券保留历史，不要求退市后继续产生行情。
3. 来源、采集、下载恢复、完整性或发布失败优先修复。拒绝访问或黑名单响应发生后，停止在该环境调用该来源，不通过更换身份、出口或重复请求绕过限制。另一个既有运行环境的成功记录必须单独核验，不能用本机结果推断其状态。
4. 日线与持续评测共用 `benchmark-hf-main` 队列，避免争用HF主分支。大目录在 HF 临时分支完整上传、核验后快进主分支。拒绝强推；遇到并行发布，先理解新提交，保留其他目录及历史，再整合。损坏重建仅经显式 `--rebuild`，不自动丢弃历史成分证据。

GitHub 数据采集每天北京时间22:37、23:37运行，不依赖本机开机。本聊天另有每日09:00维护检查，用于核验和推进下列工作；本机维护检查需要 Codex 应用所在电脑可运行。无变化时保持安静，有实际增量、失败或需处理的事项再通知。

## 后续扩充顺序

| 顺序 | 增量 | 验收条件 |
| --- | --- | --- |
| 1 | 行情及来源完整性 | 针对实际缺失查找有授权的来源，保存原件及日期；缺失、停牌、退市分别核验，不伪造数值；优化HF批量恢复请求量，遵守429的Retry-After，不以增加并发规避限流 |
| 2 | 历史指数成分 | 收集历次调样公告与生效日期，保留披露时间和原件；当前50只不能回填为历史成员 |
| 3 | 价格口径对账 | 按证券、日期、公司行动核对独立来源；未复权、后复权及其他供应商序列分开保存，不能拼接 |
| 4 | 新评分切片 | 历史选样、特征时点及结果窗口全部通过验证，再构建不可变新标签；复核已有策略及看板，不覆盖旧切片 |

每次只推进一个可验收增量，记录来源、范围、局限、验证和实际发布提交。研究数据不能直接改变正式成绩，不自动交易、读取个人资产或部署网站。策略扩充另遵守仓库的最优参数与Top-10记录规则。
