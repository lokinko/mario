# Benchmark 既有运行维护

本清单用于维护已有离线研究数据、采集任务和成功快照；不是自动扩库或探索新策略的计划。当前产品主线是[买点观察](buy-watch.md)，其在线检查不依赖本研究维护流程。HF输入和标签仓库按用户要求保持公开；不自动改变现有可见性，公开分仓不限制标签访问，未来结果仍不得进入历史决策或训练输入。日线脚本与 GitHub 定时执行方式见 [每日行情自动更新](benchmark.md#每日行情自动更新)；当前覆盖以 HF 固定提交的 `config.json`、`coverage.json` 和 `manifest.json` 为准，验收记录放在 `docs/audits/`，不把一次性统计写入架构说明。

## 每日检查

1. 核对 GitHub 每日行情任务的实际运行结果、最后交易日和 HF 主分支提交，不能只依据绿色任务状态判断数据完整。
2. 校验远端文件全集与 manifest，并核对内容标识；中证A50、上证50当前名单各50只，最新价格覆盖必须达到最后交易日；分别报告独立报价日期与历史OHLC末日，不能用报价覆盖冒充当日日线完整。退出成员与已退市证券保留历史，不要求退市后继续产生行情。
3. 来源、采集、下载恢复、完整性或发布失败优先修复。拒绝访问或黑名单响应发生后，停止在该环境调用该来源，不通过更换身份、出口或重复请求绕过限制。另一个既有运行环境的成功记录必须单独核验，不能用本机结果推断其状态。
4. 最新日线维护 `daily-public-prices/`；原 `daily-prices/` 固定为只读历史引用。Baostock已返回黑名单，不在本机或GitHub环境继续调用；当前来源的价格口径单独核验，不与旧归档拼接。日线与持续评测共用 `benchmark-hf-main` 队列，避免争用HF主分支。大目录在 HF 临时分支完整上传、核验后快进主分支。拒绝强推；遇到并行发布，先理解新提交，保留其他目录及历史，再整合。损坏重建仅经显式 `--rebuild`，不自动丢弃历史成分证据。

GitHub 数据采集按现有工作流在北京时间22:37更新独立报价，23:37刷新完整供应商历史，不依赖本机开机。应用中的聊天自动化是否存在、何时运行以自动化配置为准，本文不替代实际配置，也不因文档修改而创建、停止或调整任务。

## 维护与新增研究的边界

维护优先处理实际来源故障、完整性、恢复和发布问题。历史成分、价格口径及缺失基本面只记录为数据局限，不默认启动新采集、参数扫描、评分切片升级或 Agent 评测。新增研究须对应用户明确任务或已确认的投资疑问，并单独说明范围和验收条件。

已有历史标签、研究数据与未发布实验应保留，不能为整理当前文档而删除。维护修复提交前检查本地分支和全部待推提交；若含其他任务或未授权发布的研究，隔离交付，不根据旧记录假定当前 main 仍有同样的分叉。历史恢复经过见[公开v8持续评测恢复](audits/benchmark-live-v8-recovery-20261104.md)。

研究不读取个人资产、不执行真实交易；网站部署需另有任务授权。实际开展策略研究时仍遵守仓库的参数去重、成绩与Top-10记录规则。
