# 数据问题提示收敛实施记录

本记录对应 [设计方案](../feature_design.md) 四个阶段。当前职责边界见 [架构说明](architecture.md) 与 [模块边界](module-boundaries.md)。

## 已实施行为

1. 后端以 `DataIssue` 表达缺汇率、待确认拆合股、隔离交易链及存款待核对；原始数据读取后先生成精确会计投影，快照只构建一次。删除旧全局决策标志、重复风险项与时效门槛。缺汇率、待确认拆合股和隔离使组合总值不可用；其他持仓原币金额继续可见。存款待核对不清空再平衡。
2. 规划以问题码返回阻止原因。补充 `invalidTargetWeights` 只用于再平衡阻止原因，并返回 `targetTotalPct`，避免用文本表达目标权重缺口。未平仓期权及标的仅排除动作，其他持仓使用完整组合分母和精确十进制金额；最早日期包含参与分母的排除持仓。
3. AI 接收结构化问题与规划范围；不再强制动作逐字匹配核对套话，保留结构、证据 ID、引用路径及不可用原值校验。历史分析的冻结上下文原样保留。
4. 页面删除全局停用横幅与重复抽屉。总览可定位问题；行内按问题码提供修复入口。日期、来源和参考价使用中性元数据。财务请求待确认用 `FinancialRequestError.kind = "pending"`，保留原请求编号及重试输入。

## 设计选择与 D8 文案评审

- 价格时效：仅显示实际观察日期及来源，不新增时间阈值。沿用现有更新价格入口。
- 缺汇率：不显示部分组合总值，也不回退到旧历史总值；原币明细保留。
- 待确认拆合股：相关持仓估值不可用，依赖完整分母的再平衡不计算，其他持仓照常显示。
- 删除确认：保留删除对象、交易数、对当前现金的影响、历史交易待核对及审计保留等有决策价值的后果；合并冗长的逐种现金流解释，删除“最后一笔归零”等实现步骤。
- 隐藏金额：删除总览重复说明，按钮提示仍说明复制和导出包含真实数据。
- 其他币种存款：与常用币种使用同一行内编辑与核对流程，删除“旧数据”全局提示，不删除任何余额。

## 数据与恢复

快照派生字段不持久化，财务回执重放重新读取当前快照；备份格式不变。历史分析、隔离原始记录、每日历史与财务日志不改写；恢复仍使用原事务校验，失败整体回滚。未保留旧字段的兼容计算路径。

## 验证

分阶段执行后端测试、严格 Clippy、构建、格式与架构检查，以及前端构建、Prettier 和 Vitest；最终运行 `npm test`，覆盖一次性 PostgreSQL、HTTP、Web、Codex 桥接及财务迁移/备份恢复验收。测试使用隔离账号与临时集群，未连接开发或生产数据库。验证结果：前端 261 项通过，后端 220 项通过；4 项依赖真实行情、真实模型或本机 Codex 的测试沿用已有忽略设置，未调用真实模型。架构检查、前端构建与 Prettier、Rust 格式/严格 Clippy/构建通过；HTTP（144 项断言）、Web、模拟 Codex 桥接及财务发布门禁通过，原生备份恢复覆盖 164 张表。另用一次性 PostgreSQL 账号检查实际页面，验证问题定位、拆合股修复抽屉、旧日期无警告、不可用金额隐藏。
