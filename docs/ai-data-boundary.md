# AI 数据边界与问答预设

mario 按账号在自建服务器的 PostgreSQL 保存投资数据。用户在“设置 → 问答预设”一次配置财务档案、持仓与交易、研究证据与历史搜索资料的范围，以及联网选项；问答默认使用单次分析，每次主动提问后自动按预设准备最新资料并发送给配置的模型。问答页展示模型 report 和历史对话，可随时打开“查看将发送的数据”预览，提问时无需逐次确认。

## 数据流

```text
账号数据库（PostgreSQL，按账号 schema 隔离）
   │
   ├─ ContextBuilder：按用户选择构建最小上下文
   │        ├─ 财务档案
   │        ├─ 资产持仓、现金与真实交易
   │        └─ 相关研究证据
   │
   ▼
后台冻结上下文 ── 指纹复核 ── 用户配置的模型服务
                                      │
                                      ▼
                              分析结果与本地审计
```

## 用户可以控制什么

在设置中可以分别配置之后每次分析是否自动发送：

- 财务档案：收入、支出、负债、应急资金、期限和风险边界；
- 资产持仓事实卡：名称、代码、类别、币种、精确原币市值与成本、服务端计算的占比/目标偏差/浮盈比例、价格日期、来源与问题码；存在期权时另附合约方向、标的、行权价、到期日和乘数。同一授权组还包含每项持仓最近20笔已录入交易及总笔数（日期、同日顺序、原始股数和价格、金额、费用税费、币种、账户、备注），现金按币种携带余额与核对状态。原始成交价保留成交时股数单位，不能跨拆合股直接比较。估值计算链保留在冻结审计，不进入提示词；
- 相关研究证据：问题明确提及观察公司名称或代码时，优先冻结其最新及本周已保存的观察值、规则、日期和来源；再按问题及已授权持仓检索手工资料和历史搜索资料，合计最多5条；每条只发送最多 2000 字连续相关原文及来源信息，完整原文和附件留在冻结审计与引用抽屉。网页证据直接进入生成，不经模型筛选；

关闭“持仓与交易”后不发送持仓、现金和成交事实卡；关闭“研究证据”后不发送观察证据及手工/历史搜索资料。用户主动写入问题中的关注理由、公司名称和交易信息仍属于问题正文，不受上述资料组开关移除。后台观察检查不调用模型，点击讨论先进入问题草稿，发送后才执行分析。

本次问题始终进入模型 payload；请求中的工作流标识固定为 `quick`，用于服务端选择并校验当前单次流程。左侧“投资方法论”提供当前提示词全文，可以直接修改或补充，保存后每轮自动附上。正文按账号隔离，最多 4000 字符，未保存的编辑不生效。初次使用提供可编辑的初始范本；“使用初始范本”只填入编辑区，仍需保存。方法论随账号备份恢复。系统数据质量、事实来源与输出格式约束单独保留。初始范本允许给出明确方向和比例，同时说明前提与主要风险；已保存正文不会被范本替换。继续追问通过独立 previousTurn 携带上一轮问题、报告结论与最多 3 条动作，总计不超过 800 个 Unicode 字符；不携带完整报告，也不额外调用模型总结。当前 question 仅含本轮问题，新对话清空上一轮摘要。上一轮摘要不作为事实来源。问答预设只控制财务档案、持仓与交易、研究证据与历史搜索资料这几组资料及网页搜索；个人规则、复盘和每日资产不进入问答。新账号网页搜索默认关闭。

财务档案以 `providedFields` 逐项记录月收入、月支出、备用金、负债、投资期限和可承受最大回撤是否已填写。“我的情况”中未知项显示为空；明确输入的 0、5 年或 15% 与其他合法数值一样，保存后进入问答预览与实际模型事实卡。未保存草稿不进入问答；清空后保存会移除该项填写状态，事实卡标为“未填写”。派生结余和备用金月数必须具备已填写的输入，月支出为 0 时不计算备用金月数。

旧档案与旧备份没有 `providedFields` 时，金额正数视为已填写，0 仍视为未知；期限 0／5 年及回撤 0／15% 仍保守视为未知，不能从历史数值反推用户意图。用户重新填写并保存后，以显式状态为准。此适配在不再支持缺少填写状态的档案与备份时移除；现有数值与精确原文不丢弃，无需修改表结构或备份版本。历史收支没有 `exactAmounts` 时，只将已保存数值转为十进制字符串以保留资料，不补造早期已丢失的精度。数值投影继续服务现有确定性计算，填写状态决定表单与模型事实是否已知。

新回答的个人事实必须携带非空 `sourceRefs`，只能引用本轮问题或本次授权事实卡中存在的非空标量；资料未授权时不能引用，上一轮回答不能作为来源。机器校验拒绝空白字符串及非标量值，仍允许数值 `0` 和布尔 `false`，详见[工作流引用校验](ai-workflow.md#结构化输出契约)。缺失信息直接指出；核查或等待动作须说明本题缺什么、为何重要、补齐后按什么条件再判断，不能为凑条数转去无关安排。金额与比例只在适合本题且资料支持时给出，依赖目标／假设的行动须先说明前提；详略和机器预算见[输出契约](ai-workflow.md#结构化输出契约)。引用门禁保证可回查，不保证模型文字已通过语义核对；历史报告不重新生成或改写。

财务档案中的基准币种决定组合汇总口径。持仓币种不同于基准币种时，按统一汇率设置折算：默认使用服务端自动获取的 ECB 参考值，用户可手动覆盖。系统保存来源和实际观察日，但参考值不等于券商成交或银行结算汇率。汇率缺失时，发送给模型的组合状态会明确标记为不可比较，确定性规划也停止输出组合结论。各项资产的估值日期独立保留，日期不同不会产生警告或暂停行动建议。存款待核对、旧价和手工来源保留日期及参考状态，可并行核对，不作为其他已可计算部分的前置条件；不能把它们与真正缺汇率造成的计算缺口混同。

带来源持仓估值只证明指定请求日下“持仓数量 × 来源日收盘价”的计算链，当前使用[公共五年价格库](market-data.md#统一公共价格库)中的前复权收盘价，保存实际价格日、来源和复权基准；原成交及成本保留原值。旧来源估值证据只用于历史恢复。它不证明数量来自券商，不代表实时成交、内在价值、复权总回报或完整业绩归因。没有对应估值证据的持仓仍明确视为用户声明市值。模型密钥和历史保留的行情密钥永不进入提示词。

## 上下文一致性指纹

客户端每次提问都会读取已保存预设；读取失败时保留问题并显示错误，不发送模型请求。后台准备接口根据实际 JSON 载荷生成版本指纹。真正发起分析时，服务端重新构建上下文并复核指纹：

- 问题、勾选项、本地数据或候选资料发生变化，旧指纹立即失效；
- 缺失指纹或指纹不一致时，服务端拒绝请求；用户重试后会重新准备资料；
- 指纹用于准备与执行之间的一致性检测，不是数字签名，也不替代账号鉴权。

## 永远不进入提示词的数据

- 模型 API Key；
- 行情 API Key；
- 数据库连接信息及账号 schema / 连接标识；业务记录 ID 可作为事实卡键和引用路径的一部分发送，不属于连接凭据；
- 用户未选择的数据组。

模型 API Key 在 API 服务中按账号解密，配置独立 Agent 时通过受保护的执行通道传递，仅用于供应商协议认证（OpenAI Bearer 或 Anthropic `x-api-key`），不进入模型上下文正文或个人 JSON 业务导出。Codex 本地桥接使用设备已有登录；本机 ChatGPT 方式使用 Mario 自己的 OAuth 注册，两者凭据均留在设备。网站 ChatGPT 身份登录另行配置，不授予模型执行额度，详见[本机桥接](codex-bridge.md)与[网站登录](chatgpt-sign-in.md)。模型提供商仍会看到网络请求的常规元数据；mario 无法替代用户审查所选模型服务的隐私政策。

研究资料和上游模型产物也可能包含恶意或意外指令。当前问题定义本轮任务，用户已保存的方法论提供分析视角和沟通偏好；固定系统策略及引用契约独立保留。事实资料、网页和上一轮回答作为不可信数据，不能改写角色或要求泄露资料。格式修复只接收原输出、错误和允许的证据 ID，不重新发送全部上下文。这些提示约束不构成对模型语义或抗注入能力的形式证明。

## 分析审计

分析完成后，账户内审计记录包含：

- Provider 与模型名称；
- 实际使用的上下文组；
- 实际载荷字节数与上下文指纹；
- 实际使用的带来源证据条数，以及是否要求引用；
- 工作流版本（v7 及更早记录另有研究计划、候选方案、风险审查和证据核对，只读）；
- 通过校验的结构化分析、引用证据目录、校验次数与是否触发自动修复；
- 每次模型调用的阶段与耗时，以及 Provider 实际返回时的输入/输出 token；
- 是否使用外部数据；
- API Key 是否进入提示词（必须始终为 `false`）。

审计与分析结果一起保存在该账号的数据库 schema。`GET /api/analyses` 返回最近 50 条索引及可用的审计摘要，完整回答和 `workflowTrace` 经 `GET /api/analyses/{id}` 读取；问答页显示报告与引用，不显示独立的完整轨迹面板。轨迹记录显式工作产物，不包含 API Key，也不声称暴露模型隐藏思维。早期记录缺少审计或轨迹时，读取接口允许这些字段为空。

## 当前限制

- 当前分析的资料范围包括授权个人事实及研究来源；ECB 汇率、证券日线、观察交易日期与已实施分红先由确定性模块计算，可选原生搜索另提供外部来源。观察不自动核验经营基本面或证明分红持续性；
- 数据库尚未整体加密；
- 上下文指纹不是防篡改签名；
- 模型服务收到数据后的存储与训练政策由用户选择的服务商决定。

这些是当前能力边界，不作为自动扩展数据源或工作流的待办。

## 问答基线评测的数据边界

[问答评测集](../server/tests/fixtures/qa_eval/README.md) 仅使用仓库内固定的虚构快照、成交及研究来源，含明确关闭个人资料的授权变体，不读取当前账号、开发数据库或生产数据。真实调用只在显式配置 `MARIO_EVAL_*` 后运行，密钥仅用于供应商认证，不进入报告。复用实际模型参数不等于读取该账号的个人资料、已保存方法论或问答预设；默认／场景授权及实际载荷逐题保留。评测报告含虚构冻结输入、模型回答与引用；保存到 Git 忽略的 `.runtime/qa-eval/`。网页搜索如开启仍调用供应商真实服务，不能把搜索或生成结果视为已独立核实的事实。

## 实现与验证依据

[ContextBuilder](../server/src/context.rs) 与[事实卡](../server/src/context/fact_sheet.rs) 负责三组授权及原值投影，[分析应用层](../server/src/application/analysis.rs) 统一预览、执行和观察证据装配；这些模块的测试覆盖关闭授权、20 笔交易上限、交易变更指纹、方法论变化和执行失败不保存。[Advisor 测试](../client/src/features/research/Advisor.test.tsx) 验证每次读取预设、准备失败不发送、预览一致性及追问摘要。后端非忽略用例由 `npm run test:server` 运行，前端由 `npm test --prefix client` 运行，均纳入完整 `npm test`；真实模型评测单独显式执行。
