# AI 数据边界与问答预设

mario 按账号在自建服务器的 PostgreSQL 保存投资数据。用户在“设置 → 问答预设”一次配置财务档案、持仓明细、研究证据与历史搜索资料的范围，以及联网选项；问答默认使用单次分析，每次主动提问后自动按预设准备最新资料并发送给配置的模型。问答页展示模型 report 和历史对话，可随时打开“查看将发送的数据”预览，提问时无需逐次确认。

## 数据流

```text
账号数据库（PostgreSQL，按账号 schema 隔离）
   │
   ├─ ContextBuilder：按用户选择构建最小上下文
   │        ├─ 财务档案
   │        ├─ 资产持仓
   │        └─ 相关研究证据
   │
   ▼
后台冻结上下文 ── 指纹复核 ── 用户配置的模型服务
                                      │
                                      ▼
                              分析结果与本地审计
```

## 用户可以控制什么

在设置中可以分别配置之后每次分析是否自动发送：

- 财务档案：收入、支出、负债、应急资金、期限和风险边界；
- 资产持仓事实卡：名称、代码、类别、币种、精确原币市值与成本、服务端计算的占比/目标偏差/浮盈比例、价格日期、来源与问题码；存在期权时另附合约方向、标的、行权价、到期日和乘数。估值计算链保留在冻结审计，不进入提示词；
- 相关研究证据：按问题和当前持仓名称进行关键词检索，取前 5 条；每条只发送最多 2000 字连续相关原文及来源信息，完整原文和附件留在冻结审计与引用抽屉。网页证据直接进入生成，不经模型筛选；

本次问题和单次分析工作流标识始终发送，否则模型无法执行任务。左侧“投资方法论”提供当前提示词全文，可以直接修改或补充，保存后每轮自动附上。正文按账号隔离，最多 4000 字符，未保存的编辑不生效。初次使用提供可编辑的初始范本；“使用初始范本”只填入编辑区，仍需保存。方法论随账号备份恢复。系统数据质量、事实来源与输出格式约束单独保留。初始范本允许给出明确方向和比例，同时说明前提与主要风险；已保存正文不会被范本替换。继续追问通过独立 previousTurn 携带上一轮问题、报告结论与最多 3 条动作，总计不超过 800 个 Unicode 字符；不携带完整报告，也不额外调用模型总结。当前 question 仅含本轮问题，新对话清空上一轮摘要。上一轮摘要不作为事实来源。问答预设只控制财务档案、持仓明细、研究证据与历史搜索资料这几组资料及网页搜索；个人规则、复盘和每日资产不进入问答。新账号网页搜索默认关闭。

事实卡将未填写或仍为初始值的收支/偏好标为“未填写”，不将默认零值断言为没有收入或负债。历史收支没有 exactAmounts 时，只将已保存数值转为十进制字符串以保留资料，不补造早期已丢失的精度。

新回答的个人事实必须携带非空 `sourceRefs`，只能引用本轮问题或本次授权事实卡中存在的非空标量；资料未授权时不能引用，上一轮回答不能作为来源。缺失说明放在结论或最多一个追问中，不单独以“核实、暂缓”填充建议。引用门禁保证可回查，不保证模型文字已通过语义核对；历史报告不重新生成或改写。

财务档案中的基准币种决定组合汇总口径。持仓币种不同于基准币种时，按统一汇率设置折算：默认使用服务端自动获取的 ECB 参考值，用户可手动覆盖。系统保存来源和实际观察日，但参考值不等于券商成交或银行结算汇率。汇率缺失时，发送给模型的组合状态会明确标记为不可比较，确定性规划也停止输出组合结论。各项资产的估值日期独立保留，日期不同不会产生警告或暂停行动建议。

带来源持仓估值只证明指定请求日下“持仓数量 × 来源日收盘价”的计算链（默认 Yahoo 拆股调整日收盘价，配置个人 Key 后主动查询可用 Twelve Data 未复权日收盘价）。它不证明数量来自券商，不代表实时成交、内在价值、复权总回报或完整业绩归因。没有对应估值证据的持仓仍明确视为用户声明市值。行情 API Key 与模型密钥一样永不进入提示词。

## 上下文一致性指纹

客户端每次提问都会读取已保存预设；读取失败时保留问题并显示错误，不发送模型请求。后台准备接口根据实际 JSON 载荷生成版本指纹。真正发起分析时，服务端重新构建上下文并复核指纹：

- 问题、勾选项、本地数据或候选资料发生变化，旧指纹立即失效；
- 缺失指纹或指纹不一致时，服务端拒绝请求；用户重试后会重新准备资料；
- 指纹用于准备与执行之间的一致性检测，不是数字签名，也不替代账号鉴权。

## 永远不进入提示词的数据

- 模型 API Key；
- 行情 API Key；
- 数据库连接信息与内部数据库标识；
- 用户未选择的数据组。

模型 API Key 在 API 服务中按账号解密，通过受保护的执行通道交给 Agent，用于到模型服务的 HTTP Authorization 请求头，不进入用户上下文正文或业务导出。Codex 本地桥接使用设备已有登录，凭据保留在设备。模型提供商仍会看到网络请求的常规元数据；mario 无法替代用户审查所选模型服务的隐私政策。

研究资料和上游模型产物也可能包含恶意或意外指令。固定系统策略把 冻结上下文、网页资料和格式修复输入统一视为不可信数据：只有明确标记的当前用户问题能定义任务，其他字段不能改写角色、要求泄露数据或绕过护栏。

## 分析审计

分析完成后，账户内审计记录包含：

- Provider 与模型名称；
- 实际使用的上下文组；
- 实际载荷字节数与上下文指纹；
- 实际使用的带来源证据条数，以及是否要求引用；
- 工作流版本（v7 及更早记录另有研究计划、候选方案、风险审查和证据核对，只读）；
- 通过校验的结构化分析、引用证据目录、校验次数与是否触发自动修复；
- 每次模型调用的阶段与耗时，以及 Provider 实际返回时的输入/输出 token；
- 是否使用外部数据；
- API Key 是否进入提示词（必须始终为 `false`）。

审计与分析结果一起保存在该账号的数据库 schema，可通过 `GET /api/analyses` 读取。轨迹是模型被明确要求输出的工作产物，不包含 API Key，也不声称暴露模型隐藏思维。缺少审计或轨迹字段的早期记录显示为无审计信息。

## 当前限制

- 外部数据只有用户整理的研究证据、ECB 汇率、证券日收盘价和可选的原生网页搜索；证券价格只核验计算来源，尚未接入基准指数、基本面自动抓取或现金流时点全组合估值；
- 数据库尚未整体加密；
- 上下文指纹不是防篡改签名；
- 模型服务收到数据后的存储与训练政策由用户选择的服务商决定。

这些限制必须在正式公开发布前继续收敛。

## 问答基线评测的数据边界

[问答评测集](../server/tests/fixtures/qa_eval/README.md) 仅使用仓库内的虚构快照，不读取当前账号、开发数据库或生产数据。真实调用只在显式配置 `MARIO_EVAL_*` 后运行，密钥仅用于供应商认证，不进入报告。评测报告含虚构冻结输入、模型回答与引用；保存到 Git 忽略的 `.runtime/qa-eval/`。网页搜索如开启仍调用供应商真实服务，不能把搜索或生成结果视为已独立核实的事实。
