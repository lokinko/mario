# AI 数据边界与发送前预览

知衡默认在本机保存投资数据，但用户主动发起 AI 分析时，完成任务所需的上下文会发送给用户配置的模型服务。发送前预览把这一步从模糊承诺变成可检查、可选择、可审计的数据契约。

## 数据流

```text
本地 SQLite
   │
   ├─ ContextBuilder：按用户选择构建最小上下文
   │        ├─ 财务档案
   │        ├─ 投资目标
   │        ├─ 资产持仓
   │        ├─ 确定性规划结果
   │        ├─ 规则型风险检查
   │        ├─ 个人投资规则
   │        ├─ 周期系统复盘
   │        ├─ 组合变化归因
   │        ├─ 组合资金流水
   │        └─ 相关研究证据
   │
   ├─ MemoryRetriever：按问题初筛最多 16 条结构化候选记忆
   │
   ▼
发送前预览 ── 用户确认 ── 指纹复核 ── 用户配置的模型服务
                                      │
                                      ▼
                              分析结果与本地审计
```

## 用户可以控制什么

每次分析都可以分别选择是否发送：

- 财务档案：收入、支出、负债、应急资金、期限和风险边界；
- 投资目标：目标金额、已投入、月度投入、日期和优先级；
- 资产持仓：名称、代码、类别、原币市值、成本、目标权重、币种、用户填写的折算汇率、估值日期与口径完整状态；
- 确定性规划结果：目标情景、月度缺口、风险预算和再平衡偏差；
- 规则型风险检查：本地规则引擎生成的事实与行动提示；
- 个人投资规则：当前启用的规则、触发条件、依据和版本；
- 周期系统复盘：最近最多 8 期纪律、违规、经验、行动与聚合快照；
- 组合变化归因：最近最多 12 个组合检查点、冻结的流水汇总、总市值变化、估值/数据残差、资产类别漂移和明确标注的 Modified Dietz 近似回报；
- 组合资金流水：最近最多 100 笔入金、出金、分红、利息、费用、税费和买卖额，包含用户填写的原币、汇率、发生日期与说明；CSV 导入来源和外部交易编号仅用于本地审计与去重，不进入模型载荷；
- 相关研究证据：按问题和当前持仓名称筛选，最多 12 条，包含摘要、来源层级、HTTPS 链接与资料日期；
- 相关历史记忆：仅深度工作流使用；包含来源类型、复盘状态、反证信号、相对分数和命中原因，可以整体关闭或逐条排除。

本次问题和工作流选择始终发送，否则模型无法执行任务。若用户关闭基础数据却保留派生数据，预览会明确显示派生规划或风险检查仍被包含。

## 记忆不会在预览后越界

深度工作流先用用户问题在本地初筛最多 16 条候选记忆。预览会显示候选记录的完整结构化内容、复盘状态与命中原因。用户可以逐条标记“本次发送”或“留在本机”；选择变化会立即使旧预览过期，必须重新生成指纹。用户确认后，原问题最多复核 4 条，模型生成的研究计划最多扩展 6 条，合并后实际使用不超过 8 条；两轮都只能访问已授权候选，不能访问排除项或候选集之外的历史记录。

快速工作流不发送历史记忆，即使界面中的记忆开关仍处于开启状态，预览也会明确说明本次不会读取。

组合变化归因和原始组合流水是两个单独授权的数据组。固定系统策略明确禁止把“估值/数据残差”称为投资收益或业绩归因；Modified Dietz 数值也只能称为按现金流日期加权的期间近似回报，不能称为时间加权收益率、超额收益或能力证明。两者都依赖用户录入的完整性，只能作为进一步核对的线索。

财务档案中的基准币种决定组合汇总口径。持仓币种不同于基准币种时，用户必须填写“1 单位持仓币种折合多少基准币种”；当前版本不声称自动核验该汇率。汇率缺失时，发送给模型的组合状态会明确标记为不可比较，确定性规划也停止输出组合结论。全部持仓估值日期未对齐时，系统允许查看当前折算总值，但拒绝冻结新的组合检查点。

## 上下文一致性指纹

预览会根据实际 JSON 载荷和候选记忆生成本地版本指纹。真正发起分析时，服务端重新构建上下文并复核指纹：

- 问题、勾选项、本地数据或候选记忆发生变化，旧指纹立即失效；
- 任一候选记忆的逐条授权发生变化，旧指纹立即失效；
- 缺失指纹或指纹不一致时，服务端拒绝请求并要求重新预览；
- 指纹仅用于同一台设备上的一致性检测，不是数字签名，也不替代进程间鉴权。

## 永远不进入提示词的数据

- 模型 API Key；
- SQLite 文件路径；
- 数据库内部连接信息；
- CSV 导入来源与外部交易编号；
- 用户未选择的数据组；
- 未进入候选集的历史记忆。

API Key 仅由系统钥匙串读取，用于到模型服务的 HTTP Authorization 请求头。模型提供商仍会看到网络请求的常规元数据；知衡无法替代用户审查所选模型服务的隐私政策。

历史记忆和上游模型产物也可能包含恶意或意外指令。固定系统策略把 `local_context`、历史记忆、研究计划、候选方案和独立审查统一视为不可信数据：只有明确标记的当前用户问题能定义任务，其他字段不能改写角色、要求泄露数据或绕过护栏。

## 本地审计

分析完成后，本地审计记录包含：

- Provider 与模型名称；
- 实际使用的上下文组；
- 实际载荷字节数与上下文指纹；
- 实际使用的历史记忆条数；
- 其中已复盘记忆和反证记忆的条数；
- 实际使用的带来源证据条数，以及是否要求引用；
- 工作流版本、研究计划、独立候选方案与风险审查；
- 通过校验的结构化分析、引用证据目录、校验次数与是否触发自动修复；
- 每次模型调用的阶段与耗时，以及 Provider 实际返回时的输入/输出 token；
- 是否使用外部数据；
- API Key 是否进入提示词（必须始终为 `false`）。

审计与分析结果一起保存在本地 SQLite，可通过 `GET /api/analyses` 读取。轨迹是模型被明确要求输出的工作产物，不包含 API Key，也不声称暴露模型隐藏思维。旧版本的分析记录没有审计或轨迹字段时仍能正常读取，并显示为无审计信息。

## 当前限制

- 已支持用户整理的带来源研究证据；包含证据时 `externalDataUsed` 为 `true`。尚未接入自动抓取和核验行情或基本面的 Provider；
- 本地 HTTP 服务已使用 loopback、严格 CORS、随机端口、每次启动的 256 位令牌与桌面生命周期隔离；它不能防御已经取得当前用户账户任意代码执行或进程内存读取能力的恶意软件；
- 数据库尚未整体加密；
- 上下文指纹不是防篡改签名；
- 模型服务收到数据后的存储与训练政策由用户选择的服务商决定。

这些限制必须在正式公开发布前继续收敛。
