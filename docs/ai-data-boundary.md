# AI 数据边界与问答预设

mario 按账号在自建服务器的 PostgreSQL 保存投资数据。用户在“设置 → 问答预设”一次配置财务档案、持仓明细、研究证据与历史搜索资料的范围，以及联网选项；问答固定使用深度分析，每次主动提问后自动按预设准备最新资料并发送给配置的模型。问答页只展示模型 report 和历史对话，不再逐次展示预览和发送确认。

## 数据流

```text
账号数据库（PostgreSQL，按账号 schema 隔离）
   │
   ├─ ContextBuilder：按用户选择构建最小上下文
   │        ├─ 财务档案
   │        ├─ 资产持仓
   │        └─ 相关研究证据
   │
   ▼
后台冻结上下文 ── 指纹复核 ── 用户配置的模型服务
                                      │
                                      ▼
                              分析结果与本地审计
```

## 用户可以控制什么

在设置中可以分别配置之后每次分析是否自动发送：

- 财务档案：收入、支出、负债、应急资金、期限和风险边界；
- 资产持仓：名称、代码、类别、原币市值、成本、目标权重、币种、折算汇率、汇率来源与观察日、估值日期与口径完整状态；存在时还包含估值日数量、未复权日收盘价、交易所、MIC、价格来源与实际观察日；
- 相关研究证据：按问题和当前持仓名称筛选，初筛最多 30 条，再由模型结合本次网页资料筛选最多 10 条，包含摘要、来源层级、HTTPS 链接与资料日期；

本次问题和固定的深度分析工作流标识始终发送，否则模型无法执行任务。左侧“投资方法论”提供当前提示词全文，可以直接修改或补充，保存后每轮自动附上。正文按账号隔离，最多 4000 字符，未保存的编辑不生效。初次使用提供可编辑的初始范本；“使用初始范本”只填入编辑区，仍需保存。方法论随账号备份恢复。系统数据质量、事实来源与输出格式约束单独保留。继续追问会带上上一轮问题及最多 6,000 字符的回答摘要，新对话清空该摘要。问答预设仅提供财务档案、持仓明细、研究证据与历史搜索资料三组资料。读取或保存旧预设时，自动关闭规划、风险检查、个人规则、周期复盘和每日资产记录，并将快速分析调整为深度分析；保留上述三组资料与分析选项的原有勾选状态。

财务档案中的基准币种决定组合汇总口径。持仓币种不同于基准币种时，用户必须填写“1 单位持仓币种折合多少基准币种”，也可主动查询 ECB 参考值后确认。系统保存来源和实际观察日，但参考值不等于券商成交或银行结算汇率。汇率缺失时，发送给模型的组合状态会明确标记为不可比较，确定性规划也停止输出组合结论。各项资产的估值日期独立保留，日期不同不会产生警告或暂停行动建议；有效日期、时效与价格确认检查仍分别执行。

带来源持仓估值只证明指定请求日下“用户声明数量 × Twelve Data 未复权日收盘价”的计算链。它不证明数量来自券商，不代表实时成交、内在价值、复权总回报或完整业绩归因。没有对应估值证据的持仓仍明确视为用户声明市值。行情 API Key 与模型密钥一样永不进入提示词。

## 上下文一致性指纹

客户端每次提问都会读取已保存预设；读取失败时保留问题并显示错误，不发送模型请求。后台准备接口根据实际 JSON 载荷生成版本指纹。真正发起分析时，服务端重新构建上下文并复核指纹：

- 问题、勾选项、本地数据或候选资料发生变化，旧指纹立即失效；
- 缺失指纹或指纹不一致时，服务端拒绝请求；用户重试后会重新准备资料；
- 指纹用于准备与执行之间的一致性检测，不是数字签名，也不替代账号鉴权。

## 永远不进入提示词的数据

- 模型 API Key；
- 行情 API Key；
- 数据库连接信息与内部数据库标识；
- 用户未选择的数据组。

模型 API Key 在 API 服务中按账号解密，通过受保护的执行通道交给 Agent，用于到模型服务的 HTTP Authorization 请求头，不进入用户上下文正文或业务导出。Codex 本地桥接使用设备已有登录，凭据保留在设备。模型提供商仍会看到网络请求的常规元数据；mario 无法替代用户审查所选模型服务的隐私政策。

研究资料和上游模型产物也可能包含恶意或意外指令。固定系统策略把 `local_context`、研究计划、候选方案和独立审查统一视为不可信数据：只有明确标记的当前用户问题能定义任务，其他字段不能改写角色、要求泄露数据或绕过护栏。

## 分析审计

分析完成后，账户内审计记录包含：

- Provider 与模型名称；
- 实际使用的上下文组；
- 实际载荷字节数与上下文指纹；
- 实际使用的带来源证据条数，以及是否要求引用；
- 工作流版本、研究计划、独立候选方案与风险审查；
- 通过校验的结构化分析、引用证据目录、校验次数与是否触发自动修复；
- 每次模型调用的阶段与耗时，以及 Provider 实际返回时的输入/输出 token；
- 是否使用外部数据；
- API Key 是否进入提示词（必须始终为 `false`）。

审计与分析结果一起保存在该账号的数据库 schema，可通过 `GET /api/analyses` 读取。轨迹是模型被明确要求输出的工作产物，不包含 API Key，也不声称暴露模型隐藏思维。旧版本的分析记录没有审计或轨迹字段时仍能正常读取，并显示为无审计信息。

## 当前限制

- 已支持用户整理的研究证据、用户主动查询的 ECB 汇率和 Twelve Data 日收盘价；证券价格只核验计算来源，尚未接入公司行动、基准指数、基本面自动抓取或现金流时点全组合估值；
- 本地开发 HTTP 服务使用 loopback、严格 CORS 与访问令牌；它不能防御已经取得当前用户账户任意代码执行或进程内存读取能力的恶意软件；
- 数据库尚未整体加密；
- 上下文指纹不是防篡改签名；
- 模型服务收到数据后的存储与训练政策由用户选择的服务商决定。

这些限制必须在正式公开发布前继续收敛。
