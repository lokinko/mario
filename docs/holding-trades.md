# 真实成交与持仓

“我的情况 → 投资持仓”按账户分别记录同一证券的真实买入、卖出和现金分红。请从最早一笔买入开始补齐历史，按券商成交单的实际日期和同日顺序填写。一笔记录对应一笔实际成交或分红到账，误录可直接编辑或删除原记录。系统不再生成期初余额、撤销或修正行。

## 录入字段

买卖填写账户、成交日期、当日顺序、数量、单价、不含费用的成交金额、交易费用和税费。金额默认按数量 × 单价估算，并可按成交单的实际金额校正；金额与数量 × 单价的偏差不能超过 0.01 个计价单位，JPY 为 1。编号应填写每笔成交的编号，避免把多笔成交共用的委托编号当作成交编号；没有编号可留空。备注也是选填。

现金分红填写到账日期、当日顺序、税前总金额、费用和代扣税费，不填写数量与单价。分红净收入单独计入收益，不减少持仓数量或成本。卖出后收到此前应得的分红仍可录入，但完整历史中必须有更早的买入。红利再投资应另记一笔真实买入。拆股、转托管、送股、做空和券商自动导入暂不支持。

同一持仓只能包含同一账户、同一证券和币种。该账户证券已有交易持仓时，请在原持仓追加成交，清仓后重新买入也沿用原持仓，不另建重复项。同日顺序可修改，与数据库录入先后无关；回填历史成交不受当前估值日期限制。系统按整个交易链检查每个时点的数量，超卖、重复顺序、重复成交编号和字段错误均整次拒绝并回滚，输入仍保留。不同账户的同一证券请分别建仓。

## 计算与行情

服务端使用十进制数计算交易和成本，数量、价格及金额以字符串存储和传输，最多 8 位小数。前端只估算待录入的成交额，不自行重放历史计算盈亏。

买入总成本 = 成交金额 + 交易费用 + 税费。卖出按当时加权平均成本扣除对应成本，已实现卖出盈亏 = 成交金额 - 费用 - 税费 - 卖出成本。小额成交的费用若高于收入，会如实记录净支出。清仓时准确归零剩余数量与成本。已结算盈亏 = 已实现卖出盈亏 + 净现金分红；页面同时展示两项明细和累计费用、税费。统计不包含尚未录入的历史。

首次给已有手工持仓记录交易，将用完整真实成交链替换其手工数量和成本；页面保存前会提示这一行为，不把原手工余额伪装成一笔成交。当前行情价格、估值日期和交易日期分别管理，买卖或分红不会把成交价当成当前市场价。新持仓的当前价格初始为零，有证券代码时读取自动行情，没有代码时需手动核对价格。交易持仓的数量、成本、币种与类别通过交易管理；名称、当前行情、目标权重及同一证券的代码仍可编辑。

买卖和分红的现金收支仅供核对，不会自动增减存款或券商现金余额，请按真实账户余额另行更新。组合流水的金额记录不是证券成交记录，不参与本持仓重建。

## 保存、重试与数据重置

新增使用 POST /api/holding-trades；编辑使用 PUT /api/holding-trades/{id}。原记录编号和创建时间保持不变，更新时间单独保存。新建请求编号和相同内容的编辑均可安全重试。打开表单时固定持仓版本，旧表单不能覆盖之后的更改。成交编号在同一账户内去重。成交保存、持仓重算、每日资产观测及行情核验失效均在同一数据库事务内完成。

交易明细每笔支持“删除交易”，确认后调用 DELETE /api/holding-trades/{id}，请求携带 expectedRevision 校验持仓版本。删除直接移除原记录，按剩余交易重算数量、成本、已结算盈亏、费用、税费和现金收支，同时更新当日资产观测、清除旧行情核验。若剩余历史存在超卖或分红前没有买入，整次删除拒绝并回滚，请先编辑或删除依赖它的后续交易。删除最后一笔后保留证券资料和当前参考价格，数量、成本和市值归零，不恢复首次录入前的手工余额。重复删除已不存在的记录不产生额外更改。删除不会自动修改现金账户余额，也不会重写此前日期的资产观测。

旧交易格式完全停用：没有旧 opening/void 类型、voidOf 字段或旧数字字段的适配器。升级到托管数据库 schema 5 时，逐持仓校验现有交易。结构错误、币种或账户混用、历史超卖、重复编号等非法链整链清空，同时归零对应证券的数量、成本和市值，清除其旧行情核验，并保留证券名称、代码、当前参考价格及其他合法持仓。页面持续提示重新录入，成功保存新成交后消除提示。符合新格式的合法链保留，数量成本缓存若不一致则从合法成交重建。

备份/同步格式为 v18，严格校验新交易关联和计算结果。带旧交易记录的 v1–v17 包不再恢复，整次导入拒绝且不覆盖现有数据；不含交易记录的旧财务包仍可按财务资料原有规则恢复。每日历史观测继续保留其当时的快照，不伪装成券商成交，也不被新交易格式转换。
