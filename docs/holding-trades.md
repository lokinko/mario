# 真实成交与持仓

“我的情况 → 投资持仓”按账户分别记录同一证券的真实买入、卖出和现金分红。请从最早一笔买入开始补齐历史，按券商成交单的实际日期和同日顺序填写。一笔记录对应一笔实际成交或分红到账，误录可直接编辑或删除原记录。系统不再生成期初余额、撤销或修正行。

## 录入字段

买卖填写账户、成交日期、当日顺序、数量、单价、不含费用的成交金额、交易费用和税费。金额默认按数量 × 单价估算，并可按成交单的实际金额校正；金额与数量 × 单价的偏差不能超过 0.01 个计价单位，JPY 为 1。编号应填写每笔成交的编号，避免把多笔成交共用的委托编号当作成交编号；没有编号可留空。备注也是选填。

现金分红填写到账日期、当日顺序、税前总金额、费用和代扣税费，不填写数量与单价。分红净收入单独计入收益，不减少持仓数量或成本。卖出后收到此前应得的分红仍可录入，但完整历史中必须有更早的买入。红利再投资应另记一笔真实买入。拆股与合股使用独立公司行动记录核对后重放，不改写成交单。转托管、非比例送股、做空、券商自动导入和零碎股现金替代分配暂不自动处理。

同一持仓只能包含同一账户、同一证券和币种。该账户证券已有交易持仓时，请在原持仓追加成交，清仓后重新买入也沿用原持仓，不另建重复项。同日顺序可修改，与数据库录入先后无关；回填历史成交不受当前估值日期限制。系统按整个交易链检查每个时点的数量，超卖、重复顺序、重复成交编号和字段错误均整次拒绝并回滚，输入仍保留。不同账户的同一证券请分别建仓。

## 计算与行情

服务端使用十进制数计算交易和成本，数量、价格及金额以字符串存储和传输，最多 8 位小数。前端只估算待录入的成交额，不自行重放历史计算盈亏。

买入总成本 = 成交金额 + 交易费用 + 税费。卖出按当时加权平均成本扣除对应成本，已实现卖出盈亏 = 成交金额 - 费用 - 税费 - 卖出成本。小额成交的费用若高于收入，会如实记录净支出。清仓时准确归零剩余数量与成本。已结算盈亏 = 已实现卖出盈亏 + 净现金分红；页面同时展示两项明细和累计费用、税费。统计不包含尚未录入的历史。

首次给已有手工持仓记录交易，将用完整真实成交链替换其手工数量和成本；页面保存前会提示这一行为，不把原手工余额伪装成一笔成交。当前行情价格、估值日期和交易日期分别管理，买卖或分红不会把成交价当成当前市场价。新建证券在取得当前行情前，暂以首笔买入价作为参考价，避免扣除现金后证券仍按零元估值；有证券代码时读取自动行情，没有代码时需手动核对价格。后续交易不覆盖当前参考价。交易持仓的数量、成本、币种与类别通过交易管理；名称、当前行情、目标权重及同一证券的代码仍可编辑。

存款以 CNY、HKD、USD 三种货币分别维护一个当前余额，不再按银行卡或券商账户拆分；交易账户仍用于区分证券持仓和成交编号。买入从同币种存款扣除成交金额、交易费用和税费；卖出与现金分红将扣费扣税后的净收入加回同币种存款。不会跨币种自动换汇，也不支持负余额；不足时整笔交易、持仓变化、存款变化及当日观测一起回滚。小额卖出或分红若费用高于收入，也会扣款并检查余额。

仅对当前核对基准后已结算的交易，编辑按现金流差额结算，删除退回原现金影响。历史交易及新余额确认已覆盖的交易发生现金影响更正时，保留当前现金并标记待核对；仅补充备注不产生核对差异。重试不会重复扣款或回款。若先前收入已经被用掉，删除或调减收入导致余额不足时同样整次拒绝。手动核对存款通过带 expectedRevision 和 requestId 的金额接口保存，旧表单不能覆盖交易后的新余额。

升级与恢复备份时，已有同币种存款合并，金额合计保持不变；历史成交不会重新扣款，已有余额作为当前余额继续使用。表单明确选择“结算本次现金”或“补录历史，不结算现金”。前者绑定打开表单时冻结的现金 baselineId，余额已重新确认时拒绝旧表单；后者不重放现金。新增和更正接口必须显式传入 `settlementMode: history | settle`，不再接受 `auto` 或缺失模式；更正继续遵循原记录已保存的现金归属，删除只冲回已归属的现金变化。日期不能代替用户对实际余额是否已包含该成交的判断。其他币种的旧存款保留并继续计入总资产，页面提示核对，不静默丢弃。

内部股票等手动估值的交易持仓，可点击“当前价格”录入新价格，再保存资产。市值按真实成交汇总的数量 × 新价格更新；原交易记录、数量、平均成本和总成本保持不变。小数均价在请求传输中的浮点误差不会被误判为修改成本，也不会用于重新计算交易成本。

## 保存、重试与数据重置

新增使用 POST /api/holding-trades；编辑使用 PUT /api/holding-trades/{id}。原记录编号和创建时间保持不变，更新时间单独保存。新建请求编号和相同内容的编辑均可安全重试。打开表单时固定持仓版本，旧表单不能覆盖之后的更改。成交编号在同一账户内去重。成交保存、持仓重算、存款结算、每日资产观测及行情核验失效均在同一数据库事务内完成。

交易明细每笔支持“删除交易”，确认后调用 DELETE /api/holding-trades/{id}，请求携带 expectedRevision 校验持仓版本。删除直接移除原记录，按剩余交易重算数量、成本、已结算盈亏、费用、税费和现金收支，同时更新当日资产观测、清除旧行情核验。若剩余历史存在超卖或分红前没有买入，整次删除拒绝并回滚，请先编辑或删除依赖它的后续交易。删除最后一笔后保留证券资料和当前参考价格，数量、成本和市值归零，不恢复首次录入前的手工余额。重复删除已不存在的记录不产生额外更改。删除只撤回当前基准仍计入的现金贡献；已被核对基准覆盖的历史变更触发待核对，不改当前余额，也不会重写此前日期的资产观测。

持仓列表的“更多操作 → 删除”和详情中的“删除持仓”支持整项移除，包括已有买卖或分红的持仓。确认框列出关联交易数量。DELETE /api/holdings/{id} 携带 expectedRevision，原子删除持仓、全部活动交易及公司行动，并按当前核对基准汇总撤回交易对存款的净影响；历史部分不重放现金，标记存款待核对。净扣款导致余额不足、版本冲突或交易链尚未修复时整次拒绝。原始持仓、交易及公司行动保留在更正历史中，此前日期的资产观测继续保留。此操作用于移除误录资料，真实清仓应记录卖出。删除请求支持事务回执和相同请求重试，网络结果不明时点击“核对删除结果”，不会重复结算。

旧交易格式完全停用。schema 8 升级逐持仓校验，非法链保留原始行与隔离原文，暂停相关估值、交易写入和组合行动。禁止自动删除、归零或让用户重复录入结算。交易明细提供原文、候选 JSON、独立预览与带依据的确认修复；修复保留原版本，不重放历史现金，完成后重新核对存款。合法链的数量成本缓存可以从真实成交和已确认公司行动重建。

备份/同步当前格式为 v23；从 v21 起严格校验新交易关联和计算结果。带旧交易记录的 v1–v17 包不再恢复，整次导入拒绝且不覆盖现有数据；不含交易记录的旧财务包仍可按财务资料原有规则恢复。每日历史观测继续保留其当时的快照，不伪装成券商成交，也不被新交易格式转换。

存款合并随数据库 schema 7 升级执行一次。v18/v19 交易备份仍可恢复，恢复时仅合并已有现金，不重放交易现金流。

## 事务回执、公司行动与永久更正历史

交易提交只依赖本地数据库事务，不等待行情网络刷新。financial_operations 的回执与成交、现金、证券重算、financial_journal 和当日观测原子提交。服务器先识别原请求回执再拒绝旧全局版本；回执返回当前快照，避免旧结果覆盖后续更正。网络/5xx 的结果不明时客户端查询只读回执，保留原请求与输入并阻止修改，核对仍使用原请求。不能把未知结果当作明确失败后重新创建交易。

financial_journal 保留前后原文、精确现金差额、说明、时间和 operationId。界面删除移除活动行，但不删除更正记录。升级之前已被旧程序删除的记录无法补造，须从旧备份或券商单据恢复。

Yahoo 收盘价按拆股调整，检查范围从最早成交开始，历史估值查询也检查到今日，以匹配当前股数口径；当日生效的公司行动也可能影响上一交易日收盘价。自动发现后先登记待核对并暂停估值/交易。未上市证券可按券商通知人工登记比例。确认后按生效日重放股数和均价，总成本与现金不变，原始成交保留，价格标为待重新核对。合股产生超出 8 位精度的零碎股时拒绝整次确认，不能静默舍入。

来源有误可填写依据否决；已确认的错误调整可撤回并按剩余行动重放，若导致历史超卖则整次拒绝。原记录与更正均保留。同一行情源再次给出已否决事件时不能自动采用，需核对证券代码或人工价格。Twelve Data 未复权报价用于成交链估值前还需独立检查公司行动，报价早于新生效行动时暂停。

cash_state 与 holding_amounts 保存十进制原值，accounting 返回服务端十进制汇总；旧 number 字段仅用于显示投影和比例分析。界面最多显示两位小数不会改变计算精度。源数据、每日历史和备份保留精确字符串，行情/汇率沿用其原始口径。数据问题由结构化 issues 定位到持仓；缺汇率、待确认拆合股和隔离交易阻止依赖组合总值的计算，存款待核对与价格日期不阻止再平衡。未平仓期权及标的只排除自身动作。AI 根据问题范围解释建议，结构与来源校验继续保留。

## 股票关联期权

股票详情的“关联期权”支持认购（Call）、认沽（Put）及多头、空头。每份合约绑定当前账号内同一账户、同币种的股票持仓，记录账户、到期日、行权价和整数合约乘数。可先建立数量为零的股票资料，再录入该股票的期权；不要求先买入股票。一个账户的同一股票、类型、方向、行权价、到期日及乘数只建一份合约，后续开平仓追加到原合约。更改合约定义需核对后更正资料，不能通过改股票代码、币种或类别使历史归属漂移。

期权按整数张记录，每单位权利金与股票价格分别管理，成交额 = 张数 × 每单位权利金 × 合约乘数。乘数由券商合约决定，不固定假设为 100。多头买入开仓、卖出平仓；空头卖出开仓、买入平仓。每张合约独立按加权平均成本重放，费用、税费计入盈亏，不与其他行权价、到期日或方向的合约混算。期权买卖不改变股票股数或股票成本。

多头剩余成本为开仓支出（含费用税费），空头剩余成本为负的开仓净收入。多头市值 = 未平仓张数 × 当前每单位权利金 × 乘数；空头市值取其负值，表示平仓负债，收到权利金不会被误记为已赚取全部收益。浮动盈亏 = 有符号市值 − 有符号剩余成本；平仓盈亏由平仓现金流扣除对应有符号成本。比如卖出 2 张、权利金 3、乘数 100、开仓费 2，现金增加 598，负债市值为 −600，浮亏 2；之后每单位报价降至 1，负债为 −200，浮盈为 398。盈亏与现金均在服务端使用十进制原文计算。

股票列表按标的汇总股票及关联期权的净市值、浮动盈亏和已结算盈亏，并在详情分别展示合约明细。股票股数为零而仍有未平仓期权时不会被折叠为已清仓。组合会计只统计底层股票与合约各一次，标的汇总是展示投影，不再次计入总资产。投资概览成本为有符号账面成本，空头部分为负数，并非保证金或最大风险敞口。

期权报价使用独立的“更新期权报价”，支持零权利金；不会取标的股票价格或普通证券自动行情作为期权价格。初次开仓价只作待确认参考。存在未平仓期权时暂停普通股票再平衡建议，提示核对保证金与交割风险；当前不计算 Greeks、保证金、期权理论价格或自动调整合约。

到期不会自动清零。核对券商记录确实未行权、未被指派后，可在到期日显式记录“到期作废”，一次关闭全部剩余张数，权利金和成交金额为零，允许录入实际费用。到期后的成交、分红、零碎张数及超额平仓整次拒绝。行权、被指派、现金交割及拆股后的期权合约调整尚不自动处理；发生这些情况时保留合约记录并核对券商单据，不能用到期作废代替实际交割。

成交继续使用既有版本检查、现金核对基准、历史补录与结算模式、事务回执和更正历史。报价使用 `PUT /api/holdings/{id}/option-price`，带 `requestId`、`expectedRevision`、`price` 和 `observedOn`，原子更新估值、每日资产与审计回执，未知结果可按同一请求核对。删除标的前需先处理关联期权；删除期权与删除误录证券一样会撤回当前基准仍计入的现金贡献，不代表平仓。

本功能将租户 schema 升为 11，备份格式升为 v23，新增 `holding_options` 合约关联表；股票与既有成交保持原样。v22 及此前受支持的备份仍可恢复为无期权资料，导入失败整次回滚。每日资产观测冻结当时的合约定义，删除合约后历史仍能验证和恢复。升级前可保留现有备份；要回退程序，需使用升级前备份恢复至匹配版本，不能将 v23 合约包交给旧程序导入。
