# lint 范围与验证边界

lint 负责可自动判定的代码质量、模块边界、契约一致性和文档有效性。业务正确性由测试验证，AI 回答质量单独评测。业务归属和允许的依赖见[架构](architecture.md)，不在本文维护另一套模块划分。

本文确定检查范围，并说明已有入口与缺口；不表示所有检查已经实现或本次已执行。

## 1. 代码质量

检查格式、类型与编译警告，复用现有工具：

- 前端用 Prettier 检查格式，TypeScript 检查类型和无用声明。
- Rust 用 rustfmt 检查格式，用 Clippy 检查代码问题并拒绝警告。
- 检查模式不自动修改业务代码；修复与检查分别执行。

现有工具配置以[根 package.json](../package.json)、[前端 package.json](../client/package.json)、[TypeScript 配置](../client/tsconfig.json)和 [Rust 配置](../server/Cargo.toml)为准。

## 2. 模块边界

检查依赖方向、循环依赖，以及对其他域内部实现的直接访问。用户、市场、AI 的职责归属由架构文档确定，技术层检查为其提供补充约束。

当前[架构检查](../scripts/check-architecture.mjs)覆盖前端跨页面依赖、共享模块反向依赖、循环、不可达前端模块，以及后端领域、用例、端口、数据库驱动、行情适配、AI 执行和认证等技术边界。检查器自身有[回归测试](../scripts/check-architecture.test.mjs)。

[技术模块登记](../scripts/architecture-boundaries.mjs)列出前后端技术层与现有页面、API 客户端模块。新增前端模块和后端顶层生产模块必须显式登记，后端过期或重复登记会报错；仅测试模块不参与生产登记。登记用于避免新模块绕过检查，不将现有页面模块等同于用户、市场、AI 三个业务域。

前端页面与 API 客户端另登记业务归属，禁止用户页面直接依赖 AI API，跨页讨论由应用回调组合。已拆分的用户资料、方法论、AI 分析和模型设置 HTTP 路由必须放在所属适配模块；登记的路径不能迁回其他适配器。对应反向依赖与路由混放由架构回归验证。

后端计划采集、计划仓储与用户日历按具体 Rust 导入符号校验能力边界，覆盖分组导入、别名和相对路径。市场计划模块不能取得用户候选目录或账号能力；用户日历只能取得计划缓存读端口，不能导入采集器或可写计划仓储。规则针对已完成拆分的模块执行，尚未覆盖全部后端业务调用。

后端用例与端口也显式登记业务归属；新增、过期登记或混入根模块的业务入口会失败。市场来源、市场用例和公共市场仓储不得依赖用户或 AI 契约、用户用例、账号端口及账号仓储；用户用例不得依赖 AI，用例之间的访问也按归属检查。证券来源只返回市场资料，用户候选目录与观察参考价在用户域维护。共享 schema 内的用户候选目录仓储仍归用户域，不按 public 名称误归市场。上述规则不替代 HTTP 与账号仓储内部权限检查。

AI 分析、记忆、模型设置与桥接用例禁止直接依赖 Database、驱动或账号实现，只能导入各自登记的账号能力端口。泛型约束由 Rust 编译检查可调用方法，架构回归检查具体存储依赖及扩大端口范围的导入。存储适配保留在 `db/ai_access.rs`，模型执行器继续不依赖任何账号存储。

用户组合、价格、汇率和个人观察用例同样禁止依赖 Database、驱动或账号实现，只能取得各自登记的[用户账号端口](../server/src/ports/user_account.rs)。用户端口及其适配禁止依赖 AI 契约、账号能力或执行服务；AI 用例也不能通过用户写端口绕过只读授权来源。公共账号锁端口只提供锁协调，禁止依赖业务数据。编译检查实际可用的方法，架构回归覆盖扩大端口、模块别名、相对路径和跨域导入。

生产分析用例、账号端口及上下文构建禁止重新导入完整 Snapshot 或成交记录，统一使用用户域的授权当前状态投影。测试夹具可以保留完整账本，用于验证其明细不会进入模型输入。

前后端契约模块显式登记用户、市场、AI 或公共原语归属。用户契约不能依赖 AI，市场契约不能依赖用户或 AI；公共原语不能反向依赖业务契约。后端禁止通过 models 根模块、通配或未登记模块取得类型；models 根文件只声明所属模块，不保留混合定义与重导出。前端 types 只允许类型声明和显式类型导入，禁止使用统一 barrel 绕开归属；用户页面和 API 客户端也不能依赖 AI 类型。上述检查覆盖契约依赖，不能据此推断全部后端用例、仓储与协议访问已隔离。

现有混合职责在架构文档中显式登记。检查通过不能掩盖尚未解决的业务边界，也不要求本轮立即重构全库。新增约束应针对明确的职责和依赖，不通过目录名称推断整个目录只属于一个业务域。

## 3. 契约一致性

检查前后端类型、请求策略，以及路由与 API 文档是否对应。业务规则引用所属域 spec，不将自然语言需求全部转成机械文本匹配。

现有[契约检查](../scripts/check-contracts.mjs)将 Rust 序列化夹具交给 TypeScript 检查，并核对部分请求版本策略，覆盖金额、成交、财务档案、观察规则、模型配置和流式事件等契约。它不等于所有接口已经覆盖。

该入口会运行 Rust 契约夹具，并通过一次性 PostgreSQL 启动器执行，需要本机 Rust 与 PostgreSQL 工具；它不是纯文本静态扫描。现有接口清单与调用契约见 [API 文档](api.md)；`npm run check:docs` 核对其方法与路径是否对应实际路由，不验证全部字段或副作用描述。

## 4. 文档有效性

检查文档引用的文件路径、链接、锚点、脚本入口，以及生成内容是否与来源一致。只检查已经确认保留的文档；历史内容不会因缺失引用而自动恢复。

现有[入口检查](../scripts/check-entrypoints.mjs)验证 npm 脚本与完整门禁引用的脚本路径，其[测试](../scripts/check-entrypoints.test.mjs)验证缺失入口会被发现。

[文档检查](../scripts/check-docs.mjs)通过 `npm run check:docs` 检查根 README、AGENTS.md 与 `docs/` 内 Markdown 的内联本地链接、标题锚点和冲突标记，并比较 `hosted.rs`、`agent.rs`、`http/` 中的字面量路由方法/路径与 API 表格。忽略注释、字符串示例、仅测试代码和通配 404 兜底；遇到不支持的路由声明会失败，要求同步扩展扫描器。其[回归测试](../scripts/check-docs.test.mjs)验证接口遗漏、过期、重复及链接失效会被发现；该入口已接入 `npm test`。

此检查不访问远程链接，不覆盖其他目录中尚待内容复核的说明文件、全部 Markdown 语法、HTTP 字段语义或全量生成 schema。检查器需要已安装前端 TypeScript 依赖，复用架构检查的 Rust 源码屏蔽逻辑。

已确认保留的文档由[文档索引](README.md)提供查询入口。检查结果须说明实际覆盖的文件，不能将索引所列文档的局部链接检查通过描述为整个仓库文档已经通过检查。

## 5. 当前执行入口

以下是现有入口；仓库目前尚无统一的 `npm run lint` 命令。

| 类别 | 当前命令 | 覆盖说明 |
| --- | --- | --- |
| 前端格式 | `npm run format:check --prefix client` | 检查前端源码格式 |
| 前端类型与构建 | `npm run build --prefix client` | 当前将 TypeScript 检查与 Vite 构建一起执行 |
| Rust 格式 | `cargo fmt --manifest-path server/Cargo.toml -- --check` | 只检查格式 |
| Rust 代码质量 | `cargo clippy --manifest-path server/Cargo.toml --all-targets -- -D warnings` | 检查所有目标，拒绝警告 |
| 技术架构 | `npm run check:architecture` | 现有边界检查及检查器回归 |
| 前后端契约 | `npm run check:contracts` | Rust 夹具、TypeScript 契约及请求策略的一部分 |
| 脚本入口 | `npm run check:entrypoints` | 脚本存在性及检查器回归 |
| 文档与 API 清单 | `npm run check:docs` | 已确认文档的本地引用、冲突标记、路由清单及检查器回归 |
| 完整门禁 | `npm test` | 见[完整测试脚本](../scripts/test.sh)，包含构建、检查、单元及集成验收，范围大于 lint |

纯文档改动核对事实、链接、锚点、冲突标记并执行 `git diff --check`。代码或检查器发生变化时，补充相应类型检查和有意义的回归；不能把无关业务测试的执行次数当成文档或架构质量。

真实市场来源连通性、真实模型回答质量、OAuth 登录和独立部署恢复验收分别报告。lint 通过不代表这些外部行为或业务正确性已经验收。
